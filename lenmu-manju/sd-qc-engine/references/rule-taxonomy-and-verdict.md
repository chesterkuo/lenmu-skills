# 規則三分類與統一裁決（rule-taxonomy-and-verdict）

> 定位：本包規則散落在**總控 + 10 個子技能 + 51 份總控規則庫（全包 129 份）**裡，數量已過千條。**規則越多，"兩條規則打架時聽誰的"就越常發生**。本文件只解決兩件事：① 給每條規則**定級**（硬約束 / 條件約束 / 創作建議）；② 給每次判定**定態**（PASS / WARN / FAIL）。**不新增業務規則**，只做治理。
>
> 權威邊界：本文件是**分類與裁決口徑**的唯一權威；具體規則內容仍以各自規則庫為準。

---

## 一、為什麼必須三分類

現狀（治理前的三類典型事故）：

| 事故 | 病根 |
|---|---|
| 執行者被一條"建議"卡住，反覆問用戶 | 建議**被當成硬約束** |
| 兩條規則衝突，執行者自行選了一條，出片才發現選錯 | 缺**裁決順序** |
| 一個必須修的項只報了 WARN，交付後翻車 | 判定**狀態用錯** |

**三分類解決"該不該停"，裁決順序解決"聽誰的"，三態解決"能不能交付"。**

---

## 二、三分類：定義 · 判定法 · 包內實例

| 級別 | 定義 | 違反後果 | 判定三問 |
|---|---|---|---|
| **硬約束**（Hard） | 不滿足即**產出不可用 / 違規 / 不可交付** | **FAIL**，禁止進入下一階段 | ① 違反它會不會讓產物**無法使用**？② 它是不是**前置鎖/紅線**？③ 它有沒有寫"禁止/必須/不得"且**無例外分支**？——任一為是 → 硬約束 |
| **條件約束**（Conditional） | **觸發門滿足時**等價於硬約束；門不滿足時**完全不適用** | 門內 FAIL，門外不判 | ① 它有沒有明確的**觸發條件**（如"僅打戲稿""僅 2.5""僅 M2"）？② 門外出現是否屬於**誤報**？——兩問皆是為是 → 條件約束 |
| **創作建議**（Advisory） | 影響**質量高低**，不影響**能否交付** | **WARN**，可修復也可寫明依據不改 | ① 不採納它產品還能不能用？② 它是不是"推薦/建議/優先"措辭？——皆是為是 → 創作建議 |

**包內實例對照**：

| 規則 | 級別 | 依據 |
|---|---|---|
| 前置鎖定 A（模型版本）/ B（畫幅）未指定 = 任務不開始 | **硬約束** | 前置鎖，無例外分支 |
| 七段式七欄齊備 | **硬約束** | 缺欄則投餵稿件結構不成立 |
| 平台紅線（血腥 / 斷肢 / 裸露類直白詞） | **硬約束** | 違規即不可交付 |
| 打戲激烈度下限（位移 / 接觸 / 貼身佔比） | **條件約束** | 觸發門＝打戲稿；文戲稿完全不判 |
| 畫風鎖機檢 | **條件約束** | 觸發門＝稿內含畫風鎖塊或登記了來源風格 |
| 鏡長雷同告警（節奏缺乏呼吸） | **創作建議** | 不改也能出片，改了更好 |
| 無台詞鏡時長上限 | **創作建議** | 屬"防拉伸湊時"的優化項 |

> 🔴 **誤分級的代價**：把條件約束當硬約束 → 文戲稿被"打戲規則"無謂攔截；把硬約束當建議 → 該停的不停，錯誤累積到成片。

## 三、衝突裁決順序（四級優先鏈）

兩條規則打架時，**按序判定，高序勝低序**：

```
① 用戶當輪明確指令
       ↓ 無
② 前置鎖定（A 模型版本 / B 畫幅 / C 交付形態 / D 段縫 + 〇·1 素材來源鎖）
       ↓ 未涉及
③ 級別比較：硬約束  >  條件約束  >  創作建議
       ↓ 同級
④ 權威比較：專檔 > 總綱；「唯一權威」聲明方 > 引用方
       ↓ 仍不可判
⑤ 停下，寫進報告，由用戶裁定 —— 禁止執行者自行選邊
```

**第 ④ 級的操作口徑**：
- 文件裡寫了「**本文件是……的唯一權威**」「以本文件為準」的，是**聲明方**，衝突時它勝；其餘為引用方。
- 總控與子技能衝突：**術語與口徑以總控為準**（機檢碼 / 時間軸 / 語法分離等），**領域專精規則以子技能為準**（如打戲檔位路由、劇本六階段鏈）。
- 同文件內條目衝突：以**更具體者**為準（如"共 6 條鐵律"與"僅打戲稿生效的 3 檔"衝突時，後者更具體）。

> ⚠️ **第 ⑤ 級不是失敗**。規則覆蓋不到的現實情形，正確動作是**停下來問**，不是挑一條湊合——湊合出來的產物無法驗收。

## 四、PASS / WARN / FAIL 三態定義（跨階段統一）

| 狀態 | 含義 | 處置 | 能否進入下一階段 |
|---|---|---|---|
| **PASS** | 無可執行問題 | 直接放行 | ✅ 可以 |
| **WARN** | 存在風險，但**可控或可豁免** | **逐條二選一**：① 修復；② 寫明"不改的依據"（如觸發門不適用 / 已在別處滿足）。**禁止不寫依據就放過** | ✅ 可以（依據必須留檔） |
| **FAIL** | 違反硬約束或前置鎖 | 必須修復並**複驗**；不得帶 FAIL 交付 | ❌ 不可以 |

**各階段三態落點**：

| 階段 | 主要判什麼 | 典型 FAIL | 典型 WARN |
|---|---|---|---|
| 劇本門 | 結構 / 卡點 / 台詞念得完 | 劇情矛盾、台詞明顯超長 | 鉤子偏弱、情緒節拍偏平 |
| 資產門 | 三清單齊備 / 編號連續 / 與文字檔案一致 | 錨點無對應物 | 資產描述可再細 |
| 分鏡門 | 站位 / 軸線 / 景別階梯 | 軸線未聲明、擺位不入畫 | 鏡長雷同、單鏡偏長 |
| 投餵門 | 七段式 / 機檢碼 / 紅線 | 缺欄、平台紅線詞、**接續狀態殘留（C11 反轉：出現即 FAIL）** | 語氣位缺失、否定式殘留 |
| 成片門 | 連續性 / 轉場 / 聲音 | 跨段穿幫、切點非法 | 混音比例可優化 |

**與機檢的映射**：`validate_prompt.py` 的 `issues` 對應 **FAIL**，`warnings` 對應 **WARN**，二者皆空即 **PASS**。**注意**：機檢只覆蓋可機械判定項——機檢 PASS 不等於階段 PASS，語義門（軸線 / 遮擋 / 物理）仍須人工過。

---

## 五、怎麼用（執行者三步）

1. **定級**：拿到一條規則，先用 §二 的「判定三問」定級；定不出級別 = 規則本身寫得不清，提 issue。
2. **定態**：判定結果按 §四 落成 PASS / WARN / FAIL；WARN 必附依據。
3. **衝突走鏈**：遇到兩條規則打架，按 §三 四級鏈走；走到 ⑤ 就停下問，別自行選邊。

> 🔗 **配套**：機檢碼的完整說明見 `references/machine-check-manual.md`（判據碼清單、觸發門、P0~P2 與機檢先後關係）。判據的**行為驗證**由使用方按需自建迴歸樣本，本包不隨帶測試資產。
