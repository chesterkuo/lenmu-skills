## 一、命令行用法

```bash
python scripts/validate_prompt.py <提示詞文件.md|.txt> [--model 2.5|2.0] [--mode new|extend] [--combat on|off|auto] [--c23 on|off|auto] [--style-source 導演名] [--aspect 16:9|9:16|21:9] [--by-segment] [--json] [--self-test]
```

| 參數 | 說明 |
|---|---|
| `<提示詞文件>` | 待檢的投餵稿（md/txt，UTF-8），通常為七段式投餵稿 |
| `--model 2.5` | Seedance 2.5 側檢查（C1~C26），段上限 30s |
| `--model 2.0` | Seedance 2.0 側檢查（C1~C26），段上限 15s |
| `--mode new\|extend` | new=完整新稿；extend=續寫稿 |
| `--combat on\|off\|auto` | **C21 打戲護欄觸發門**，默認 `auto`：打戲信號詞達閾值即啟用 C21，文戲稿自動跳過；`on` / `off` 為強制開關 |
| `--c23 on\|off\|auto` | **C23 畫風鎖機檢觸發門**，默認 `auto`：稿內存在行首【STYLE/【PERFORMANCE 段標記即啟用（I 鎖已啟用），未啟用畫風鎖的舊稿不追溯；`on` / `off` 為強制開關（`on` 時缺段8/9 即報 C23a） |
| `--style-source 導演名` | **STYLE_BIBLE 來源風格登記**（如 `徐克`/`王家衛`）：登記後啟用 C23d② 轉譯丟失與 C23e 題材越界判據；名字本身是選項層信息，**不得出現在稿內**（出現即 C23d1） |
| `--aspect 16:9\|9:16\|21:9` | **畫幅任務鎖回填**（B 鎖）：供 **C6b** 做「`aspect_ratio=` 字段 ↔【畫幅風格】聲明 ↔ 任務鎖」三處互校；與稿內聲明不符即 FAIL。格式須形如 `16:9`（含全角冒號亦可），否則退出碼 2 |
| `--by-segment` | **分單元校驗**（2026-10-19 新增 · **多段稿必加**）：按稿內「段N/M」標題切段，**逐段獨立跑全部判據**，結果帶 `[段N]` 前綴，末尾輸出「段數N（分單元校驗）」；整份文本仍走 C31 契約核銷。**不加的後果**：3×30s 的 90s 稿會被累計成「90s / 多鏡」，**誤判打戲檔觸發 C21/C22**，C10 單鏡時長與 C15 特寫佔比同時失真 |
| `--json` | 以 JSON 輸出結果（含 `combat_checked`、`c23_checked`、`style_source` 字段） |
| `--self-test` | 腳本自帶自檢（驗證機檢器本身健康） |

> **多段稿必帶 `--by-segment`（★ 2026-10-19）**：只要一稿含 ≥2 個「段N/M」，正式結論一律用分單元口徑出。實測教訓：《獸瞳》第01集 3×30s 整份送檢時，腳本按全文判「打戲檔」並連續報 C21a/c、C22 位移與貼身佔比不足——**拆段後段2/段3 零 WARN、段1 只剩拆段導致的契約指紋報缺**，那些「打戲不夠激烈」全是解析粒度造成的誤報。
>
> **資產段另有專用門禁**：`python scripts/check_asset_blocks.py <交付稿.md>`（自包含 A1 / 16:9 A2 / 九宮格八字段 A3 / 角色四格 A4·A5 / 道具四格 A6）。`validate_prompt.py` 不管資產提示詞，**別用它的 PASSED 當作資產段合規的證明**。


**退出碼與交付鐵律**：腳本發現 FAIL 類問題退出碼 1，無問題退出碼 0。**FAIL 清零才交付**；WARN 逐條修復或在交付說明中寫明判定依據，禁止帶 FAIL 出稿。

## 三、P0~P2 門禁與機檢的先後關係

出稿按以下順序雙門聯審，**兩門都過才交付**：

```

    P2 審美缺陷（優化建議）：無任務空鏡 / 空泛形容詞 / 聲音層次不清 / VO·OS 超配額…
    ↓ 通過後
第 2 門（結構機檢，腳本兜底）：validate_prompt.py --model 2.5|2.0
    FAIL 清零 → 交付；有 FAIL → 修復 → 重跑（兩門都要重跑，見下方改動複驗鐵律）
```

- 先語義後機檢：語義門禁攔截腳本測不了的創作缺陷，機檢兜底攔結構回退；機檢 PASS 不等於語義 PASS，反之亦然。
- **改動複驗鐵律**：改稿禁止只複驗改動處，必須跑總控三步閉環——① 局部驗證（改動處自檢）→ ② 聯動衝突檢查（伏筆/角色/信息量/因果/資產錨點/時長/畫幅七項交叉掃描）→ ③ 全量審核（整片重跑 P0~P2 + 機檢）；修改類交付物文末必須附《改動複驗報告》（改動清單+聯動結論+全量結論），未附 = 禁止交付。

**質檢問題條目必填字段（每項一條，缺項視為報告無效）**：`issue_id`、證據路徑/ID、影響、責任階段（路由到哪個子技能）、最小返修範圍、**需重驗的下游**、對應的門禁項（P0/P1/P2 或 C?/H?）。

**放行結論只允許三值**：`PASS` / `PASS_WITH_MINOR_RISKS` / `FAIL_RETURN_TO_STAGE`；只有 `PASS` 或用戶明確接受的 `PASS_WITH_MINOR_RISKS` 才可進入實際生成。**結構校驗通過一律不得寫成「成片已通過」。**

## 七、解析口徑備忘：時間軸格式（C1~C30 / 閘門 / 看板全鏈路統一）
