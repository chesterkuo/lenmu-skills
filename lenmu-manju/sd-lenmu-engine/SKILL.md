# sd-lenmu-engine · Lenmu 執行引擎（L4 執行層 · fork 增補）

## 一、角色定位

原套裝只寫稿不出圖：交付「提示詞 + 接線說明書」，圖和視頻由用戶去外部平台自己跑。
本引擎是它的**執行層**——用戶授權後，用 Lenmu MCP（`https://lenmu.ai/mcp`）把稿子跑成資產圖、視頻段和成片。
它就是總控 §〇·E 裡說的「確認制生產 skill」：**出圖 / 出片一律走本引擎的報價確認閘門**。

- **不改任何創作判據。** 劇本、資產提示詞、分鏡、七段式、機檢、門禁全部照原套裝執行；本引擎只接手「稿子寫完並過檢之後」的生成動作。
- **不啟用時，套裝行為與上游完全一致**（M0 / M1 只出提示詞）。
- 本引擎只用 Lenmu 的生成與剪接工具。Lenmu 自帶的寫劇本工具（`write_script` / `write_story` / `expand_script` 等）**不用**——項目 md 是唯一真相，不設第二份劇本來源。

## 二、啟用條件（對齊總控 §〇·E）

總控 E 鐵律：默認只出提示詞，用戶明確下達出圖口令才執行。本引擎的啟用 = 該口令的落地：

1. 用戶在開工確認卡第 9 項選了「② Lenmu 直出」，或在對話中明確說「用 Lenmu 出圖 / 出片 / 直接生成」；
2. **授權範圍只到「可以報價」**：每一批生成仍要先報價、用戶同意後才調用（見 §三 鐵則 1）。用戶追問「怎麼還沒出圖」≠ 同意報價；
3. 用戶沒選、沒說 → 不啟用，不主動推銷，不把「開始跑圖」當默認動作。

## 三、鐵則

1. **花錢前先報價。** 用 `list_models` 的 price_hint 算出金額告訴用戶，同意才調用。便宜的任務 Lenmu 可能不回 `requires_confirmation` 就直接扣款，不能只靠它攔；有回時核對 `estimate_usd`，帶 `confirm_token` 重送。
2. **一案一畫布、先設預算。** 開工用 `set_budget`（不帶 canvas_id、帶 `name` = 項目名）建一張已設上限的新畫布，之後每一步都帶這個 canvas_id。
3. **拿到 generation_id 就不重送。** 超時不等於失敗。輪詢 `get_generation`：視頻 10–20 秒一次，圖片 / 音頻 5–10 秒一次。同一張畫布回 `canvas_busy` 就排隊等。
4. **機檢 FAIL 未清零不生成。** 投餵稿必須先過 `sd-feed-engine/scripts/gate_check.py`（含 C 系機檢）與本引擎的 `scripts/lenmu_wiring.py`；資產圖未經用戶確認不進視頻段。
5. **不假裝（上游四鐵律第 3 條在本層的延伸）。** 你只看得到抽出來的靜態幀，聽不到聲音、看不到真正的動態和口型。每次交付寫明「已看：…；沒看：口型、動態、台詞與音效」，請用戶看和聽。
6. **首段先過關，再批量。** 第一段視頻給用戶看過、確認圖號對位和畫風都對，才報其餘段的總價。
7. **新版本存新節點，不覆蓋舊結果。** 有 `warning`（如存儲空間將滿）原文轉告。每次回報附 canvas_url。

## 四、開工檢查

- `list_models`（免費）：確認連得上，記下 Seedance / Seedream 的 id、尺寸、上限、price_hint 與 `account.balance_usd`。**本文件裡的 id 與數字是 2026-11 的快照，一律以當次 `list_models` 為準。**
- 沙盒：`ffmpeg -version`、`ffprobe -version`、`python3 --version`；用 `curl -sSL -o t.bin <url>` 試下載一個 Lenmu 文件（Python urllib 常被擋，一律用 curl）。下載不了時 §九 的圖像級質檢做不了，要先告訴用戶。
- `set_budget` 建畫布，把 canvas_id 與預算寫進 `_內部_Lenmu執行台賬.md`（§十一）。

## 五、鎖 → Lenmu 參數映射

| 上游鎖 | 選項 | Lenmu 做法 |
|---|---|---|
| **A 模型** | ① Seedance 2.5 | `byteplus/seedance-2.5`：4–30 s；參考 圖 ≤30 / 視頻 ≤10 / 音頻 ≤10 / 合計 ≤50。省錢可用同版本的 `seedance-2.5-flash`（只有 720p / 480p），**須用戶同意** |
| | ② Seedance 2.0 | `byteplus/seedance-2.0`：4–15 s；參考 **圖 ≤8 / 合計 ≤8**（上游寫的「2.0 圖 ≤9」在 Lenmu 是 8，以這裡為準）。省錢可用 `seedance-2.0-fast` / `-mini`（只有 720p），須用戶同意 |
| | 參考模式（僅 2.5） | ① 全能參考 → `reference_media_ids`；② 首尾幀 → `first_frame_media_id` + `last_frame_media_id`。兩者互斥，Lenmu 也不允許同時給。**2.0 仍按上游契約禁用首尾幀**（Lenmu 技術上接受，但語法契約不變） |
| **B 畫幅** | 16:9 | `size` = `1280x720` 或 `1920x1080` |
| | 9:16 | `size` = `720x1280` 或 `1080x1920` |
| | 21:9 | **Lenmu 沒有 21:9 尺寸。** 停下告訴用戶，二選一：改鎖 16:9；或 16:9 生成、構圖按 21:9 安全區寫、成片後在沙盒用 ffmpeg 上下裁切。⛔ 禁止靜默改畫幅 |
| **C 交付** | ①②③ | 不變（md / 看板照出）。Lenmu 的 canvas_url 與成片是生成物，隨主文檔一併回報，不佔「件數上限 3」 |
| **D 段縫** | ①–④ | 見 §八 |
| **角色板式** | ① 16:9 四格 | Seedream `2048x1152` |
| | ② 3:2 八格 | Lenmu 的 Seedream 沒有 3:2 尺寸：該板只交提示詞（M1），或請用戶改選 ① |
| **站位方案** | C+ / C++ | 模板圖、白模圖、等軸測圖都用 Seedream `2048x1152` 出；各佔一個圖位 |
| **G 台詞音效** | 視頻內出（默認） | `generate_audio: true`（默認值）。用戶指定走後期時才設 false，並用 `generate_audio`（`byteplus/seed-tts-3.0`）另做配音 |
| **H 素材紅線** | 禁現實真人照片 | 不上傳現實真人照片當參考；平台拒絕就停，不用任何手法繞過審核 |

分辨率不是鎖：默認 720p 報價，用戶要 1080p 再按 `list_models` 重新報價。段長必須是整秒且 ≥4 s。

## 六、素材形態 M2-L（權威定義見總控 `references/asset-delivery-modes.md` §十一）

啟用本引擎後素材形態 = **M2-L（Lenmu 入庫）**：圖由本引擎在 Lenmu 生成、用戶逐張確認、media_id 登記進《資產圖冊》。交付首行寫：

```text
> 素材形態：M2-L（Lenmu 入庫 · 圖號 6 個 · media_id 已登記 · 可圖像級核驗）
```

- 上游「三不一要」照舊：**不索要、不阻塞、不假裝、要聲明**。用戶中途不想繼續生成 → 顯式降回 M1，把已寫好的出圖提示詞與接線單照 M1 交付，不卡流程。
- 部分資產已出圖、部分沒出：沒出的那幾行在掛載表標 `⏳待生成`，引用它們的段不得生成（G7-MOUNT 第 2 條）。

## 七、P2 資產出圖

前置：`sd-asset-engine` 的三清單與出圖提示詞已寫完，資產清單經用戶確認（門禁 1）。

1. **分批報價**：按「場景 → 核心角色 → 關鍵道具 → 站位 / 故事板圖」分批，每批列出張數 × 單價，用戶同意後才出。
2. `generate_image`：`model` 用 `byteplus/seedream-5-5`，`size` 按 §五，`prompt` 用資產引擎產出的出圖提示詞**原文**（不自創瘦身版）。每個資產先出 `count: 2`，不滿意再加。
3. **出圖後你先看圖再給用戶**，逐項對照外觀檔案（發 / 服裝 / 體態 / 年齡感 / 標誌物）、板式格數、圖上文字有沒有錯字。AI 寫中文常出錯字：有錯就重出，或用 `edit_image`（`edit_region`）只改那一塊。
4. 用戶逐張確認 = **鎖定**。鎖定後登記《資產圖冊》（併入主文檔的接線單段，不另起交付文件）：

   | 圖號 | 資產 | 類型 | 只控制什麼 | 不控制什麼 | media_id | 版本 | 狀態 |
   |---|---|---|---|---|---|---|---|
   | 圖1 | 客棧大堂·場景母版 | 場景 | 空間結構、固定傢俱、光源方向 | 人物、劇情動作 | `…` | v1 | ✅ 已鎖定 |

   同時把「圖號 → media_id」寫進 `圖冊.json`（§七·乙的腳本要讀）。
5. **鎖定後不改圖**。要改 = 新版本號 + 新 media_id，並回查所有引用它的段。
6. 同一角色的換裝 / 換形態：用已鎖定的圖當 `reference_media_ids` 生新圖，編號與原形態**相鄰**（上游參考圖順序鐵律 4），且兩個形態不落在同一段。
7. 跨項目複用角色（可選）：`save_character` 把角色圖存進 Lenmu 角色庫（免費，只收 Lenmu 直接生成的圖）。視頻段默認仍用 `reference_media_ids` 掛圖；要走 `characters[]` 必須先 `register_character_avatar`——它會回一段同意聲明，**原文給用戶看，由用戶決定**。

### 七·乙 接線：全局圖號 ↔ 本次調用的圖序

上游的圖號是**全項目統一編號**，每段只掛本段出場的那幾張（《逐段參考圖掛載表》）。Lenmu 送給 Seedance 的引用記號是 **`[Image N]` / `[Video N]` / `[Audio N]`**，N = 本次調用裡該類素材的第幾個（`reference_media_ids` 的順序；`characters[]` 排在其後）。提示詞裡寫「圖1」Lenmu **不認**——沒被 `[Image N]` 引用到的素材，Lenmu 只會在文末自動補一行 `References: [Image 1] [Image 2] …`，模型就不知道哪張圖對哪個角色。所以段 2 掛「圖1、圖2、圖5」時，送進 Lenmu 的提示詞必須寫成 `[Image 1]`、`[Image 2]`、`[Image 3]`。這一步用腳本做，不手改：

```bash
python3 -I sd-lenmu-engine/scripts/lenmu_wiring.py \
  --prompt 段02.txt --wiring 圖冊.json --model 2.5 --aspect 16:9 --duration 28
```

- 輸出 `args`（可直接用於 `generate_video`）、`mapping`（全局圖號 ↔ `[Image k]` ↔ media_id）、`errors` / `warnings`；稿裡的「圖N」「（參考圖N）」「[圖N]」都會改寫成 `[Image k]`，視頻 / 音頻同理；
- **首尾幀模式（僅 2.5）不走本腳本的圖號**：`first_frame_media_id` 固定是 `[Image 1]`，`last_frame_media_id` 緊接其後（有首幀時是 `[Image 2]`）；
- 它同時核對：圖號都有 media_id、參考數量不超模型上限、段長與畫幅合法、提示詞 ≤4000 字（Lenmu 上限）；
- **有 errors 不得生成**。超字數回 `sd-feed-engine` 壓字或拆段；超圖位按上游「群像 / 敵人可省圖」原則減圖；
- 主文檔與看板保留**全局圖號**；改寫後的版本只用於送 Lenmu，回報用戶時把 `mapping` 一併給出；
- 掛載順序沿用上游硬序：場景第一 → 核心角色 → 道具 → 進階形態（腳本按圖號升序排，所以接線單要按這個順序編號）。

## 八、P4 逐段生成

前置：整份投餵稿過 `gate_check.py`，FAIL 清零；逐段過 `lenmu_wiring.py`。

**`generate_video` 參數**（取自腳本輸出的 `args`，再補 canvas_id）：

| 參數 | 值 |
|---|---|
| `model` / `size` / `duration_seconds` | §五；段長取該段【時間軸分鏡】的總時長（整秒） |
| `prompt` | 該段七段式**全文**（含【強制禁止項】），不刪段、不翻譯、不另加說明 |
| `reference_media_ids` | 腳本排好的順序 |
| `generate_audio` | `true`（G 鎖默認） |
| `count` | 1。同一段要多抽幾版時每版都收費，先問用戶 |
| 不帶 | `negative_prompt`（禁項已在七段式裡）；全能參考模式不帶首尾幀 |

**流程：**

1. **首段**：報價（段長 ÷ 5 × `per_5s_at_default_size`，1080p 另算）→ 同意 → 生成 → §九 質檢 → 給用戶看。重點請用戶確認：每張參考圖有沒有對到正確的人 / 場景 / 道具，畫風是否符合畫風鎖。
2. 首段過關後**一次報其餘段的總價**（逐段列時長與金額），同意後按段序逐段送。等待時去檢查上一段。
3. 每段完成後記下 node_id、media_id、實際時長、花費（§十一）。
4. 某段不合格：先判斷是稿的問題還是抽卡問題。稿的問題 → 回對應引擎改稿、重跑機檢、再生成；⛔ 不原封重送，也不在本層直接改提示詞繞過機檢。只壞一小截且模型是 Seedance 2.0 系 → 可用 `reshoot_video` 只重拍那一截（先報價）。
5. 被內容審核擋：按上游「安全轉譯詞典」改寫後重跑機檢再送，不原封重送。

### 段縫（D 鎖）在 Lenmu 的做法

| D 鎖 | 做法 |
|---|---|
| **① 末幀定格承接** | 上一段按上游寫法末 1 秒定格 → `capture_frame`（免費，不帶 `at_ms` = 末幀）得到截幀 media_id → **你先看這張截幀合不合格**（清晰、無字幕、全員入畫、朝向可用）。合格：2.5 全能參考與 2.0 把它登記為新圖號、作為下一段的參考圖成員；2.5 首尾幀模式作 `first_frame_media_id`。不合格：回退到「按結尾狀態重繪段縫參考圖」（Seedream，另報價）。組裝時上一段 `out_ms` = 時長 − 1000，裁掉定格幀 |
| **② 換機位硬切** | 不截幀。`assemble_film` 直接硬切；需要閃白 / 疊化吃掉接口餘量時，在上一段加 `transition_out`（`white` / `dissolve` / `fade` / `black`，200–2000 ms） |
| **③ 空鏡過渡** | 空鏡單獨生成一段。Seedance 最短 4 s，上游要的 1–2 s 靠 `assemble_film` 的 `in_ms` / `out_ms` 裁出；可用同版本便宜型號，須用戶同意 |
| **④ 技巧型轉場** | 畫面內的轉場（相似動作、遮擋、甩鏡）靠提示詞本身；剪接類（閃白、疊化）同 ② 用 `transition_out`。J-cut 這類聲音先入的轉場 Lenmu 組裝做不了，要做就 `export_premiere` 交剪輯軟件 |

`continue_video`（Seedance 2.5 原生續寫）**默認不用**：它只收一段文字、不收七段式的參考圖組，一致性沒有保障。只有用戶明確要「一鏡續寫」時才用，並事先說明這一點。

## 九、P5 質檢（圖像級 · 門禁 5 原樣適用）

M2-L 下圖在手裡，上游門禁 5 的圖像級核驗**真的要做**：

```bash
curl -sSL -o 段01.mp4 "<get_generation 的 url>"
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate -of json 段01.mp4
ffmpeg -v error -i 段01.mp4 -vf "fps=1,scale=320:-2,tile=6x5" -frames:v 1 段01_抽幀.png
```

- 把抽幀拼圖和本段掛的資產圖放在一起看：臉型 / 髮型 / 服裝 / 標誌物是否與圖冊一致，有沒有換臉、雙胞胎分身、多一隻手、道具變形、站位與【站位聲明】不符、畫面出現字幕或水印、末幀有沒有按 D 鎖定格；
- 時長、寬高以 ffprobe 為準，不以 `get_canvas` 回報為準；
- 其餘連續性與聲音項照 `sd-qc-engine` 執行。**聲音、口型、動作流暢度你檢查不了**，在質檢結論裡單列「未核驗項」交給用戶；
- 結論寫進主文檔的質檢段（內部檔案口徑不變），不合格項按 §八 第 4 條處理。

## 十、成片

`assemble_film`（免費）：

- `segments` 按段序列出各段 node_id；D① 的段帶 `out_ms` 裁定格幀，空鏡帶 `in_ms` / `out_ms`；
- `keep_original_audio: true`（台詞與音效在視頻裡）；
- 配樂：按 `sd-qc-engine` 的 BGM Cue Sheet 與 AI 音樂提示詞，用 `generate_audio`（`vertex/lyria-3-clip-preview` 或 `-pro-`，先報價）生成，`music_volume` 0.08–0.15，不蓋過對白；
- `output`：`aspect` 按 B 鎖，`resolution` 720 或 1080；
- 上限：20 個片段、600 秒、音樂 + 音效合計 8 個不同音檔。超過就分集 / 分幕各自組裝；
- 字幕：投餵稿按上游規則禁字幕，成片字幕走後期。`assemble_film` 的字幕需要整條旁白才能做，短劇對白做不了——用看板導出的 SRT，或 `export_premiere` 交剪輯軟件；
- 成片是畫布上的 film 節點，用戶可以在 Lenmu 片編輯器繼續改。

發佈提醒：請用戶按發佈平台的規定標註 AI 生成內容。

## 十一、台賬與交付

## 十二、常見問題

| 狀況 | 處理 |
|---|---|
| 角色對錯圖（A 的臉出現在 B 身上） | 先查 `mapping`：送出的圖序是否與提示詞一致、有沒有手改過提示詞。再查是否同段掛了同一角色的兩個形態 |
| 段 4 突然換裝 | 該段漏掛角色圖：對照《逐段參考圖掛載表》與 `lenmu_wiring.py` 的輸出 |
| 2.0 圖位不夠 | Lenmu 上限 8：群演 / 敵人改純文字；場景只留母版；道具只掛本段用到的 |
| 提示詞超 4000 字 | 回 `sd-feed-engine` 走字數閘門壓字，或縮短段長拆成兩段（多一個段縫，先問用戶） |
| 生成很久沒回 | 不重送。繼續輪詢 `get_generation`；長時間無進展把 generation_id 交給用戶查 |
| 預算不夠 | 停下報告已花 / 尚需。調高預算由用戶決定（`set_budget` 調高會回 `requires_confirmation`） |
| `capture_frame` 或上傳被拒（`media_import_failed`） | Lenmu 儲存空間已滿：請用戶到素材庫清空間或升級，之後重試；生成本身不受影響 |
| `capture_frame` 回 `canvas_busy` | 同一張畫布還有生成在跑：等它結束再截 |
| 全景鏡頭的機位不照提示詞 | 參考圖的機位壓過文字：換一張該機位的場景圖來掛 |
| 用戶要 21:9 | 見 §五 B 鎖行，先定方案再動 |

**實測發現的行為（寫稿與執行時要知道）：**

- **參考圖的機位會壓過提示詞的機位**：場景母版是高角度全景時，寫「平視全景」仍會出高角度。要平視的全景，就另出一張平視的場景圖來掛；
- **走位與細節動作不一定照做**：左右站位可靠，但「走到方桌旁」「碗滑落」這類細節有時不出現；衣著配件（如肩上的抹布）偶爾在個別鏡頭缺漏。這些靠首段質檢發現、回稿修改；
- **儲存空間滿時**：生成仍會成功並回 `warning`，但 `capture_frame` 與上傳會失敗（`media_import_failed` / `storage_quota_exceeded`）。要用戶到 Lenmu 素材庫清空間或升級；
- **畫布有生成在跑時 `capture_frame` 回 `canvas_busy`**：等該生成結束再截；
- **帶參考圖的 `generate_image` 比不帶的貴**（實測 $0.0308 對 $0.022），報價時分開算。

**這些測試沒涵蓋、首段質檢時仍要專門核對的：**

1. 標準版 Seedance 2.5 / 2.0（只測了 Flash 與 Mini）、1080p、9:16、30 秒長段、2.5 首尾幀模式、打戲、四個以上角色、站位白模圖與故事板圖當參考；
2. 聲音、口型、台詞內容無法由 AI 核驗——上述測試的對白是否照稿說出，都未經確認；
3. 改寫後的提示詞不再跑上游機檢（機檢看的是保留全局圖號的主文檔）——改寫只換記號、不動其他文字；測試稿本身沒有過上游閘門機檢。
