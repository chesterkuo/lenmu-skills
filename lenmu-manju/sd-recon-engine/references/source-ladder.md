# 短劇信源分級清單（source-ladder）

> 本文件回答一個問題：**去哪兒找，以及找到的東西能信到什麼程度。**
> 配套：[intel-card.md](intel-card.md)（按什麼格式交）· [recon-evidence.md](recon-evidence.md)（怎麼才不出錯）

## 〇 · 怎麼用這份清單

1. 先按**目標類型**（§五）選 3~5 個源；
2. 按**分級**（§一）決定每個源的結果怎麼採信；
3. 檢索時**逐源記錄**：源名 / 分級 / 拿到什麼 / 時點；
4. 列表中的 **【實測可用】** = 本包實際檢索驗證過能拿到內容；**【待驗證】** = 行業常見但未驗證，用時須自行確認，不得當成已知事實。

**禁止**：把本清單當成"必須全查一遍"的作業單——**按目標選源**，不要為了"查全"耗盡預算。

## 一 · 三級分級判定口徑

| 分級 | 判定標準 | 採信方式 | 寫進情報卡時的措辭 |
|---|---|---|---|
| **T1 一手** | 數據由**平台或官方自己公示**，無第三方加工 | 可直接當事實引用 | 「據〈平台〉〈日期〉公示：……」 |
| **T1.5 準一手** | 專業方**基於官方數據的加工/彙總**（指數、周榜、排行） | 可引用，須標加工方 | 「據〈數據方〉〈日期〉榜單（基於〈原始來源〉）：……」 |
| **T2 二手** | 媒體解讀、自媒體轉述、觀眾討論 | **只作旁證**，不得當數據 | 「有報道稱（未核實原始數據）……」「觀眾討論中（據〈平台〉）……」 |

**分級的唯一依據是"數據的產生方式"，不是"看起來專業不專業"。**
一個排版精美的自媒體榜單文，它仍然是 T2。

## 二 · 國內信源

### 2.1 T1 · 平台官方

| 源 | 能拿到什麼 | 取用方式 | 狀態 |
|---|---|---|---|
| **抖音官方短劇數據中心** | 短劇熱播排名、播放量、完播率、搜索量、互動量綜合出的**熱播指數** | 通常不直接開放，**經數據站轉引**；引用時必須寫「經〈數據站〉轉引，原始來源標註為抖音官方短劇數據中心」 | 【實測可用·經轉引】 |
| **紅果官方熱榜** | 真人短劇榜 / AI 短劇榜 / 漫劇榜，前 N 名 + 公開熱度 | 同上，多經行業周榜或解讀文轉引 | 【實測可用·經轉引】 |

**⚠️ 口徑提醒**：抖音的**「熱播指數」不是播放量**——它是播放量、完播率、搜索量、互動量的綜合值。把熱播指數寫成"播放量"是**事實性錯誤**。

### 2.2 T1.5 · 數據指數站與行業周榜

| 源 | 能拿到什麼 | 取用方式 | 狀態 |
|---|---|---|---|
| `duanjugongcheng.com`（短劇工程 · 紅果短劇榜） | 單劇頁：**歷史最高排名 / 在榜天數 / 當週熱播指數 / 環比 / 同題材對比 / 排名走勢日線**；頁面自標「數據來源：抖音官方短劇數據中心（每日更新）」；另有"劇本心電圖"（加工產物） | 引用時標「據短劇工程〈日期〉榜單走勢，原始數據來源標註為抖音官方短劇數據中心」；**"劇本心電圖"屬該站加工，不得當官方結論** | 【實測可用】 |
| `shortdramacast.com`（周更 · 熱播短劇精選） | **每週熱播短劇 18 選**：按紅果真人/AI 劇/漫劇官方熱榜 + ReelShort TOP Verticals 選片；每劇給集數、主演、一句話簡介、公開熱度（萬）、題材標籤 | 是**彙總型 T1.5**——它整合了多個官方榜，引用時寫「據 SceneTrace〈週期〉周選（選片口徑：紅果官方熱榜 + ReelShort TOP Verticals）」 | 【實測可用】 |

### 2.3 T2 · 媒體解讀與討論

| 源 | 能拿到什麼 | 採信方式 | 狀態 |
|---|---|---|---|
| 今日頭條 / 百家號等**榜單解讀文** | 榜單前 N 名的解讀、看點、槽點、爭議 | 只作旁證；**文中的數據仍須回溯到原始榜單**；可用來**發現線索**（"哦原來有這部劇"），再用 T1.5 求證 | 【實測可用】 |
| 抖音 / 微博 / 小紅書 / B 站 討論與拉片 | 觀眾真實反饋、爭議點、名場面 | 只作 §⑨「觀眾反饋」欄；**註明平台與採集時點** | 【實測可用】 |
| 豆瓣 / 劇評 | 長評、評分 | 同 T2 | 【待驗證】 |

## 四 · 各目標類型的選源速查

| 目標類型 | 首選源（按順序） | 建議檢索詞形態 |
|---|---|---|
| **單劇對標**（國內） | ① 短劇工程單劇頁 → ② 周選站 → ③ 平台搜索 → ④ 解讀文/討論 | 「〈劇名〉 短劇」「〈劇名〉 榜」「〈劇名〉 熱度」 |
| **單劇對標**（海外） | ① verticaldrama.tv → ② CherryBowl → ③ Sonar App 榜 → ④ 外網討論 | 「〈劇名〉 ReelShort / DramaBox」「〈劇名〉 vertical drama」 |
| **題材掃描**（國內） | ① 周選站當期 → ② 短劇工程同題材對比 → ③ 榜單解讀 | 「短劇 周榜 〈當前年月〉」「短劇 〈題材〉 火」 |
| **平台掃描** | ① 周選站 → ② 單劇頁走勢 → ③ 解讀文 | 「紅果 短劇 熱榜 〈當前年月〉」 |
| **外網掃描** | ① verticaldrama.tv 周榜 → ② CherryBowl 周榜 → ③ Sonar → ④ 行業媒體 | 「ReelShort top trending 〈當前年月〉」「vertical drama ranking 〈當前年月〉」 |

**⚠️ 檢索詞必須帶當前時點**：搜"短劇周榜"會拿到任意年份的結果；**必須帶年月**，否則極可能引到過期榜單（這是本引擎最高頻的翻車點）。

## 五 · 獨立信源數怎麼數（輕量版唯一的熱度參考）

輕量版**不算熱度分**。若確實需要一個"有多火"的參考，只數：

```
獨立信源數 = 點名提到該劇的【不同來源主體】個數
```

三條數法鐵律：

1. **同一篇文章被轉載十次 = 1 個來源**（按**原始發佈方**去重，不按鏈接去重）；
2. **同一媒體的不同文章算 1 個**（"一家媒體說了三次"不是三個來源）；
3. **只有逐字點名該劇的才算**——評論裡順帶一提、合集裡羅列的不算。

> 這套數法來自外網公開周榜（CherryBowl）的方法論：**用"有幾個獨立主體在說"替代"某個平台給了多少分"**，因為前者更難偽造。

## 六 · 拿不到的東西（如實告知，不要硬編）

| 拿不到 | 原因 | 正確做法 |
|---|---|---|
| 平台 App 內的完整榜單 | 需登錄 / 客戶端內 | 用 T1.5 轉引並標註 |
| 精確播放量 | 平台不公示絕對值 | 用公示的**相對指標**（排名、熱度指數），**不要換算成播放量** |
| 付費卡點位置 | 需實際觀看 | 寫「未找到」，或據公開討論標註為**推測** |
| 完整分集劇情 | 需實際觀看 | 只寫公開可見的故事骨架 |
| 未公開的完播率 / 成本 | 商業機密 | 寫「未找到」 |

**鐵律：拿不到就寫「未找到」。** 一份誠實標著三個「未找到」的卡，比一份全填滿但有兩處編造的卡**有用得多**。

## 七 · 維護紀律

新增或改動信源時：

1. 更新本表 + 標註分級 + 標註狀態（實測可用 / 待驗證）；
2. **狀態不得越級標註**——沒實測過的源只能標【待驗證】；
3. 外網來源與本表分級口徑一致，新增外網源按同一分級標註，**不得另立一套清單**。
