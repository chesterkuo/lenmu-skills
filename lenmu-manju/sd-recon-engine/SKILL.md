# sd-recon-engine · 素材採風與對標情報引擎（〇·1 素材來源鎖 · 輕量版）

## 一、角色定位

為**「對標一個爆款」類需求**提供採風與情報整理。用戶說「我要對標《XXX》」「幫我扒一下最近什麼火」時，本引擎負責：**把公開信息從全網（含外網）找回來，按固定格式交出去**。

一句話概括本引擎存在的理由：

> **採風的價值不在「找到了什麼」，而在「找到的東西是真的、來源標得清、時點說得明白」。**
> 一份標錯時點的榜單比什麼都沒找到更有害——它會讓整個項目建立在一個已經過期的判斷上。

**⚠️ 輕量版邊界（用戶拍板 · 不得自行擴張）**

本引擎**只做三件事**：

| 做 | 內容 |
|---|---|
| ① 信源清單 | 告訴執行者**去哪找**（見 [source-ladder.md](references/source-ladder.md)） |
| ② 情報卡模板 | 告訴執行者**按什麼格式交**（見 [intel-card.md](references/intel-card.md)） |
| ③ 證據紀律 | 告訴執行者**怎麼才不出錯**（見 [recon-evidence.md](references/recon-evidence.md)） |

**明確不做**（這些屬於"全流水線模式"，本輪不建，禁止臨時發明）：

- ❌ 評分打分 / 入選門檻 / 雙打分機制；
- ❌ 事件聚簇算法 / 熱度公式 / 漲速計算；
- ❌ 持久化台賬 / 持久化數據庫 / 跨輪累計；
- ❌ 定時抓取 / 常駐監控 / 自動出簡報。

需要上述能力時，**如實告知用戶"輕量版不含此項"**，不要用近似說法糊過去。

## 二、與總控和套裝的關係

- **鎖來源**：本引擎只在總控〇·1 素材來源鎖**選定 ③ 對標爆款 或 ④ 熱點速成**時掛載。鎖未選定時不激活。
- **進入方式**：完整流程從總控 **short-drama-director** 進入；總控鎖系統（**〇·1 素材來源** → A·模型 / B·畫幅 / C·交付 / D·段縫）先鎖定，再進入生產層。
- **與其他子技能的關係**：
  - 與 `sd-script-engine` 是**前置供給**關係——本引擎產出的《對標情報卡》是後者的**上游輸入之一**（六階段鏈的「① 來源登記」可直接引用情報卡的來源與結論）。**本引擎不寫劇本、不替代六階段鏈**。
  - 與 `sd-decision-engine` 無直接傳遞——情報卡不決定機位選型。
- **不擁有**：投餵格式（七段式）、機檢腳本、資產編號、語速口徑——權威都在總控。

## 三、觸發詞與進入

**觸發詞**：對標爆款、扒一下、採風、找資料、收集信息、熱點、爆款分析、參考這部、題材調研、品類調研、市場調研。

**用戶直接說觸發詞時**，先聲明一句：

> 完整製作（劇本、資產、分鏡、投餵）請從總控 `short-drama-director` 進入；素材來源請先按總控〇·1 確認（1 原創 / 2 改編 / 3 對標爆款 / 4 熱點速成）。本引擎負責**採風與情報整理**——只交付《對標情報卡》，不寫劇本。

**進入前提**：已確認〇·1 為 ③ 或 ④，且已明確**對標對象**（劇名 / 鏈接 / 題材方向）。對標對象未知時先停下追問——**「對標某部具體的劇」與「看看這個題材最近什麼火」是兩次不同的採風**。

## 四、採風四步（輕量流水線）

> 順序固定，不跳步。每一步的產出都要能落到紙上，**不能只在腦子裡過一遍**。

### 第 1 步 · 定目標

先寫清採風要回答的問題（**一次採風只回答一到兩個主問題**）：

| 目標類型 | 主問題 | 典型觸發 |
|---|---|---|
| **單劇對標** | 這部劇到底怎麼成的？哪些結構我能用？ | 「對標《XXX》」 |
| **題材掃描** | 這個題材最近什麼最火？共性是什麼？ | 「最近重生復仇火什麼」 |
| **平台掃描** | 這個平台的榜單現在長什麼樣？ | 「紅果現在榜上都是啥」 |
| **外網掃描** | 海外市場這個品類在跑什麼？ | 「ReelShort 上什麼類型火」 |

**目標未寫清 = 不開始檢索**（否則會把一整天花在無關信息上）。

### 第 2 步 · 定信源

按 [source-ladder.md](references/source-ladder.md) 選源。**默認檢索預算**：

```
國內源 ≥ 3 個（至少 1 個 T1 或 T1.5）
外網源 ≥ 2 個（對標海外品類時必選）
同一目標檢索 6~12 輪，超出即收手並說明"已達預算"
```

**預算必須向用戶說明**——採風不是無限檢索，超預算時**如實說"還有沒查到的"**，不要用推測補滿。

### 第 3 步 · 檢索與篩選

每輪檢索後，對拿到的東西做**三道快速判斷**（輕量版不評分，只做判斷）：

1. **相關嗎**——跟本次主問題有關嗎？無關的直接丟棄，不要"順手也記一下"。
2. **一手嗎**——是平台公示數據，還是媒體轉述？兩者**分欄記錄，不得混排**。
3. **有出處嗎**——能給出可回訪的來源嗎？給不出的，**丟棄**（寧缺勿濫）。

### 第 4 步 · 落卡

按 [intel-card.md](references/intel-card.md) 的十一字段模板產出《對標情報卡》。**找不到的字段寫「未找到」，不許留空、不許用推測填寫。**

## 五、信源分級（三級 · 判定口徑）

完整清單見 [source-ladder.md](references/source-ladder.md)，判定口徑如下：

| 分級 | 定義 | 短劇領域對應 | 採信方式 |
|---|---|---|---|
| **T1 一手** | 數據由平台/官方直接公示 | 平台官方榜、官方數據中心公示數據 | **可直接引用為事實**，仍須標時點 |
| **T1.5 準一手** | 專業數據方基於官方數據的二次加工 | 數據指數站、行業周榜、外網獨立指數 | 可引用，**須標"經 X 加工"** |
| **T2 二手** | 媒體解讀、自媒體轉述、觀眾討論 | 榜單解讀文、社媒討論、評論聚合 | **只作旁證**，不得當成數據；可用來找線索 |

**鐵律：分級決定採信方式，不決定重要性。** T2 的一條討論可能比 T1 的一條榜單更能說明"觀眾到底在聊什麼"——但它**不能**被寫成數據。

## 六、對標情報卡（核心交付物）

十三項字段模板與填寫口徑見 [intel-card.md](references/intel-card.md)。字段骨架：

```
① 劇名          劇名 / 原文名 / 別名（含"是否為改編"標註）
② 平台與上線    平台 / 上線日期 / 是否仍在榜
③ 體量          集數 / 單集時長 / 總時長 / 是否分季
④ 題材與標籤    題材 / 常見標籤 / 同題材對比位置
⑤ 主創          主演 / 導演 / 編劇 / 出品方（公開可見者）
⑥ 熱度證據      分條列出：指標 / 數值 / 時點 / 來源 / 分級   ← 一行一條，不得合併
⑦ 故事骨架      一句話前提 / 主要衝突 / 結局走向（公開可見者）
⑧ 爽點結構      開局鉤子 / 反轉點位 / 情緒峰值位置
⑨ 觀眾反饋      正面 / 負面分列，各自標來源
⑩ 可遷移點      ★ 本卡最有用的一欄：哪些結構能被新項目複用
⑪ 不可遷移點    ★ 同等重要：哪些是它的專屬資源（演員/平台流量/檔期），抄不來
⑫ 未找到項      明確列出沒查到的字段
⑬ 採集記錄      檢索詞 / 覆蓋源 / 採風時點 / 採風者
```

**⑩⑪ 兩欄是本引擎對用戶的核心價值**——採風不是抄，是**提取結構**。只填①~⑨ 而不填⑩⑪，等於白採。

## 七、證據紀律（六條鐵律 · 違反即返工）

詳見 [recon-evidence.md](references/recon-evidence.md)。

1. **不編造**：沒查到的寫「未找到」；**禁止**用"行業常識"把榜單數字、排名、演員、集數補全。
2. **時點必標**：任何榜單 / 熱度 / 排名**必須帶日期**；**過期榜單不得當成當前熱度**。
3. **來源必標**：每條硬信息帶**來源名 + 鏈接 + 分級**；給不出來源的資訊**不進卡**。
4. **一手與轉述分開**：平台公示數據與媒體轉述**分欄**，禁混排、禁用轉述冒充數據。
5. **事實與推斷分開**：寫「紅果 10/5 榜第 1、公示熱度 5559 萬」是事實；寫「這部劇很火」是推斷——推斷可以寫，但**必須標為推斷**。
6. **熱度只看獨立信源數**：輕量版不算熱度分。若需給一個參考，**只數"多少個獨立來源提到它"**；同一篇文章被轉載十次**算 1 個來源**。

**一句話判據**：這條信息，我能指出它是誰在哪一天說的嗎？不能，就不進卡。

## 九、跨階段交接（本引擎的主要輸出）

交付《對標情報卡》時，**必須**隨卡攜帶一段交接說明：

```
recon_target:      本次採風的目標與主問題
sources_covered:   實際覆蓋的信源（按分級列出）
time_anchor:       所有數據的時點（最早 / 最新）
budget_status:     檢索預算是否用盡（用盡時寫明"未覆蓋部分"）
confidence_note:   本卡中哪些是事實、哪些是推斷、哪些是未驗證
handoff_to:        建議交接給哪一層（通常為 sd-script-engine 的「① 來源登記」）
```

**下游紀律**：

- `sd-script-engine`：情報卡進入「① 來源登記」時，**必須保留來源與分級**，不得把 T2 討論當設定依據；
- **任何下游階段都不得把情報卡里的「推斷」升級成「事實」**。

## 十、禁止越界

- **不**寫劇本、不替代 `sd-script-engine` 六階段鏈；
- **不**另立投餵格式、資產編號、機檢腳本（權威在總控）；
- **不**在輕量版裡私自加回打分 / 門檻 / 聚簇 / 台賬 / 定時抓取；
- **不**用推測補全未找到的字段（寧可交一份"缺項清楚"的卡）；
- **不**把 T2 討論、自媒體解讀寫成數據；
- **不**把過期榜單噹噹前熱度交付；
- **不**把同一篇文章的多次轉載算成多個獨立來源；
- **不**越過鎖邊界——〇·1 未選定 ③/④ 時不啟動採風。
