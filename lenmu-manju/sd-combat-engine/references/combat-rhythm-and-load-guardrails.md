# 打戲節奏與渲染負載護欄

> **本庫定位**：C21（激烈度護欄）管「不許躺平」，本庫管「不許躺平得太用力」。
> 二者缺一，打戲必然在「呆板站樁」與「小孩打架」兩檔之間來回擺。
>
> ⚠️ **本庫是「參考護欄」，不是凌駕於打戲引擎之上的硬閘**：當本庫量化口徑與
> `sd-xuanhuan-engine` / `sd-real-engine` / `sd-combat-engine` 自身規則庫衝突時，
> **以打戲引擎本檔規則為準**（詳見 §七「檔位豁免與放行條款」）。
> 機檢側 C22a~d 一律為 **WARN**，**永不作為 P0 FAIL 阻斷交付**。

## 〇、為什麼建這份庫（病根檔案 · 勿刪）

出片實測（UE5.5，15 秒玄幻打戲稿，機檢 `PASSED / 0 error / 0 warning`），
出片觀感 = **「太呆滯，兩個人撞來撞去，拿手在那動，像小孩打架」**。
逐秒抽幀復盤後定位三條病根，**全部是"規則存在但沒進執行鏈"或"規則缺可機檢口徑"**：

### 病根① 一鏡塞多動作 —— 規則寫了，量化口徑掛在別的引擎裡
- **既有規則**：`combat-iron-laws.md` 鐵律26 第 7 條已明寫
  **「一個 2 秒節點只主攻一個主爆點寫透、每 2 秒主動作 ≤3（單秒絕不超過 3）」**；
  鐵律0 第1步 亦有 **「一鏡一主任務，不貪多」**。**規則不缺。**
- **實測違反情況**：15 秒稿 V2 四鏡的主任務數 = `1 / 2 / 4 / 3` 個（鏡頭3 一次塞了
  捅入 + 角力 + 拽倒 + 滾地互毆 = 4 個主任務），**逐鏡違反鐵律0 第1步**。
- **★ 真正病根在接線**：打戲引擎的「六步流程」末端第 5 步自檢掛的是
  `combat-iron-laws 鐵律45 五維交替檢驗 + combat-intensity-guardrails（C21）`，
  **鐵律26 第 7 條這條"動作數上限"從未被抬進自檢閘口**；
  而實際交付走的是**總控七段式投餵鏈**——那條鏈上沒有任何一站接這條上限。
  → **規則在 A 引擎，執行在 B 鏈，A 的硬約束在 B 上失效。**
- **機檢盲區**：C1~C26 全 35 條 C 碼中，唯一帶"上限"語義的是 C14（OS/VO 配額），
  **打戲域零條上限型判據**。→ 稿子動作越密，C21 越容易滿足，**護欄在方向上反向鼓勵內捲**。
  *（※「35 條」為 2026-10-09 建庫時口徑；該盲區已由本庫 §五 新增 **C22a 上限型判據**修復。2026-10-10 六維審計後全包機檢口徑為 **C1~C26 · 子檢查碼共 104 條**（2026-10-24 補 C40a~d 群像行為缺失；2026-10-11 複核實測補 **C7b 鏡行解析元檢查** 與 **C7c 站位人物賬解析元檢查**；2026-10-11 補 **C18m 段縫景別落差**；2026-10-12 補 **C26a~d 錨點繼承門**；2026-10-13 補 **C27a~d 對話戲節奏與台詞密度下限**；**2026-10-13 項目體檢補 C18n 人物特寫佔比**），見 `sd-qc-engine/references/machine-check-manual.md` §二。）*

### 病根② 單鏡勻速 —— 只有"鏡與鏡之間"的節奏維度，沒有"鏡內"維度
- **既有規則**：鐵律45 五維交替之「④速度節奏交替」要求
  `超高速連段↔凝滯衝擊幀↔短暫蓄勢↔高強度爆發↔短暫收勢喘息，每5-8鏡做一次節奏波`。
- **★ 真正病根**：① 該條判據是 **"禁止任何一維連續 5 鏡不變" = 下限型**，
  只管"不許一直不變"，**沒有"一鏡內部必須有速度層次"的概念**——
  於是**全片四鏡都寫成勻速位移，它完全查不出**（實測該稿五維交替全部合規）。
  ② 鐵律26 九要素（①鏡頭空間起點 ②高度朝向 ③人物動作 ④能量生命週期 ⑤特效尺寸
  ⑥參照物 ⑦命中反饋 ⑧環境結果 ⑨鏡頭落點）**九項全是空間/材質/靜態結果，
  零項是"時間拍"** → 寫作清單層面，"一鏡勻速"是合法產出。
- **實測**：V2 稿「蓄力/預備」命中 **0 次**（出手即最快、勻速到底）。

### 病根③ 缺全身景別 —— 規則要求"交替"，沒規定"必須含全身"
- **既有規則**：鐵律45 ③景別機位交替要求 WS/EWS/FS/MS/CU/ECU 六檔交替。
- **★ 真正病根**：只要求"交替"，未要求"**必須含全身檔**"。
  V2 稿景別序列 = `中近景→近景→特寫→大遠景`，
  **從貼身檔一步跳到超遠景，全片無任何全身入畫的中景/中全景**
  → 貼臉時看不見重心與位移幅度，位移只剩"撞來撞去"的讀感。

### 病根④（底層）"模型渲染能力上限"從未被寫下來
全包 129 份規則庫中，**"視頻模型 3 秒內可靠渲染約 2~3 個獨立動作單元"這條硬約束零命中**。
沒有這條，任何"動作數上限"都只是無根之木——寫規則的人不知道上限從哪來。

## 一、渲染負載硬上限（病根①④ 的唯一口徑）

### 1.1 獨立動作單元（Independent Action Unit, IAU）
**定義**：一次**獨立可命中的打擊或位移動作**。判定詞表（機檢 `COMBAT_IAU_RE`）：

```
撩斬 斬中 劈中 劈碎 劈開 挑刺 刺中 捅入 橫掃 豎劈 剪斬 掃腿 掃堂 踢中 踹中
頂中 肘擊 膝頂 點中 拍中 砸中 撞中 撞碎 撲擊 砸在 撞在 劈在
抓住 揪住 扼住 勒住 擒住 抓住腳踝 抓住手腕
格擋 架住 架開 格開 磕開 硬接 硬扛 對撞 交擊 兵器相擊 拳掌相交
```

**同一次接觸的多寫只算 1 個**（例：`格擋 + 硬接` 是同一次架住，`拍中 + 撞中` 是同一次命中）。
機檢按**去重後的詞頻**計數，不按分句數。

### 1.2 上限（**上限型判據 = 不許過載**）

| 鏡長 | IAU 上限 | 依據 |
|---|---|---|
| ≤ 2s | 2 | 鐵律26「單秒絕不超過 3」的保守化 |
| 3s | **2** | 實測：3s 內塞 5 個 → 模型只渲染第一個，其餘丟失 |
| 4s | 3 | |
| 5s | 3 | |
| ≥6s | 4 | 每 +3s 放寬 1 個 |

> **為什麼 3s 只能是 2 而不是我原來以為的 3**：實測模型在 3 秒內可靠渲染 **2~3 個 IAU**，
> 但**一旦超過 2 個，第 3 個之後保質率驟降**。留 1 個冗餘 → **3s 定為 2**。
> 違反此條的症狀是**可辨識的**：多動作稿出片必現"貼臉互毆 + 後半段動作消失"。

### 1.3 一鏡一主任務（鐵律0 第1步的量化落地）
每鏡只能有 **1 個主任務**，取自鐵律0 第1步六選一：
`證規模 / 證力量 / 證速度 / 證招式 / 證招式軌跡 / 證情緒`。
判定：若某鏡 IAU 中屬於**不同動作類型**（拳腳/兵器/投技/摔擒拿/突刺/反彈/暗器/大招）的
**≥3 類**，即判"一鏡多任務"。機檢 `C22a` 同時查這兩項。

## 二、鏡內速度四拍（病根② 的唯一口徑）

### 2.1 四拍定義
**每一鏡內部**必須具備下列節拍，**順序不可顛倒**：

| 拍 | 語義 | 時長佔比 | 判定詞表 |
|---|---|---|---|
| **① 起（慢）** | 蓄力/預備/重心下沉/微調站位 | 15~30% | `沉肩 壓低重心 碾碎 繃緊 屏息 蓄 預備 屈膝 後仰 重心下壓` |
| **② 爆（快）** | 蹬地暴起/驟出/疾掠 | 極短 | `暴起 驟然 猛地 瞬間 陡然 疾掠 撲上 衝出 甩出 彈射` |
| **③ 頓（停）** | 命中瞬間畫面時停 | 2~3 幀 | `頓住 時停 頓幀 定格 凝固 壓在 靜止` |
| **④ 收（慢）** | 卸力/穩住/滑步/落地緩衝 | 20~35% | `卸力 穩住 側滑 滑退 收勢 滑步 落地緩衝 後撤 站定 單膝` |

> **頓拍是全片最關鍵的一拍**：命中瞬間畫面定住 2~3 幀，是"打到了"的唯一視覺證據。
> 缺頓拍 = 觀眾沒看見"擊中" = 再多動作也讀作"在亂動"。

### 2.2 逐鏡判定（**不是全片總數**）
- **必須逐鏡各含 ≥1 處四拍**。
- ⚠️ **禁用"全片總數 ≥ 鏡數"口徑**：該口徑下"鏡頭1、4 全空 + 鏡頭2、3 各塞兩處"
  總數照樣夠，**一處寫滿、一處全空能矇混過關**（構建期實測該缺陷，
  改為逐鏡判定後立即咬出兩處真缺口）。
- ⚠️ **節拍統計須剔除純結構標註**：`（起手拍，慢）`這類括號標籤是給人看的結構說明，
  計入命中 = **護欄被自己的標註餵飽**，刪掉真實描述反而照樣通過。
  但**不得連坐含實寫正文的括號塊**（如`（命中瞬間畫面頓住兩幀，命中點炸開一圈衝擊波）`——
  這是正文，必須保留）。正法：**只剝離 ≤6 字的純結構標籤**。

### 2.3 速度層次作為景別之外的第五維
鐵律45 的速度維度管"鏡與鏡之間"，本條管"**鏡內**"。兩者疊加才構成完整節奏：
- 鏡間：鐵律45 ④速度節奏交替（每 5~8 鏡一個節奏波）
- 鏡內：本節四拍（每鏡都有）

## 三、全身景別下限（病根③ 的唯一口徑）

### 3.1 硬下限
**每 2 鏡至少 1 鏡為全身入畫**（`中全景 / 中景 / 全景 / 大遠景` 中，
須**至少 1 鏡能看清身體重心與雙腳位置**）。
- 全片 `中景+中全景` 合計 **≥ 半數鏡數**。
- ⚠️ **貼臉檔（特寫/近景/中近景）連續不得超過 2 鏡** —— 第三鏡必須切回全身檔，
  否則觀眾丟失空間參照，動作讀作"原地亂動"。

### 3.2 為什麼這條不可省
打戲的說服力來自**身體力學**：蹬地、轉胯、腰、肩、手的完整發力鏈，以及重心轉移。
全身檔是**唯一能同時看見"重心"與"位移量"**的景別。
貼臉檔只能看見接觸點，看不見"誰把誰推到哪裡" → 觀感即"撞來撞去"。

## 四、機檢載體

| 子碼 | 判據 | 方向 | 閾值 |
|---|---|---|---|
| **C22a** | 單鏡獨立動作單元（IAU）超上限 | **上限型** | 按 1.2 表 |
| **C22b** | 一鏡多任務（動作類型 ≥3 類） | **上限型** | ≥3 類 |
| **C22c** | 鏡內速度四拍逐鏡缺拍 | **下限型** | 逐鏡 |
| **C22d** | 全身景別不足 / 貼臉檔連續 >2 鏡 | **下限型** | ≥半數；≤2 連 |

- **觸發門**：與 C21 共用 `--combat on|off|auto`（默認 auto，打戲信號詞達閾值即啟用），文戲稿跳過。
- **不改 C21**：C21 管激烈度（不許躺平），C22 管負載與節奏（不許過載/不許勻速），二者獨立。
- **C22c 的統計實現**：必須走 `strip_struct_annot()` 剔除純結構標註後再逐鏡計數（見 2.2）。

## 五、寫作期自查（掛在打戲引擎第 5 步，與 C21 並列）

出稿前逐鏡問 6 問，任一為"否"即返工：
1. **這一鏡有幾種獨立動作？**（>2 → 拆鏡或刪動作）
2. **這一鏡的動作類型是否 ≤2 類？**（≥3 → 只留 1 類）
3. **這一鏡有沒有"起—爆—頓—收"四拍？**（缺任一拍 → 補）
4. **命中瞬間畫面定住了嗎？**（無頓幀 → 觀感必然糊）
5. **這一鏡能看見身體重心嗎？**（貼臉檔 → 檢查是否連續超 2 鏡）
6. **抽掉全部特效後，剩下的純動作連得成一段打得起來的武打嗎？**（C21 護欄⑥，本條不替代）

### ⚠️ 與鐵律26 第 7 條的口徑差異（必讀，避免誤判）
- 鐵律26 原文：**「每 2 秒主動作 ≤3（單秒絕不超過 3）」** —— 這是**打戲引擎內部**的節點口徑。
- 本庫 1.2 表：**3 秒鏡 ≤2 個 IAU** —— 這是**投餵稿**的口徑，**比鐵律26 更嚴**。
- **兩者不衝突**（本庫更嚴，取嚴者）；差異原因：投餵稿的單鏡是"直接渲染單元"，
  而鐵律26 的 2 秒節點是"編織單位"，後者還要熔進同一條長句、可被後續節點稀釋。
- **判罰以本庫（投餵稿口徑）為準**，因為出片質量由投餵稿決定。

## 六、出片復盤義務（本庫獨有 · 反向約束）

**任何投餵稿出片後，必須抽幀復盤並回填本庫**：
1. 抽幀：`-vf "fps=1"` 每秒一幀 + `tile` 拼網格圖，**逐幀看**，不聽描述。
2. 回填三問：
   - 出片是否**每鏡都看得見身體重心**？（否 → §3 閾值需下調）
   - 出片是否**每鏡都有命中頓幀**？（否 → §2.1 頓拍需加嚴到"必須顯式寫幀數"）
   - 出片是否**出現"動作消失"**？（是 → §1.2 上限需下調）
3. ⚠️ **機檢 PASSED ≠ 出片好看**。稿子機檢 `PASSED / 0 error / 0 warning`，
   出片仍是"呆滯"。**報告護欄結論時，必須同時給出機檢數據與出片抽幀結論，兩者不可互替。**

## 七、檔位豁免與放行條款（★讓行 · 打戲引擎規則優先 · 2026-10-12 用戶裁定）

> **一句話**：**本庫讓行於打戲引擎本檔規則**。本庫 §一~§六 提供的是**通用工程參考線**；
> 打戲檔（R1 寫實 / R2 通用高燃 / R3 玄幻）持有完整領域規則庫，**衝突時以引擎本檔為準**。
> C22a~d 是 **WARN 參考**，**不是 P0 FAIL**；⛔ **不得為消除告警而把打戲改呆**。

### 7.1 為什麼必須讓行（病根⑤：單樣本外推）

本庫 §一~§六 的量化口徑——`3s 鏡 ≤2 個 IAU` / `逐鏡四拍` / `全身檔 ≥ 半數鏡` / `貼臉檔連續 ≤2 鏡`——
**全部來自 2026-10 一次 UE5.5、15 秒、單場"一對一貼身對拆"稿的逐幀復盤**（見 §〇 病根檔案）。

- 單樣本對「一人一場、近身互毆」有效；
- 但**外推**到「近景機槍對招連招段 / 槍戰狙擊 / 追車 / 暗殺 / 多人圍殺 / 萬劍歸宗 / 對軍清場 / 術法對轟 / 巨獸法相」
  會**反向壓制**：把本該連排的近景對招拉開成遠景、把連招拆成單招、給每鏡硬塞慢動作 → **觀眾讀到的就是"呆板"**。
- 這不是"護欄不夠嚴"，而是**把單一戲型的量化線當成了全戲型的法規**。

### 7.2 豁免表（先判檔 · 再決定是否採納告警）

| 場面類型（先定檔） | 豁免/放寬項 | 放行口徑（改按什麼執行） |
|---|---|---|
| **R1 寫實 · 近景機槍對招 / 連招段**（序列化招式鏈） | C22a 上限、C22c 逐鏡四拍、C22d 貼臉檔連續上限 | C22a 改按 `combat-iron-laws.md` 鐵律26 節點口徑（每 2 秒主動作 ≤3）；C22c 改為「**段落層面**至少完整出現一次起-爆-頓-收」，**不再逐鏡強制**（**鏡間**速度交替仍以鐵律45④ 為權威）；C22d 貼臉檔連續上限放寬至 **≤4 鏡**——機槍對招本就是貼身檔連排，這是本檔設計而非缺陷 |

### 7.3 保底（豁免之後仍然成立的兩條）

無論哪一檔，以下兩條**不放行**：

1. **不得整場零接觸、零位移、無收束**（"對峙 → 站著發光 → 對峙"的空轉模板）；
2. **相鄰區間的機位不得完全相同地連排 ≥3 段**。

即：**豁免的是"量化上限"與"幾何模板"，不是"打得起來"本身。**

### 7.4 執行口徑（寫進《改動複驗報告》）

- 機檢 `--combat on|off|auto` 輸出的 C21/C22 是 **WARN 參考**；出稿時**先判檔、再逐條決定採納或豁免**，
  採納或豁免的理由寫進《改動複驗報告》（`sd-qc-engine`）。
- ⛔ **禁止**為了消 C22 告警而：拆掉引擎的招式序列、把連續的近景對招拉開成遠景、
  給每一鏡硬塞一段慢動作、或把大場面寫成一鏡一動作——**那是把"呆板"當合規**。
- 豁免不影響 §7.3 兩條保底；也不影響 C21/C22 之外的門（結構門 / 語義風險門 / 畫風鎖門照舊）。
