# 外部劇本潤色層（EXTERNAL_SCRIPT_POLISH · 劇本適配前置環節）

## 一、這一層為什麼必須存在（結構性斷鏈）

本包分鏡引擎有一條**鐵律**：**每句台詞必掛「具體神態 + 具體動作」兩項，缺一 = 廢鏡重寫**（`sd-storyboard-engine/SKILL.md`）。

這條鐵律**默認上游是本包劇本**——`sd-script-engine` 的產出自帶神態、動作相位、狀態欄、台詞重音、場次因果脊柱。**閉環成立**。

但**外部標準劇本**（網文改編稿 / 平台約稿 / 第三方編劇稿 / 用戶自帶劇本）通常只有：

```
場景標題 + 「角色：台詞」 + 少量結果性動作提示
```

**沒有微表情、沒有動作相位、沒有狀態欄、沒有台詞重音、沒有場次因果連接。**

```
外部標準劇本
     ↓
分鏡引擎鐵律要求「每句台詞掛神態 + 動作」
     ↓
執行者無米下鍋 → 二選一：
    ① 現編（= 越權改用戶劇本，用戶沒授權）
    ② 寫空（= 撞鐵律，判廢鏡重寫）
```

**結論：本包此前是「自產自銷閉環」，缺一個對外來劇本的適配入口。** 本層就是那個入口。

> **用戶原話（2026-10-13）**：「這個分鏡關聯的是**你的 skill 出來的劇本**（因為你的 skill 出來的劇本有表情和動作的描述），**但外部的標準劇本不一定有微表情和豐富的動作描述，針對外部劇本應該要有一個劇本潤色的動作，讓它適配你的分鏡**。」

## 二、觸發條件（何時必須走潤色層）

**同時滿足前兩項 + 命中第三項任一子條 → 必須走潤色層**：

| 序 | 條件 | 說明 |
|---|---|---|
| A | **〇·1 素材來源 = ② 改編** | 原創（①）不走——原創走完整六階段鏈，產出即自帶表演層 |
| B | **輸入物是「已成型的劇本」** | 有場次劃分 + 台詞行；**小說 / 大綱 / 梗概不是**（走完整六階段鏈） |
| C | **檢測到下列任一缺失**（外部劇本體檢） | ① 台詞行無神態標註；② 無動作相位（只有結果、無過程）；③ 無狀態欄（人物狀態/情緒/傷勢/道具位置）；④ 無台詞重音標註；⑤ 無場次因果脊柱 |

**C 項五條檢測（逐條打勾，命中 ≥1 即觸發）**：

```
□ 台詞行形如「角色：台詞」——角色名後無（語氣）位、鏡行無神態描寫？
□ 動作提示是結果性的（「他生氣了」）——而非過程性的（「下頜收緊、指節抵住桌沿」）？
□ 沒有狀態欄——人物此刻的情緒/傷勢/道具在手位置無從查證？
□ 關鍵台詞沒有重音字標註？
□ 相鄰場次之間沒有因果連接——讀不出「這一場為什麼接在那一場後面」？
```

**免走條件（三項全成立才可免）**：外部劇本**已自帶**神態 + 動作相位 + 狀態欄。此時直接進 P3 分鏡，但需在交接卡首行聲明「外來劇本自帶表演層 · 免潤色」。

⛔ **〇·1 = ① 原創 / ② 改編但輸入是小說大綱 → 不走潤色層**（走完整六階段鏈，見 `six-stage-pipeline.md`）。潤色層**只服務"已成型的劇本"**，不替代編劇鏈。

## 三、潤色邊界（硬約束 · 不可越權）

**潤色只補「表演層 + 調度層」，嚴禁觸碰「台詞層 / 事件層 / 人物層」。**

| 層 | 允許 | ⛔ 禁止 |
|---|---|---|
| **台詞層** | ❌ 一律不動 | 改台詞、加台詞、刪台詞、改說話人、改語序 |
| **事件層** | ❌ 一律不動 | 增刪事件、改事件順序、改事件結果、改場次歸屬 |
| **人物層** | ❌ 一律不動 | 改人物關係、性格、身份、動機、結局 |
| **表演層** | ✅ 只補 | 神態（FACS 化）、動作相位、視線落點、語氣位 |
| **調度層** | ✅ 只補 | 站位、進出場、場次過渡、道具在手位置與狀態 |

**⚠️ 發現硬傷怎麼辦 —— 不得直接改**：

潤色過程中若發現台詞 / 事件 / 人物層存在硬傷（**人物降智、因果斷裂、動機不成立、時間線矛盾**），**不得順手改**（那是越權重寫）。**另出《潤色發現清單》（`POLISH_FINDINGS.md`）交用戶裁定**——用戶決定改則回 `sd-script-engine` 六階段鏈處理，不改則原樣保留。

**判據一句話**：**潤色後的劇本，用戶能指著任何一句台詞說「這句還是我寫的原話」——改了台詞就是越界。**

## 四、潤色產出物（六件 · 逐件交付）

| # | 產出物 | 從什麼補到什麼樣 | 落點 |
|---|---|---|---|
| **1** | **台詞神態補全** | `角色：台詞` → 台詞行補 `（語氣）` 位 + 鏡行補**具體神態**（FACS 四區：眉/眼/顴頰/嘴下頜） | 逐台詞行 |
| **2** | **動作相位補全** | 結果性動作（「他生氣了」）→ **過程性動作**（起-持-落三拍：`下頜繃緊 → 保持 → 牙關鬆開`） | 逐動作提示 |
| **3** | **狀態欄補全** | 無狀態 → 逐場補**人物狀態 / 情緒 / 傷勢 / 道具在手位置**（這是資產層與連續性台賬的輸入） | 逐場次 |
| **4** | **台詞重音標註** | 無重音 → 逐關鍵台詞標**重音字**（表情峰值須對齊重音字，非台詞開頭） | 逐關鍵台詞 |
| **5** | **場次因果脊柱** | 場次之間無連接 → 逐場補 `前因 → 觸發 → 後果`，標在**場次卡**上（與 `episode-planning.md` §CAUSALITY_AND_RELATION_TABLE 同構） | 逐場次 |
| **6** | **場次過渡設計** | 相鄰場次硬接 → 按 `TRANSITION_AS_BEAT` **四類型**（動作橋 / 空鏡敘事 / 聲音橋 / 硬接需理由）補過渡設計 | 逐相鄰場次 |

**潤色稿格式**：**保持用戶原劇本的場次編號與結構不變**，只在行內**就地標註**（推薦用行內括號夾註，不新增段落層級），確保「原稿 vs 潤色稿」可**逐行對照**。

```
【潤色示意】（左＝原稿，右＝潤色後；台詞一字未改）

原稿：  李明：我不籤。
潤色後：李明（壓抑、一字一頓）：「我不籤。」
        ▸ 神態：眉壓低、下眼瞼繃緊、唇線抿成一條直線（AU4+AU7+AU24）
        ▸ 動作相位：指節先抵住桌沿 → 保持 → 收回手插進口袋
        ▸ 重音：**不**籤
```

## 五、回籤流程（強制 · 不得跳過）

**潤色產出物 = 創作決定**——補出來的神態 / 動作 / 過渡**不是用戶寫的**。

```
潤色稿完成
     ↓
輸出《潤色確認卡 POLISH_CONFIRM_CARD.md》交用戶
     ↓
用戶逐條過 —— 三條路：
    ① 全部接受 → 潤色稿凍結，進 P3 分鏡
    ② 部分駁回 → 被駁回處按「不補」處理（分鏡層該鏡走中性表演，不得現編）
    ③ 全部駁回 → 放棄潤色，回用戶原稿（分鏡層報 BLOCKED_REPORT 說明無米下鍋）
     ↓
用戶確認後才進 P3 —— ⛔ 不得默認自動通過
```

**《潤色確認卡》必須逐項列出**：補了哪句台詞的什麼神態、補了哪個動作的什麼相位、補了哪些過渡設計——讓用戶**能逐條駁回**，而不是「整體接受/拒絕」一個黑箱。

## 七、與下游的接線

| 下游 | 從潤色稿拿到什麼 |
|---|---|
| **sd-asset-engine（P2）** | 從**狀態欄**提取人物外觀/道具/場景三清單 |

## 八、⛔ 禁止事項（違規即退回）

1. ⛔ **改台詞**——哪怕改得更好、更短、更順口；
2. ⛔ **改事件**——增刪、調序、改結果一律禁止；
3. ⛔ **改人物**——關係、性格、身份、動機、結局一律禁止；
4. ⛔ **不加工直接進分鏡**——檢測到缺失卻不走潤色層，等於把「無米下鍋」問題推給下游；
5. ⛔ **潤色後不回籤**——補出來的表演層是創作決定，未經用戶確認即進分鏡 = 越權代筆；
6. ⛔ **把《潤色發現清單》裡的硬傷順手改掉**——只報告，由用戶裁定。

## 九、與「六階段鏈」的分工（改前必讀）

```
〇·1 = ① 原創     → 完整六階段鏈（本層不參與）
〇·1 = ② 改編
    ├── 輸入是小說/大綱/梗概 → 完整六階段鏈（本層不參與）
    └── 輸入是成型的外部劇本 → 【本潤色層】→ P2 資產 → P3 分鏡
                    ↓ 發現台詞/事件/人物硬傷
                  《潤色發現清單》→ 用戶裁定 → 回六階段鏈
```

**一句話**：**六階段鏈是「造劇本」，潤色層是「接劇本」。** 前者產出，後者適配。**顛倒或合併兩者 = 越權**。
