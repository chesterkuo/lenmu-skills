# 來源登記與源頭處理

> 精編自《靈境AI劇本改編 skill》（6階段編劇鏈）

本文件覆蓋階段①的三件事：來源登記（SOURCE_MANIFEST 與長篇分塊處理）、源頭人物挖掘（全篇角色證據掃描）、源本改編與裁剪（原作主導改編與刪減審計）。前兩項是階段①②的主輸入，第三項在階段⑤正式劇本中執行。

## 一、來源登記

### 1.1 SOURCE_MANIFEST

`SOURCE_MANIFEST.json` 為每塊來源記錄：

- `source_id`：穩定來源鍵。
- 文件或消息標識。
- 章節起止。
- 字符或頁碼範圍。
- 內容哈希。
- 讀取狀態、提取狀態和合並狀態。

### 1.2 材料類型自動識別

自動識別輸入是完整小說、小說節選、大綱、已有劇本或續接項目；自動識別已有交付物和當前最後鎖定階段，不要讓用戶手工說明內部階段編號。模式未確定前只登記來源和識別材料類型，不生成正式 IP。

### 1.3 長篇分塊與合併

- **分塊**：優先使用自然章節邊界；沒有章節時再按長度分塊。分塊之間保留小範圍重疊只用於識別承接，事件不得重複入賬。
- **合併**：比較姓名與別稱、時間線、身份、關係、地點、道具、傷勢、知識邊界和伏筆狀態。相同事實合併來源；變化事實保留生效事件。
- **衝突**：先按原文證據強度和時間順序解決。無法解決時保留兩個候選，分別列證據並寫入 `OPEN_ITEM`，不得選擇更戲劇化的版本冒充事實。
- **續接**：新批次只處理未覆蓋內容哈希。續接前讀取現有事件與人物賬本，不重新編號已經鎖定的 ID。

### 1.4 項目狀態文件

每個項目創建：

- `projects/<project-id>/SCRIPT_PIPELINE_STATE.json`
- `projects/<project-id>/PROJECT_MANIFEST.md`
- `projects/<project-id>/00_source/SOURCE_MANIFEST.json`

階段狀態只允許：`NOT_STARTED / IN_PROGRESS / AWAITING_CONFIRMATION / AWAITING_USER_DECISION / LOCKED / STALE / BLOCKED`。鎖定輸入發生改變時，從變更階段向下傳播 `STALE`，不得靜默沿用舊版本；受影響的劇本、資產與下游包同步標記。

## 二、源頭人物挖掘：全篇角色證據掃描

IP 設計必須來自整本已提供材料，而不是隻讀簡介、開篇或作者形容詞。目標是得到可複核的全篇角色證據，再決定哪些內容屬於穩定內核、階段狀態、他人誤解或創作候選。

### 2.1 P1 分塊掃描

長篇按章節、卷或自然劇情塊處理。每塊建立 `CHARACTER_EVIDENCE_LEDGER`：

| 字段 | 內容 |
|---|---|
| evidence_id | `CE-####` |
| character_id | 穩定角色鍵 |
| source_trace | 來源與準確範圍 |
| evidence_type | 作者說明/自述/他評/重複行為/關鍵選擇/失敗後果/關係行為/視覺聲音 |
| context | 當時目標、壓力、知識和關係狀態 |
| action_or_line | 人物實際做了什麼或說了什麼 |
| cost_or_result | 行為產生的代價與結果 |
| reliability | HIGH/MEDIUM/LOW |
| possible_meaning | 可支持的人格結論，不直接冒充事實 |

證據權重默認：重大代價下的重複選擇 > 造成後果的行動 > 多次穩定行為 > 人物私下自述 > 他人評價 > 作者標籤。評價與行動矛盾時同時保留，交給 P2 判斷，不靜默選擇更討喜的版本。

### 2.2 P2 全篇合併

合併所有 P1 證據，分別判斷：

- `STABLE_CORE`：跨階段仍穩定的價值選擇。
- `START_STATE`：人物早期使用的自保策略。
- `CONTEXT_STATE`：僅在特定身份、關係或危險下出現。
- `PUBLIC_MASK`：人物希望別人看見的樣子。
- `PRIVATE_SELF`：獨處或安全關係中出現的行為。
- `ARC_CHANGE`：由事件和代價觸發的真實變化。
- `CONTRADICTION_TO_RESOLVE`：來源內部尚未解釋的衝突。
- `OPEN_ITEM`：已提供材料無法回答。

全篇角色證據必須覆蓋：首次出場、至少一次主動目標、至少一次受壓選擇、至少一次失敗或代價、主要關係變化、能力邊界、結局或當前最新狀態。來源確實沒有某項時寫 `OPEN_ITEM`，不得自動發明童年傷口或秘密。

### 2.3 角色層級

- `S`：作品情感和商業識別核心；建立完整靈魂、視覺、聲音、關係與成長系統。
- `A`：長期核心對手、搭檔或關係對象；完整建立，但視覺層級不得搶走 S 角色主識別。
- `B`：反覆出現且承擔獨特功能；只建立必要靈魂、聲音和關係邊界。
- `C`：一次性功能人物；留給資產階段，不在本階段過度包裝。

層級看故事影響和長期複用，不看財富、戰力或戲份單一指標。

### 2.4 通用性防線

測試案例、參考劇本和流行角色只能貢獻抽象方法，不能貢獻默認答案。檢查輸出中是否出現與本項目來源無關的固定職業、道具、色彩、創傷、親屬失蹤、重生秘密或身份揭露；出現即標記 `GENRE_TEMPLATE_IMPRINT`。

### 2.5 完成條件

`source_coverage.coverage_status` 只有在全部已提供來源都完成 P1、完成 P2 合併、別名和時間狀態衝突已處理、`unresolved_ranges` 為空時才能寫 `COMPLETE`。尚未收到小說後續不算遺漏，但必須明確「當前只覆蓋已提供範圍」，終局類字段保持 `OPEN_ITEM`。

## 三、源本改編與裁剪：原作主導改編與刪減審計

> 本節在階段⑤正式劇本中逐集執行；階段②③建立改編藍圖時同樣遵循其核心原則。

### 3.1 改編不是另寫故事

階段⑤的創作空間存在於「如何把原作寫得更可看、更可演」，不在「替原作發明更刺激的主線」。判斷一項改動能否執行，先問：

1. 它是否改變觀眾對事實、責任、關係、規則或結局的判斷？
2. 它是否改變人物為什麼行動、何時知道、能做什麼或必須付什麼代價？
3. 刪除它後，後續事件、伏筆、情緒和台詞是否仍能自然成立？

任一答案涉及核心變化，就不是階段⑤可自行處理的連接優化。

### 3.2 四級來源比對

每集建立 `SOURCE_ADAPTATION_PACKET`：

| 層級 | 核對內容 | 不一致時處理 |
|---|---|---|
| 小說原文 | 事實、順序、人物動機、知識邊界、關鍵台詞 | 原文為最高事實權威 |
| 故事聖經 | 事件 ID、因果、世界規則、關係和伏筆 | 修正結構化誤讀或退回階段③ |
| 分集卡 | 主事件歸屬、單集承諾、局部兌現、主鉤子 | 退回階段④，不在劇本中靜默改動 |
| 正式劇本 | 場次、行動、對白、表演和節奏 | 重寫至與前三層一致 |

每個條目至少記錄：

```yaml
source_event_id: EVT-0001
source_trace: "SRC-001:第12—15段"
adaptation_mode: KEEP
source_function: "建立主角為何必須拒絕交易"
script_scene_ids: ["EP001-SC02"]
preserved_result: "拒絕仍由保護弟弟的動機觸發，並導致失去資源"
causal_protection: "EP002 的追責和關係裂痕仍有成立條件"
decision_reason: "核心選擇，必須原意保留"
```

### 3.3 七種改編動作

**`KEEP`**：用於主線因果、核心選擇、關鍵關係、世界規則、伏筆回收和不可替代的關鍵台詞。允許口語化和可視化，但事實、功能、關係位置和發生條件不變。

**`COMPRESS`**：壓縮重複解釋、同一結論的多次內心獨白、無獨立結果的往返過程。壓縮後仍要讓觀眾知道：人物為何採取行動、對手如何反應、什麼發生了變化、代價或情緒為何成立。

**`MERGE`**：合併同功能場次、過程或次要人物功能。禁止因合併而把不同人的責任、關係位置、知情範圍或關鍵選擇交給錯誤人物。

**`VISUALIZE`**：把敘述轉成可觀察的行為。優先順序：`行動結果 > 對手反應 > 空間/道具證據 > 策略對白 > 極少量旁白`。可視化不能創造新的證據。例如「她懷疑賬本被改過」可以寫成她對比頁碼、停下簽字；不能憑空新增鑑定報告證明賬本造假。

**`REORDER_AUTHORIZED`**：只執行故事聖經或分集卡已登記的重排。重排後仍須保護：原因先於結果；人物先獲得信息再據此行動；賭注先被建立再被調用；伏筆先種下再回收；原作事實的實際生效順序不被偽造。

**`DELETE_REDUNDANT`**：只刪沒有獨立因果、人物、關係、情緒、主題、伏筆或節奏功能的重複內容。主事件和 `MUST_KEEP` 永不使用此標籤。

**`CONNECTIVE_INFERENCE`**：只補充入場、移動、拿取、停頓、職業流程、生活化反應和必要連接對白。新增內容必須同時滿足：不改變核心事實；不改變人物動機和知識邊界；不提供來源未給出的答案；刪除後不影響故事走向，隻影響呈現順暢度。

### 3.4 刪減影響審計

刪減不是「覺得拖沓就刪」。每項刪除都填寫：

```yaml
audit_id: DEL-EP001-01
source_trace: "SRC-001:第18—21段"
removed_content: "第二次重複解釋比賽規則"
reason: "觀眾已在行動場中理解，重複說明不產生新反制"
original_function: "再次說明截止時間"
replacement_carrier: "EP001-SC01 的倒計時屏顯與對手催促"
causal_chain_status: PRESERVED
motivation_status: PRESERVED
setup_payoff_status: NOT_APPLICABLE
decision: SAFE_DELETE
```

審計必須繼續向後看至少一個事件鏈和相鄰集。以下任一情況不得刪除：

- 它是人物改變策略的理由。
- 它建立了後續會被調用的賭注、知識、關係或道具狀態。
- 它是伏筆、誤導、回收或關鍵台詞的必要語境。
- 它讓觀眾理解「為什麼現在」和「為什麼是這個人」。
- 它承擔關係付出、情緒積累或後果見證。

找不到替代承載或無法證明影響時，`decision` 不能寫 `SAFE_DELETE`。

### 3.5 關鍵台詞保護

關鍵台詞不等於逐字照搬所有小說句子。保護順序是：

1. 事實和語義。
2. 說話人與關係位置。
3. 當下行動目的。
4. 衝突或情緒功能。
5. 原句中真正有辨識度的措辭。

每句關鍵台詞只設一個 `PRIMARY_USE`。若原句不適合口語，可進行 `SEMANTIC_PRESERVE`，但要登記直白語義主幹，證明沒有改寫事實。若法規或平台尺度必須調整，標記 `USER_AUTHORIZED` 或項目合規決策，保留功能與影響。

### 3.6 禁止的「優化」

- 用更強身份、更大財富或突然援軍替代人物解決問題。
- 為卡點新增來源不存在的照片、錄音、合同、鑑定、秘密身份或超能力。
- 把人物謹慎改成無腦挑釁，把人物善良改成無底線忍讓。
- 為追求快節奏刪掉動機、反制、反應和代價，只留下事件結論。
- 把複雜人物改成熱門標籤，把原作衝突換成連續打臉或重複羞辱。
- 把未揭曉謎底提前寫死，把條件風險寫成已發生事實。

出現上述情況分別標記 `UNAUTHORIZED_PLOT_INVENTION`、`SOURCE_MOTIVATION_DRIFT`、`MECHANICAL_FAST_PACING`、`TROPE_REPLACEMENT` 或 `UNSOURCED_CORE_CHANGE`。
