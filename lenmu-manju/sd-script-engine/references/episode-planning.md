# 觀眾留存分集規劃

> 精編自《靈境AI劇本改編 skill》（6階段編劇鏈）

本文件覆蓋階段④的完整規範：分集策劃崗位與九遍工作流、觀眾理解與追看機制、分集邊界與長線編排、編劇室分集結構模板與短劇結構速查。

## 一、崗位定位與邊界

### 1.1 崗位定義

分集策劃是把「已經成立的完整故事」重新組織成「觀眾可以一集一集理解、獲得滿足並願意繼續追看」的編劇室崗位。核心不是「把小說切成多少段」，而是同時回答：

1. 觀眾能否看懂這一集主要講什麼？
2. 觀眾能否說清誰要什麼、受到什麼阻擋、如何換策、結果改變了什麼？
3. 觀眾本集獲得了什麼真實結果或情緒兌現？
4. 觀眾為什麼還要看下一集，而且下一集如何馬上兌現？

追看來自清楚的未完成問題、人物或利益投入和可信兌現，不來自故意講不清或把完整動作腰斬。

分集策劃不承諾市場必然爆款，但必須消除可預防的棄看原因：開場不知所云、中段只有解釋、結尾沒有結果、卡點只截半句話、人物關係無故變化、相鄰集重複同一衝突。

### 1.2 與其他階段的邊界

| 階段 | 核心問題 | 階段④不能替代的內容 |
|---|---|---|
| ② IP 與角色開發 | 這個人是誰，觀眾為何記住和喜歡 | 不重新發明人物靈魂、外形和聲音 |
| ③ 全劇開發聖經 | 這是什麼故事，事實、規則、因果和價值是什麼 | 不擅改真相、主線、人物終局和世界規則 |
| ④ 分集策劃 | 觀眾按什麼順序、以什麼節奏消費故事 | 不展開正式場次、完整對白和鏡頭 |
| ⑤ 劇本改編 | 每一集具體怎樣演、怎樣說 | 階段④不能用「後面寫劇本再解決」掩蓋目標和鉤子不清 |

階段④的專業價值是做選擇：保留什麼、合併什麼、哪項先讓觀眾知道、什麼事件屬於同一集、在哪個不可逆變化後結束、下一集第一步怎樣兌現。

### 1.3 為什麼不能按章節或字數平均切

小說章節服務閱讀節奏，可能包含大量心理、背景、回顧或作者解釋；短劇單集服務視聽行動和連續追看。兩者的最小單位不同。

- 一個小說章節可能只有一個動作，卻有大量解釋，不能自動成為一集。
- 三個相鄰章節可能共同組成一次完整行動，拆開會變成三個片段。
- 一個章節也可能包含兩個不可兼得的目標和兩次狀態變化，需要拆成兩集。
- 字數相同的兩段，表演時長可能完全不同：爭辯、動作、沉默、群體反應和規則首建都需要時間。

正確的分集依據是「不可逆狀態變化與觀眾等待問題」，不是章節名、字數或固定 90 秒。

## 二、模式門禁與上游門禁

只讀取已鎖定的階段②和階段③：`01_IP_BIBLE`、`IP_CANON_MANIFEST.json`、`02_STORY_BIBLE`、`STORY_CANON_MANIFEST.json` 及其交付文件。以下任一情況立即停止並輸出 `BLOCKED_REPORT`：

- 任一上游狀態不是 `LOCKED` 或存在失敗標記。
- `ip_version`、`story_version` 或人物 ID 不一致。
- 階段③的全源覆蓋、事件賬本、人物因果、容量診斷或鉤子候選未通過。
- 用戶指定範圍不足以回答所要求的終局問題，又沒有授權新增事實。

`STEPWISE` 完成階段④後等待用戶確認；`FULL_SCRIPT_PIPELINE` 自檢和校驗清單通過後鎖定階段④，再進入階段⑤。

### 分集方式選擇門禁

正式排集前必須先確定 `episode_count_mode`，只允許兩種：

1. `SMART_RECOMMENDED`（智能推薦集數，推薦）：根據階段③的容量區間、事件負荷、完整故事單元、情緒支付和有效斷點，自動給出精確集數與理由。
2. `USER_DEFINED`（用戶自定義集數）：用戶指定目標總集數，系統先核對容量與質量代價，再按該目標規劃。

`STEPWISE` 進入階段④時，若用戶尚未選擇，先原樣提供：

```text
請選擇第三步的分集方式：
1. 智能推薦集數（推薦）：系統根據小說容量、每集60—180秒、完整故事單元和鉤子位置給出最合適的總集數。
2. 用戶自定義集數：由你指定想製作的總集數。

請直接複製下面任意一種格式回覆：
- 如果希望系統自動決定集數，回覆：1
- 如果希望自定義為60集，回覆：2，60集
- 如果希望自定義為80集，回覆：2，80集

你也可以直接回復"智能推薦"或"自定義60集"，系統都能識別。
```

用戶只選擇第 2 項而未給出數字時，回覆「請告訴我想製作的總集數，例如：60集」，不得先生成詳細分集。接受中文逗號、英文逗號和自然語言表達，不要求用戶理解內部枚舉名。用戶已經明確過選擇時不得重複詢問。

`FULL_SCRIPT_PIPELINE` 中，用戶未指定總集數時自動使用 `SMART_RECOMMENDED`；用戶已明確指定總集數時使用 `USER_DEFINED`。若自定義數字低於或高於階段③容量區間，必須先輸出 `CAPACITY_CONFLICT_AUDIT`，說明壓縮或擴展代價、`MUST_KEEP` 保護方式與推薦方案；只有用戶明確確認仍按該數字執行，才能記為 `CONFIRMED_OVERRIDE`。即使是全流程模式，也不得把未確認的重大容量衝突自動視為同意。

自定義集數是規劃目標，不是刪除因果、遺漏人物選擇、虛構內容或用重複爭吵、空場、假反轉湊數的授權。若用戶堅持的數字無法同時滿足 60—180 秒、來源完整性和單集理解門，輸出 `BLOCKED_REPORT` 並給出最接近的可行集數，不生成偽合格方案。

### 必須讀取的輸入

讀取 `PROJECT_PROFILE`、目標受眾、目標集數或時長要求、`IP_CANON_MANIFEST.json`、`IP_ARC_BINDINGS`、`STORY_CANON_MANIFEST.json`、`ADAPTATION_BLUEPRINT.md`、`SERIES_CAPACITY_REPORT.md`、`HOOK_CANDIDATE_LEDGER.md`、`WORLDVIEW_VALUE_BIBLE.md`、事件/人物/規則賬本、信息矩陣、伏筆回收賬本和來源追蹤。

## 三、九遍策劃流程

### 第一遍：消費集數選擇並鎖定精確集數

先記錄 `episode_count_mode`。聲明 `source_scope`、閉合類型、60—180 秒時長區間和精確集數。默認約 90 秒，但完整故事單元優先。

- `SMART_RECOMMENDED`：讀取階段③的最小值、推薦值和最大值，在區間內按自然故事單元與鉤子質量確定最終精確值；最終值可以因更完整的斷點審計而不同於階段③推薦值，但必須說明差異。
- `USER_DEFINED`：記錄 `user_requested_episode_count`，精確集數必須與之相同。若超出容量區間，先完成衝突審計和用戶二次確認；無法保住核心因果與 `MUST_KEEP` 時阻斷。

無論哪種模式，都要寫 `capacity_reference` 和 `capacity_conflict_audit`，不得用空場、重複爭吵或假反轉湊數。

鎖定精確集數時必須記錄：`episode_count_mode` 與選擇來源；`user_requested_episode_count`（智能推薦為 `null`）；`exact_episode_count` 和明確的選擇理由；`duration_range_seconds` 和默認目標時長；階段③的最小值、推薦值、最大值和來源；容量區間與最終採用值的差異；壓縮、合併、擴展分別影響哪些事件和人物弧；為滿足數字可能損失的 `MUST_KEEP`、因果、情緒或回收。

衝突狀態只允許：`WITHIN_RANGE`（最終集數位於容量區間）、`BELOW_RANGE`（自定義集數低於區間，必須說明合併、降載和無法保留項）、`ABOVE_RANGE`（自定義集數高於區間，必須說明可合法展開的情緒、關係和過程，以及禁止使用的注水手段）。

### 第二遍：標註事件歸屬與可壓縮性

將每個事件 ID 標為 `ATOMIC`、`COMBINABLE`、`MONTAGEABLE` 或 `CALLBACK_ONLY`。所有選定事件必須且只能一次作為 `PRIMARY_EVENT` 落入某集，其他出現只登記為 `CALLBACK`。`MUST_KEEP` 事件不得遺漏。

### 第三遍：建立開篇爬坡與大弧

用 `OPENING_RAMP` 證明題材異常、主角損失與目標、能力及限制、關鍵關係和長線升級引擎。用 `ARC_MAP` 記錄每個大弧的驅動問題、升級邏輯、情緒線、局部兌現、高潮和出口狀態。

### 第四遍：建立完整單集故事單元

每集圍繞一個主目標和主要行動問題，填寫進入壓力、主動目標、首次策略、對手或規則反制、策略變化、衝突升級、可見代價、局部結果和新壓力。無法寫出反制、換策、代價或局部結果時，它通常只是信息片段或過場，必須合併或重排。

### 第五遍：建立觀眾理解契約

每集先寫 `EPISODE_THESIS`、`VIEWER_TAKEAWAY`、`VIEWER_EMOTION` 和 `ONE_SENTENCE_RECALL`，再寫 `COMPREHENSION_CONTRACT`（字段見第六節 6.2）。冷啟動觀眾若不能在看完後複述「誰想做什麼、遇到什麼、怎麼改變辦法、結果怎樣」，本集不通過。

### 第六遍：建立局部兌現與追看契約

先寫本集 `local_payoff`，再寫 `RETENTION_CONTRACT`（字段見第六節 6.3）。鉤子必須是具體行動、選擇、證據、到場、危險、身份驗證或關係變化。空泛威脅、突然黑屏、重複揭露、無來源巧合和只截斷半句話不算有效鉤子。非終局集的下一集必須先承接主鉤子，不能跳線拖延。

### 第七遍：編排情緒、關係與 IP

每集寫 `EMOTION_CURVE` 的進入、累積、轉折、情緒兌現和餘味。`IP_DRAMATIZATION` 必須填寫 `soul_test`、`affection_beat`、`flaw_consequence`、`behavior_anchor`、`voice_rule`、`relationship_signature` 和 `growth_state`，讓靈魂選擇、喜愛證據、缺點後果、行為錨點、聲音規則和關係信號落入本集行動；使用 `PRIMARY`、`VARIATION`、`PAYOFF`、`WITHHELD_WITH_REASON` 控制記憶點密度，禁止機械重複口頭禪。

### 第八遍：檢查邊界、連續性與防重複

每個斷點說明故事理由、觀眾理由和前後承接理由。單集必須在不可逆狀態變化之後結束，下一集以新目標、新策略或上集鉤子的第一兌現動作開始。

每集寫 `CONFLICT_SIGNATURE`：`pressure_pattern`、`resolution_pattern`、`novelty_from_previous`。連續三集使用相同壓力模式和解決公式，必須重排。逐集核對日期、日夜、倒計時、知識、資源、傷勢、關係和危險狀態。

### 第九遍：三種觀眾終審

- 冷啟動觀眾：是否無需內部術語也能看懂本集？
- 連看觀眾：是否感到事件、關係或資源真實推進，而非重複上一集？
- 挑剔觀眾：本集是否兌現了上一集承諾，鉤子是否誠實可支付？

結論只能是 `PASS`、`REVISE` 或 `REPLAN`。核心理解、局部兌現、事件覆蓋、來源真值或鉤子支付失敗時不得鎖定。

### ★ CAUSALITY_AND_RELATION_TABLE · 因果與關係表（2026-10-12 新增 · 階段④ 強制產出）

> **由來（粉絲群實測反饋）**：「skill 劇本創作**希望能加入因果關係，還有人情世故這些**，感覺有一些是沒有因果關係邏輯的」
> 「有些東西他**理所當然的以為是這樣了，但是具體並沒有介紹出來**」「**劇情跳的太快了**」。
> **病根**：本引擎此前只有「因果節拍表」與「刪減影響審計」兩處**檢查性**因果記錄，
> **沒有一張要求"每場戲把前因→觸發→後果寫出來"的產出件**，也沒有"人情世故 / 關係利害"這一層——
> 於是"理所當然"的東西（誰跟誰是什麼關係、為什麼他會這麼做、這事為什麼輪得到他）全靠模型自補，一自補就跳。

階段④ 交付 `03_episodes/` 時必須附本表（每集一張，隨稿傳下游分鏡層）：

```
【因果與關係表 CAUSALITY_AND_RELATION_TABLE · EP__】
  人物關係矩陣（人 × 人）：關係 / 利害 / 親疏 / 權力方向 / 欠與債
    例：陳舟—站長：同一平台同事→競爭單量；陳舟—女兒：撫養方→唯一軟肋
  場次因果鏈（逐場）：
    場次 X｜前因：（上一場留下了什麼條件/後果）｜觸發：（誰做了什麼）
         ｜後果：（不可逆地改變了什麼）｜為什麼輪得到他（人情/利害/性格依據）
  人情世故清單（每集 ≥3 條，逐條寫"誰憑什麼這麼做"）：
    例：站長不直接開除陳舟 = 平台工齡折算 + 年會當天曝光成本，扣人會被平台約談
  ⛔ 理所當然禁令：凡"默認應該發生"卻無人解釋的設定，一律回填進本表或改寫
```

**六條鐵律**：
1. **逐場三段式**——每場必須寫滿 **前因 → 觸發 → 後果**；缺任一段即視為該場沒交代清楚。
2. **"為什麼輪得到他"必寫**——這是"人情世故"的落點：把人物行為掛回利害關係/性格/歷史，而不是掛回劇情需要。
3. **人情世故清單 ≥3 條/集**——寫明"誰憑什麼這麼做"；沒有利害支撐的行為一律改成有代價的選擇。
4. **人物關係矩陣進本表**——上游《人物錨卡》/關係引擎矩陣的關係與利害，在此落成可查的矩陣，並隨 `HANDOFF_CARD` 傳到分鏡與台詞層。
5. **⛔ 理所當然禁令**——凡"按常理應該如此"卻**沒人解釋過**的設定，必須回填本表或改寫；**禁留作"默認設定"交給模型自補**（粉絲原話：模型會"理所當然的以為是這樣了"）。
6. **情節點密度下限（治"劇情跳太快"）**：
   - **15 秒投餵段 ≥1 個情節點**（一次意圖變化 / 一次關係變化 / 一次信息翻轉，任一）；
   - **單集 ≥5 個情節點**，且相鄰情節點之間**不得跨過一場戲**——即"這一場的後果必須在下一場被看見"；
   - 一集內情節點 <5，或任一 2 句台詞內跨了兩次時空跳切，**判 `REVISE`**（不許鎖稿）。

### ★ TRANSITION_AS_BEAT · 過渡即戲點（2026-10-13 新增 · 用戶實測反饋 · 階段④ 強制）

> **由來（用戶實測反饋 2026-10-13）**：「你這個邏輯沒對……事實上是**你的劇本，就是整個劇情設計的問題**，跟分鏡這些東西沒關係」；
> 「段一是大哥和那個女角色在那兒對話，到段二的時候**一下就是四個人在那兒了**，**它得有一個什麼過渡吧**」。
> **病根**：本套此前把「過渡」當成**分鏡層的技術補丁**（C17e 人數變化交代、景別承接）——**方向錯了**。
> 過渡的本質是**劇本層的一個戲點**：它要麼加信息、要麼加人物、要麼加情緒，**不是填縫**。
> 分鏡層只能"補交代"，補不出"戲"；**戲必須在劇本階段就設計出來**。

階段④ 交付 `03_episodes/` 時，**每兩個相鄰場次之間必須指定一個過渡設計**（寫進場次卡，隨稿傳下游）：

```
【場次過渡設計 TRANSITION_AS_BEAT · EP__ 場X→場Y】
  過渡類型（四選一，見下表）
  過渡內容（一句寫清"這一下給觀眾什麼"）
  是否承載新信息（是 → 寫清是什麼信息；否 → 說明為何必須是純節奏過渡）
  ⛔ 禁止項：不得只寫"接著/隨後/不久後"這類時間副詞當過渡
```

**四種過渡類型（按"加戲量"從高到低，優先選上三種）**：

| 類型 | 寫法 | 加什麼 | 例（用戶原話場景） |
|---|---|---|---|
| **① 動作橋（人物帶戲過渡）** | 用某個人物的**一個動作**把觀眾帶過去；動作本身合情合理、且透露狀態 | **加人物狀態 + 加信息** | 「拍一個他們送外賣那個，**他噠噠噠跑進來**，跑一個這樣的聲音」——跑進來 = 他遲到了/他剛下班/他不情願來，一句話不說就把人物立住了 |
| **② 空鏡敘事（環境承載過渡）** | 用一個**承載情緒或信息的空鏡**掃過，再進新場 | **加情緒 + 加空間** | 「從段一最後結尾的時候**靈堂掃一下**，或者段二開頭靈堂那掃一下，然後過渡到他們四個人在那兒商量」——靈堂 = 遺像 + 白花 + 沒撤的供桌，直接壓住全場的"父親剛走" |
| **③ 聲音橋（畫外先聲）** | 新場的聲音**先於畫面出現**（腳步 / 敲擊 / 爭執 / 電話鈴） | **加懸念 + 加節奏** | 段1 末鏡句尾「門外由遠及近傳來兩個人的腳步聲」；聲音必須是**新場裡真實存在**的聲音，不是音效貼片 |
| ④ 硬接（時間副詞） | 直接進新場 | 無 | ⛔ **默認禁止**，僅在"刻意製造突兀/驚嚇"時用一次，且須在過渡設計裡寫明理由 |

**四條鐵律**：
1. **過渡必須選①②③之一**——⛔ 默認禁止用"隨後/接著/轉眼"這類時間副詞硬接（④ 需寫明理由）。
2. **過渡必須承載新信息**——若一個過渡只起"時間流逝"作用、不給任何新信息，則**它不是過渡、是拖時長**，刪掉或加料。
3. **過渡的落點寫在場次卡上**——寫明"掛在前場末尾 / 掛在後場開頭"（兩種都行，但必須指定一個，**不得兩處都不寫**——這正是段1→段2 斷層的直接成因）。
4. **人物進出場要掛過渡**——凡相鄰兩場**在場人物集合變化**，新登場人物必須走①②③之一進場（**"走進來"是①動作橋，"先聞其聲"是③聲音橋**）；分鏡層機檢 **C17e** 只做兜底，**劇本層必須先有設計**。

⚠️ **與分鏡層的分工（改前必讀）**：
- **劇本層 = 造過渡**（本節）：過渡是戲點，要有內容。
- **分鏡層 = 落過渡**（`segment-splicing.md` §四·補二 + 機檢 C17e）：把劇本層定好的過渡，寫成鏡行裡可執行的畫面/聲音，並做人數變化的兜底告警。
- **顛倒這個分工 = 本末倒置**：此前把過渡當分鏡技術補丁，結果"補了交代、沒補戲"——觀眾看到的仍是一段乾巴巴的"人物走進來"。

## 四、觀眾理解、情緒滿足與下一集追看

### 4.1 追看動力公式

觀眾不會閱讀分集表、人物小傳和事件賬。他們只接觸眼前這一集。分集策劃不能用「後面會解釋」掩蓋當前無法理解，也不能把「有懸念」誤當成「願意追看」。

可用一個非數值公式檢查追看動力：

`追看欲 = 具體未完成問題 × 人物或利益投入 × 已被證明會兌現 − 理解負擔 − 重複感 − 被拖延感`

任何一項接近於零，鉤子再大聲也可能無效：不知道問題是什麼，觀眾不會等答案；不在意誰承擔後果，觀眾不會關心答案；前面多次不兌現，觀眾不再相信答案會來；本集什麼也沒完成，觀眾感到被截斷而不是被吸引。

### 4.1.1 懸念存量配額（★ 2026-10-13 新增 · 治「懸念基本歸零」）

> **由來（粉絲系統性實測反饋）**：「**懸念基本歸零**」。
> **病根**：本包的懸念機制全是**逐集**的（每集有沒有鉤子）——「每 15-20 秒一個鉤子」只要"本集有個鉤子"就能全綠；但**每集鉤子當集就兌現 → 整部劇沒有任何長期懸著的問題 → 觀感上懸念歸零**。**逐集機制撐不起跨集懸念。**

三條存量配額（**進入階段④時與 `ARC_MAP` / `HOOK_PAYOFF_LEDGER` 同批填寫，缺任一條即 `REVISE`**）：

1. **同時掛起 ≥2 條未解問題**——任何一集結束時，**"已種下但未支付"的長線問題**至少 **2 條**並存（1 條主線 + 1 條副線/關係線）。⛔ 不得只靠"本集鉤子"——本集鉤子是**短鉤**，長線問題才是**留住觀眾的繩**。
2. **單集不得全部兌現**——**本集結束時，手上至少留 1 條懸而未決的問題**過渡到下一集；⛔ 不得本集把所有種下的問題都收乾淨（那是"完結感"，不是"追看欲"）。
3. **長線懸念須登記保留期**——每條長線懸念在 `HOOK_PAYOFF_LEDGER` 登記**種下集 → 計劃兌現集**，**跨度 ≥5 集**（低於 5 集的是短鉤、不算長線）；⛔ **不得連續 ≥8 集不提醒**（觀眾會忘）——中途須有"提醒拍"（迴響 / 提及 / 局部兌現），但**提醒 ≠ 提前支付**。

**與追看公式的關係**：`追看欲 = 具體未完成問題 × …` 中的「具體未完成問題」**在此變為可核對的存量**——不再只是公式裡的一項乘數，而是**逐集可數的條數**。

**與鉤子的分工**：**短鉤**（本集鉤子）負責"這一集看完想看下一集"；**長線懸念**負責"這部劇看到第 30 集還想知道結局"。**二者都要有，缺一不可。**

### 4.2 首次觀看理解合同 COMPREHENSION_CONTRACT

- `who`：本集行動中心是誰。
- `wants_what`：他本集想完成的具體目標。
- `obstacle`：誰或什麼規則主動阻止。
- `action_change`：第一個辦法失效後換了什麼策略。
- `result`：本集最後已經改變的事實、關係、資源或危險。
- `new_question`：下一步唯一主要問題。
- `required_prior_knowledge`：看懂本集最低需要記住什麼。
- `forbidden_assumption`：不能要求觀眾自行腦補什麼。

**ONE_SENTENCE_RECALL**：用一句「誰想做什麼，但是遇到什麼，於是怎樣換策，結果怎樣」的因果句複述本集。


不合格示例：「這一集主要是他們在會議室吵架，並發現事情不簡單。」——沒有目標、策略和結果，說明單集仍是材料片段。

**理解負荷控制**：一個短集可以引入複雜世界，但不能同時要求觀眾第一次記住過多新角色、組織、規則、時間條件和道具。必要信息按三類處理：`NOW`（不理解就無法判斷當前行動，必須在動作中建立）、`LATER`（暫時不知道也不影響人物行動，可以延後）、`NEVER_EXPLAIN_AGAIN`（已通過動作清楚建立，不要每集重複）。

### 4.3 單集注意力曲線

60—180 秒內不機械套固定秒數，但必須完成四段功能：

1. **定向與在場壓力**：儘快讓觀眾知道當前是誰、壓力已到哪一步、為什麼現在必須行動。承接上集時優先用未完成動作、聲音、道具或關係位置，不用長篇回顧。
2. **主動行動與反制**：主角嘗試一個可見辦法，對手、規則或環境依據自身目標回應。沒有反制的方案彙報不是戲。
3. **換策與局部結果**：舊辦法失效後，人物因新信息或代價改變策略。結果可以成功、失敗或部分成功，但必須改變狀態。
4. **餘味與下一壓力**：讓觀眾看見本集結果如何影響人物，再留下下一項具體動作問題。鉤子不是突然切黑，而是結果自然產生的新債務。

對 90 秒默認集可把注意力預算近似看成：前約 15% 完成定向，隨後約 45% 行動與反制，約 25% 換策與支付，末約 15% 結果餘味與鉤子。比例可變，功能不能缺。

### 4.4 局部兌現

局部兌現是觀眾本集真正得到的東西：一個目標完成或明確失敗；一項證據得到驗證；一段關係完成站隊、拒絕或破裂；一個規則的限制被證明；一次反擊產生可見後果；一個危險被暫時解除併產生新代價。

局部兌現不等於全劇謎底。長線可以保持開放，但本集不能只建立問題。

檢查問題：1. 刪除集尾鉤子後，本集仍然有可複述的結果嗎？2. 這個結果會改變下一集的行動條件嗎？3. 觀眾等待已久的承諾是否至少部分支付？三項都否定時，應與下一集重新組合。

### 4.5 下一集點擊理由

NEXT_CLICK_REASON 必須回答五件事：

1. 等什麼：一個具體動作、選擇、證據、到場、危險或關係後果。
2. 為什麼在意：它會傷害或改變誰的目標、關係、尊嚴、資源或生命。
3. 為什麼現在：危險已逼近、選擇已啟動、證據剛出現或行動不可逆。
4. 下一集先做什麼：第一場具體承接動作。
5. 何時支付：部分或完整兌現集。

有效表達：「她已經把解藥遞到仇人手裡，觀眾下一集要看他會救孩子還是保住身份；因為兩者不能同時保住，下一集先從他伸向藥瓶的手接起。」

無效表達：「更大的陰謀即將浮出水面，敬請期待。」

### 4.6 鉤子設計與兌現

**鉤子七型**：

- ACTION：動作已啟動，等待直接結果。
- CHOICE：人物必須在兩個有代價方案間選擇。
- EVIDENCE：新證據改變判斷，等待驗證或行動。
- ARRIVAL：已有關係與目的的人進入，立刻改變局勢。
- DANGER：已建立危險進入不可迴避階段。
- IDENTITY：身份被懷疑、驗證或公開；同一秘密不可反覆假揭露。
- EMOTION：承諾、背叛、保護或拒絕改變下一步行動。

完整終局可使用 CLOSURE，支付最後一項行動與情感承諾，不再偽造下一集問題。

**好鉤子的四項質量**：具體（觀眾能用疑問句說出來）、重要（答案影響已建立的人或目標）、臨近（下一集可立即推進，不需先繞開三場戲）、可支付（已有來源事件或故事聖經支持答案）。

**部分支付**：下一集可以先回答「發生了什麼」，再把「為什麼」延後；也可以完成選擇，再讓後果繼續升級。必須在 HOOK_PAYOFF_LEDGER 標記 PARTIAL 和最終支付，不能把同一問題換句話重複種下。

**偽鉤子**：角色說「我有一個秘密」後切黑，下一集先閒聊；在一句完整答案說到一半時切斷；隨機陌生人推門，沒有關係和目的前置；對手泛泛冷笑「你等著」；重複已揭曉身份，只換一批圍觀者震驚；本集沒有行動結果，只靠危險音樂結束；下一集用回顧重播上集最後十幾秒再給答案。

### 4.7 情緒和關係留存

觀眾持續追看通常不只為事實答案，也為人物如何選擇。每集建立 EMOTION_CURVE：`entry`（進入時的主情緒）、`build`（壓力如何讓情緒增強或變質）、`turn`（哪次行動改變感受）、`payoff`（本集得到的情緒支付）、`aftertaste`（帶入下一集的餘味）。

關係場必須改變行動權限、信任、稱謂、站位、資源或承擔方式。只說「我理解你了」但下一步行動不變，不算關係推進。

長線關係節奏可輪換：試探 → 小額互助 → 暴露缺點 → 真實損失 → 主動站隊 → 誤解或價值衝突 → 更高成本修復。不能只靠重複吃醋、偶遇和誤會維持。

### 4.8 不同題材的追看引擎

| 題材 | 觀眾每集主要等什麼 | 必須支付什麼 | 常見偽留存 |
|---|---|---|---|
| 懸疑 | 證據是否改變判斷 | 一項驗證結果或行動後果 | 不斷增加謎團但不驗證 |
| 甜寵 | 對方會不會主動選擇關係 | 一次有成本的保護、拒絕或靠近 | 無行動的曖昧與誤會 |
| 逆襲爽劇 | 主角怎樣改變不公局面 | 準備、反擊、見證、後果中的階段閉環 | 換場景重複受辱 |
| 喜劇 | 人物策略怎樣因性格反噬 | 笑點同時改變目標或關係 | 可刪除的段子拼盤 |
| 生存/末日 | 資源和規則會逼出什麼選擇 | 真實消耗、損失或能力限制 | 突然出現新怪物 |
| 權謀宅鬥 | 誰掌握規則、證據和執行權 | 權力、資源或名分的可見轉移 | 全靠嘴贏且對手降智 |

### 4.9 三類觀眾複審

- **冷啟動觀眾**：不讀取前情簡介，只看本集入口：能否在短時間內定位人物、壓力和目標？若不能，補動作定向，不補百科旁白。
- **連續追劇觀眾**：檢查上集問題是否在本集第一行動中被承接；同一事件是否重複；人物、道具、傷勢、時間和關係是否連續。
- **懷疑型觀眾**：主動尋找編劇作弊：反派為何突然變笨？資源為何突然出現？人物為何知道秘密？代價是否只是口頭聲稱？若答案依賴「觀眾別細想」，分集不能通過。

### 4.10 觀眾層失敗模式

- EPISODE_THESIS 只能寫「本集繼續上一集劇情」。
- VIEWER_TAKEAWAY 是抽象主題，不是觀眾看懂的行動事實。
- ONE_SENTENCE_RECALL 需要三個「然後」才能勉強複述。
- LOCAL_PAYOFF 為空或只是「危機加深」。
- WHY_CARE 只說「很重要」，沒有影響對象。
- NEXT_EPISODE_FIRST_ACTION 與鉤子無關。
- 同一鉤子連續兩集仍處在「準備回答」。
- 結構字段全 PASS，但隱藏字段後只剩解釋、爭吵或半場戲。

## 五、分集邊界、容量與長線編排

本節解決三個問題：一集該裝多少、為什麼在這裡斷、幾十集如何既連續又不重複。分集不是把原文等分，而是把事件重新組織成觀眾能看懂、能獲得局部滿足、又願意繼續追看的行動單元。

### 5.1 事件可壓縮性標註

給階段③的每個事件標註一種處理方式：

- `ATOMIC`：因果、選擇、代價或情緒兌現不可拆，必須在同一集完成。
- `COMBINABLE`：可與相鄰事件合併，只要不損傷知識邊界和人物動機。
- `MONTAGEABLE`：重複訓練、趕路、積累、準備等可壓成蒙太奇或一句可視化結果。
- `CALLBACK_ONLY`：已發生事件只承擔回看、證據重現或承接，不再算一次新覆蓋。

`MUST_KEEP` 事件至少一次作為 `PRIMARY_EVENT` 落入某集。任何事件只能有一個主歸屬集，其他集只能作為 `CALLBACK`。

### 5.2 自然邊界與錯誤邊界

適合斷集的自然邊界通常同時滿足：

1. 本集行動已有局部結果，不是半句話、半個動作或半場爭吵。
2. 目標、關係、信息、資源或危險至少一項發生不可逆變化。
3. 舊行動問題已經回答或階段性回答。
4. 新行動問題已經具體出現，下一集知道先做什麼。
5. 觀眾已經獲得一次情緒兌現，再承受新的等待。

常見錯誤邊界：只因為達到 90 秒就在同一動作中間切斷；在基礎設定尚未講清時故意藏信息；本集沒有結果，只用一句威脅、冷笑或黑屏拖延；把一個完整反擊拆成「準備、開口、宣佈」三集；上集鉤子在下集開頭被忽略，先去講另一條線；用突然出現的身份、證據、資源或事故製造偽反轉。

### 5.3 七問分集決策

對每個候選斷點依次回答：

1. 本集觀眾能用一句話說出主要發生了什麼嗎？
2. 主角本集的目標、阻力、換策和結果完整嗎？
3. 觀眾已經獲得哪一次局部兌現？
4. 與開場相比，什麼狀態真實改變了？
5. 斷點之後出現的是新問題，還是同一動作被硬切？
6. 觀眾為什麼在意這個新問題，為什麼現在就想知道？
7. 下一集第一行動能否直接承接並開始兌現？

第 1—4 問任一答不出，優先合併或重排；第 5—7 問任一答不出，說明斷點缺乏追看動力。

### 5.4 邊界理由卡（每個斷點必須說明）

每個邊界至少說明三層理由：

1. `story_reason` 故事理由：哪個局部目標已經完成、失敗或發生不可逆變化。
2. `audience_reason` 觀眾理由：觀眾本集得到什麼，又具體等什麼。
3. `continuity_reason` 連續性理由：下一集為什麼能以新動作、新策略或新局面開始。

可選補充 `production_reason` 製作理由：場景、角色、動作和時長負荷是否可執行。製作理由可以影響組織方式，但不能刪除主線或改變人物選擇。如果理由只是「這一段夠 90 秒」「這裡看起來刺激」「原著正好換章」，邊界不成立。

### 5.5 時長與信息負荷

單集允許 60—180 秒，默認約 90 秒。時長是結果，不是切割尺。

估算時同時計算：對白朗讀、動作反應、空間建立、情緒停頓、信息理解和鉤子停頓。一個完整單元 75 秒可直接成立，不要注水；一個必須 110 秒才能完成選擇與結果的單元，不要在策略轉變處腰斬。

單集若同時出現以下高負荷項目，通常需要拆分或降載：多個新地點、三個以上新角色、新世界規則、複雜時間跳轉、重大關係轉折和高潮兌現。刪減順序優先是重複解釋、同功能場次和背景閒談，不得刪掉因果前提、人物選擇與情緒反應。

### 5.6 開篇爬坡與大弧地圖

`OPENING_RAMP` 負責讓新觀眾快速建立五件事：題材與異常、主角損失與目標、可用方法及限制、關鍵關係、後續升級引擎。它不要求固定五集，但每一項都必須由事件證明。爬坡長度隨項目調整，不機械規定前三集或前五集。

`ARC_MAP` 對每個大弧記錄：驅動問題、入口狀態、主事件、升級階梯、情緒線、承諾兌現、高潮集與出口狀態。大弧不是章節目錄，而是一段「觀眾持續等待同一個答案」的區間。

每個大弧結束時至少完成一項外部結果和一項人物或關係變化，同時打開更高層行動問題。若連續三個大弧只有同一種打臉、揭身份或眾人震驚，必須改換衝突機制。

### 5.7 信息釋放與事件歸屬

為每集區分：觀眾已知、主角已知、對手已知；本集新增信息及其證據來源；暫緩信息的戲劇理由；暫緩是否影響本集基本理解。

**存量檢查（★ 2026-10-13 · 與 §4.1.1 懸念存量配額配套）**：本集結束時，**未解的長線問題存量 ≥2 條**、且**至少留 1 條過渡到下一集**——逐集核對 `HOOK_PAYOFF_LEDGER` 中狀態為 `OPEN`/`PARTIAL` 的長線條目數，**不足即 `REVISE`**。

懸念可以延遲答案，不能延遲看懂當前行動所需的前提。觀眾不知道終極謎底沒有問題，但必須知道角色此刻為什麼行動、失敗會怎樣。

倒序、插敘、混編只在六項審計通過後採用：因果、人物知識、懸念、回到主時間線、情緒累積、來源追蹤。呈現順序變化不等於事實順序變化（六門定義見 [story-bible-and-ip.md](story-bible-and-ip.md) 第 2.16 節）。

### 5.8 衝突簽名與防重複（★ 2026-10-13 升級：從「連續三集滑窗」升級為「全劇配額 + 階段升級 + 基線差異」）

每集記錄 `CONFLICT_SIGNATURE`：

- `pressure_pattern`：壓力來自人、規則、時間、資源、關係、知識差還是自我缺陷。
- `resolution_pattern`：本集靠選擇、博弈、證據、犧牲、合作、技能、忍耐還是拒絕獲得結果。
- `novelty`：相對前兩集新的壓力組合、關係位置或解決方式。

**四條去重鐵律（按嚴格度遞增）**：

**① 滑窗去重（原有）**：連續三集的壓力模式和解決模式完全相同，判定為機械重複。即便事件名稱不同，只要仍是「被輕視—公開證明—眾人震驚」，也算同一公式。

**② 全劇公式族配額（★ 新增 · 治「後面疲勞、可預判」）**：以 `pressure_pattern × resolution_pattern` 組合為**「公式族」**——**全劇同一公式族出現不得超過 3 次**，且**每 10 集內不得超過 2 次**。超限判 `REPLAN`。

> **病史（粉絲實測）**：此前去重窗口**統統是「連續三集」滑窗**。粉絲描述的恰是**非連續重複**——「第 1-10 集公式 A（可行），第 11-20 集仍是公式 A，但中間插幾集 B 打斷連續性 → 滑窗掃過去『連續三集同公式』始終不成立 → 全綠通過 → 觀眾第 11 集起就能預判」。**滑窗去重 ≠ 全劇去重。**

**③ 階段升級義務（★ 新增）**：每滿 10 集（EP010 / EP020 / EP030…）**必須引入新的衝突層級**——至少升級下列一檔：**對手級別 / 代價級別 / 信息層級 / 衝突維度**。⛔ 不得沿用首 10 集的公式族。

**④ 新鮮度衰減檢查（★ 新增）**：以**首 10 集的 `CONFLICT_SIGNATURE` 集合為基線**，此後每批必須**證明與基線的差異**（寫出本批與基線不同在哪裡），⛔ 而非只與「前兩集」比。

⚠️ **與反派強度聯動**：公式之所以能重複，**本質是對手強度沒升級**——同一個弱對手換個名字再來一遍。故 ②③④ 與「反派能力基線」（`six-stage-pipeline.md` §6.5）**必須同時達標**。

變化不等於隨機；每次變化仍必須來自鎖定人物能力、缺點、關係和世界規則。

### 5.9 人物關係與 IP 長線分佈

不能要求每集重複同一口頭禪或標誌動作。按功能分佈人物記憶點：

- `PRIMARY`：本集由核心選擇或行為錨點主導。
- `VARIATION`：在新壓力中展示同一人格邏輯的變體。
- `PAYOFF`：早期人格、關係或缺點鋪墊在本集回收。
- `WITHHELD_WITH_REASON`：本集刻意不使用，並說明節奏理由。

人物弧必須通過選擇和後果推進；關係弧必須通過共同經歷、試探、保護、背叛、拒絕或修復推進。不能只用稱呼變化或旁白宣佈關係升級。

### 5.10 跨集連續性

每集記錄入口和出口的目標、關係、信息、資源、危險與時間。相鄰集檢查：日期、日夜、倒計時、流程耗時是否相容；標註「連續」時是否真的從同一動作和情緒接上；若時間跳轉，下一集正文是否能可視化建立；上集鉤子的第一兌現動作是否進入下集開場；傷勢、道具位置、人物知識與資源是否憑空重置。

### 5.11 交付範圍與閉合類型

先聲明當前交付屬於：`SERIES_OPENING`（只完成系列開篇小弧）、`SERIAL_BATCH`（長線中的連續一批）、`CLOSED_MINI_ARC`（來源支持的閉合小弧）、`FINALE`（來源支持的最終閉合）。

局部完整不等於虛構謎底。來源沒有提供身份、真相、證據、規則或勝負答案時，只能閉合角色當下的行動問題，相關事實繼續登記為 `OPEN_ITEM`。

### 5.12 全局終審十二問

1. 每集一句話能否說清主要事件？
2. 每集是否有完整行動鏈與局部結果？
3. 每集鉤子是否有具體等待問題、在意理由和兌現集？
4. 下一集開場是否承接上一集等待？
5. 所有必須事件是否且僅一次作為主事件覆蓋？
6. 是否存在按章節、字數或固定秒數機械切割？
7. 是否連續三集使用同一衝突和解決公式，或同一公式族全劇超配額（>3 次 / 每 10 集 >2 次，見 §5.8）？
8. 是否有未兌現鉤子或重複揭露同一秘密？
9. 關係、資源、知識、危險和時間是否連續？
10. IP 行為、聲音和關係記憶點是否自然分佈而非機械重複？
11. 分集方式是否已選擇，精確集數是否有容量理由，自定義集數是否完成衝突審計，而不是先定數字再湊內容？
12. 冷啟動觀眾能否看懂，連看觀眾是否覺得有進展，挑剔觀眾是否感到承諾被兌現？

任一核心問題失敗，結論為 `REPLAN`；局部字段或承接可修正時為 `REVISE`；全部通過才能 `PASS` 並交給階段⑤。

鉤子類型優先使用行動、選擇、證據、到場、危險、身份驗證、情緒關係或終局閉合；每個主鉤子都必須登記兌現集。狀態只允許 `OPEN`、`PARTIAL`、`PAID`、`CLOSED` 或 `BROKEN`。計劃鎖定時不得存在 `BROKEN`。長線可部分兌現再升級，但必須登記最終支付位置。

### 6.8 結構化清單

`EPISODE_PLAN_MANIFEST.json` 頂層至少包含：`schema_version`、`version`、`ip_version`、`story_version`、`source_scope`、`planning_contract`、`files`、`episode_ids`、`primary_event_coverage`、`opening_ramp`、`arc_map`、`hook_payoff_ledger`、`episodes`、`quality_gates`、`failure_flags`、`open_items`。

其中 `planning_contract` 必須包含：`episode_count_mode`（`SMART_RECOMMENDED` 或 `USER_DEFINED`）、`user_requested_episode_count`（智能推薦為 `null`，自定義為正整數）、`exact_episode_count` 與 `episode_count_basis`、`capacity_reference`（階段③的最小、推薦、最大集數及來源）、`capacity_conflict_audit`（`conflict_status`、壓縮或擴展代價、`MUST_KEEP` 保護、最終決定與用戶確認狀態）、時長上下限、默認時長、敘事順序、受眾、系列承諾、理解目標和留存目標。

每個 `episodes.EP###` 至少包含：`episode_role`、`episode_thesis`、`viewer_takeaway`、`viewer_emotion`、`one_sentence_recall`、`duration_target_seconds`、`primary_events`、`callbacks`、`source_trace`、`story_unit`、`comprehension_contract`、`retention_contract`、`emotion_curve`、`conflict_signature`、`timeline`、`ip_character_ids`、`ip_dramatization`、`duration_budget`、`quality_gates`、`failure_flags`。

JSON 內字段統一使用小寫蛇形命名，含義與逐集卡的大寫審稿標籤完全對應。

### 6.9 終審十項

逐集確認：

1. `ONE_SENTENCE_RECALL` 是否具體到行動與結果。
2. `COMPREHENSION_CONTRACT` 是否無需隱含前提。
3. `STORY_UNIT` 是否包含反制、換策、代價和局部結果。
4. 是否先有 `local_payoff` 再有鉤子。
5. `waiting_question`、`why_care`、`urgency` 是否缺一不可。
6. 下一集第一動作是否真實承接。
7. 時間、知識、關係、資源和危險是否連續。
8. `CONFLICT_SIGNATURE` 是否與前兩集形成有效變化。
9. IP 選擇、缺點、行為、聲音和關係是否參與劇情。
10. 來源未提供的謎底是否仍保持開放。

任一核心項失敗，退回重排，不能用階段⑤的對白或任何後續鏡頭包裝來掩蓋。

## 七、短劇分集結構速查

- **單集最小完整單元**：每集至少包含進入壓力、主動目標、首次策略、有效反制、策略變化、可見代價、局部結果和新壓力或閉合。只發生談話、準備、說明、爭吵或半個動作，不構成完整一集。
- **觀眾理解**：看完後，首次觀看者應能用一句話回答——誰想完成什麼？什麼阻止了他？他如何改變做法？最後什麼狀態變了？下一步要解決什麼？懸念可以隱藏答案，不能隱藏看懂當前行動所必需的前提。
- **情緒與局部兌現**：每集都要支付一個真實結果：目標完成、部分完成、失敗但獲得信息、關係作出選擇、資源改變或危險被確認。觀眾可以等待更大答案，但不能整集只得到「還沒結束」。
- **分集邊界**：在局部結果和不可逆狀態變化後斷開；下一集以新目標、新策略或鉤子的第一兌現動作開始。不要按章節、字數、固定秒數或場景長度機械切割。
- **追看理由**：有效鉤子必須同時具備具體等待問題、人物或利益的在意理由、此刻發生的緊迫性、下一集可見的第一行動和明確兌現位置。空泛威脅、冷笑、黑屏、重複揭露和無來源巧合都不是可靠鉤子；禁止機械反轉。
- **升級與防重複**：升級來自代價增加、信息變化、關係選擇、時間壓力、規則限制、資源衝突或人物缺點。**同一公式族（`pressure_pattern × resolution_pattern`）全劇 ≤3 次、每 10 集 ≤2 次**（§5.8）；連續三集不能使用相同的壓力與解決公式；每滿 10 集必須引入新衝突層級（對手級別/代價級別/信息層級/衝突維度）；尤其禁止反覆「被輕視—亮身份—眾人震驚」。
- **時長**：單集允許 60—180 秒，默認約 90 秒。完整故事單元優先於整齊時長。通過合併重複功能、壓縮說明和可視化信息控制負荷，不刪因果前提、人物選擇和情緒兌現。
- **長線連續**：每集都要對齊目標、關係、信息、資源、危險和時間。上集的主鉤子應在下集開場先得到承接；伏筆可以延遲支付，但必須登記兌現集與來源事件。

## 七·五、平台節奏矩陣與節奏檔位

> 融合自 script-writing-studio 01b 節奏矩陣。**核心原則：不是所有東西都變快，而是讓慢有價值。**

### 7.5.1 節奏檔位四檔（必須記錄並傳給下游）

分集規劃時必須同時記錄**節奏檔位**，後續傳給分鏡/投餵環節。用戶未指定時由 AI 自動判定，用戶不滿意可只改某一組。

| 節奏檔位 | 使用時機 | 寫作提醒 |
|---|---|---|
| **電影感中速** | 情緒交鋒、儀式感、懸疑凝視、單鏡調度 | 慢鏡頭必須承擔信息、情緒或關係變化 |
| **短視頻中高密度** | 默認短視頻、豎屏短劇、紅果、抖音、小紅書 | 每段要有可見動作、信息增量或反應點 |
| **高密度動作或強鉤子** | 前 3 秒/前 15 秒鉤子、打鬥、追逐、爆點、強反轉 | 用動作鏈和短反應推進，不寫空泛鋪墊 |
| **慢節奏但高信息** | 用戶指定或命中強情緒壓迫、重要台詞白名單 | 必須寫清慢的功能，避免被誤判拖沓 |

⚠️ **橫屏/豎屏/21:9 只是畫幅選擇，不自動等於慢節奏或快節奏**；節奏由平台、目標時長、內容類型和完播目標共同決定。

### 7.5.2 平台時長層級

| 時長層級 | 節奏要求 | 寫作策略 |
|---|---|---|
| 15-30 秒極短視頻 | 0-3 秒直接給鉤子，7 秒內給反差，結尾留互動 | 不寫完整三幕，只寫動作鏈和爆點 |
| 30-90 秒短視頻 | 每 10-15 秒一個新信息/情緒點 | 場景極少，動作和台詞都要壓縮 |
| 90 秒-3 分鐘短劇/短片 | 前 5 秒強鉤子，每 15-20 秒推進 | 可有小三幕，但不允許空轉鋪墊 |
| 3-10 分鐘平台微電影 | 可有電影呼吸，但前 15 秒必須給留人理由 | 慢鏡頭集中放在情緒峰值前後 |
| 10-30 分鐘微電影 | 允許更完整的鋪陳，但每 30-60 秒要有有效推進 | 主題留白保留，重複信息壓縮 |

### 7.5.3 呼吸鏡頭合法條件（★ 關鍵）

慢鏡頭、空鏡、沉默、長停頓、靜止畫面**只有滿足下列至少一項時才保留**：

```
① 情緒變化：角色從一種狀態進入另一種狀態
② 懸念加深：觀眾獲得"為什麼會這樣"的追問
③ 人物關係變化：視線、距離、稱呼、肢體反應發生變化
④ 關鍵信息釋放：畫面裡出現必須被看見的信息、道具、環境線索
⑤ 視覺記憶點：形成可做封面、標題、切片傳播的畫面
⑥ 動作蓄力：為下一次爆發、反轉、決定做準備
```

**這一條與「尾幀錨定法」口徑一致**——靜止必須是為了被截圖/強調，不是為了被觀看。

### 7.5.4 平台節奏紅線（違反即重寫）

```
❌ 開場 3 秒內只有風景、天氣、慢走、背影、環境鋪墊，且沒有懸念或反差
❌ 連續兩場都在重複同一情緒，沒有新信息
❌ 角色長對白解釋設定，卻沒有動作或關係變化
❌ 為了"電影感"寫長空鏡，但觀眾不知道該看什麼
❌ 微電影結尾有留白，但沒有情緒迴響、主題回扣或討論點
```

## 九、階段自檢與校驗清單

在鎖定前先人工核對：每個事件 ID 是否唯一歸屬；每集主目標、反制、換策、局部結果是否完整；觀眾是否能一句話複述；本集是否先完成情緒兌現；集尾鉤子是否有在意理由與兌現集；相鄰集前後承接是否直接；時長預算是否等於目標時長；連續三集是否避免同一衝突公式；所有 IP 字段和上游版本是否一致。

同時核對：集數模式是否來自用戶選擇或全流程默認規則；自定義集數是否等於最終精確集數；容量參照是否與階段③一致；區間外自定義是否已有 `CONFIRMED_OVERRIDE`；智能推薦是否仍位於合理容量區間。

校驗清單必須證明：精確集數、ID、文件、來源範圍和版本一致；分集方式、用戶目標、容量參照、衝突狀態和確認狀態彼此一致；選定事件全部且僅一次作為主事件覆蓋；每集理解、行動、局部兌現、追看、情緒、連續性和 IP 字段完整；鉤子種下集、兌現集、來源事件和逐集留存契約一致；不存在連續三集同一衝突公式；全劇與逐集質量門均為 `PASS`，失敗標記為空。

校驗失敗先修訂一次；仍失敗則輸出 `BLOCKED_REPORT`，禁止交給階段⑤。

### 交付和退回標準

- **PASS**：首次觀看能複述、主角主動、對手有效反制、本集有局部結果、鉤子可兌現、關係和信息連續、時長可執行。
- **REVISE**：故事單元成立，但時長、信息密度、情緒順序、鉤子措辭或個別事件歸屬需要調整。
- **REPLAN**：集數與故事容量衝突、單集只是片段、連續場機械拆分、三集重複同一公式、事件遺漏或重複、鉤子無兌現、觀眾無法說清本集講什麼。此時必須重新分集，不能交給階段⑤靠台詞補救。

## 十、階段⑤交接約束

階段⑤必須逐集消費 `episode_thesis`、`one_sentence_recall`、`story_unit`、`comprehension_contract`、`retention_contract`、`emotion_curve`、`timeline` 和 `ip_dramatization`。正式劇本可以優化場次與台詞，但不得靜默改變主事件歸屬、局部兌現、主鉤子、兌現集、人物靈魂選擇或鎖定版本。

## 十一、禁止越界

本階段不寫正式場次、完整對白、演員調度、鏡頭、資產清單或視頻提示詞；不為製造鉤子新增故事聖經之外的身份、證據、能力、規則、關係和結局；不把來源未回答的終極謎底偽裝成本階段推斷。

## 附：題材通用性速查

方法不綁定單一題材：

- 懸疑：每集支付一項驗證結果，再打開更深證據問題；不能只不斷增加秘密。
- 甜寵/關係：每集讓關係位置因行動改變，不能只靠誤會拖延告白。
- 逆襲/爽劇：每集支付準備、反擊、見證或後果中的完整階段，不能連續重複公開打臉；**反派須達能力基線**（首戰佔上風 / 反殺前 ≥3 輪博弈 / 被擊敗前至少贏 1 次 —— 見 `six-stage-pipeline.md` §6.5 反派能力基線）。
- 生存/末日：每集明確資源、規則、危險與選擇代價，不能用無來源新怪物充數。
- 喜劇：笑點必須來自目標受阻、人物策略和關係反差，同時推動狀態變化。
- 群像：單集仍需一個主行動軸，其他人物線圍繞同一價值或後果匯合。

長篇重點增加重複機制、狀態和伏筆審計；短篇重點確保有限集數閉合主問題。方法的骨架保持一致。


## 九、文戲道具物理因果鏈與 AIGC 反穿模劇本設計鐵律（2026-10-14 實測拉片新增）

> **病根復盤（用戶實測「車內遞傘穿模」案例）**：
> 原稿寫作：`後座車窗降下，沈敘坐在車內，西裝領口一絲不亂，右手把一把黑色長柄傘遞出車窗，傘尖懸在雨裡；他目光隔著雨看林晚。`
> **翻車後果**：視頻模型看到「雨裡 + 長柄傘 + 遞出車窗」，由於既無動作因果鏈、又未交代傘的開合狀態，模型直接在半降的車窗上渲染出一把**完全撐開的大黑傘**往窗外亂伸，把車門和玻璃穿模得一塌糊塗！
> **核心癥結**：**這是劇本設計層面的物理常識與 AIGC 算力邊界失察**——在車內隔著狹小車窗遞長柄雨傘（哪怕遞出去再讓女主在雨裡撐開），在 3 秒視頻生成裡都是必然穿模的廢戲設計！

### 劇本層三大物理因果鐵律（P1 寫劇本時必須前置規避）
1. **禁設計「跨狹小窗口/孔洞遞送長柄或大體積道具」**：
   - ❌ **錯誤劇本設計**：男主坐在車裡把長柄傘從車窗遞給雨裡的女主 / 隔著窄窗遞長劍或大托盤。
   - ✅ **正確劇本因果鏈**：**女主原本就在雨裡撐著傘站定**（進屋或上車前在門外收攏傘），車內男主**只降下車窗露臉對視開口**；若一定要男主給女主撐傘，必須是**推開車門邁下車，手裡已撐開黑傘走到女主頭頂**。
2. **可開合/變形道具（雨傘/摺扇/長卷軸/外套）遵循「狀態前置鎖死 · 切鏡換態」**：
   - 嚴禁在同一個 3~4 秒鏡頭裡讓角色完成“接過收攏的傘→當場撐開”或“邊走邊收傘進車門”（傘骨變形極易穿模成蜘蛛網）。
   - **正解**：用切鏡（Cut）跨鏡交代狀態變化——鏡 A 車外女主右手握著**已撐開的黑傘**立於雨中 → 鏡 B 車內男主降下車窗說“上車” → 鏡 C 女主站在開啟的車門旁、右手已握著**收攏捆好的黑傘**彎腰上車。
3. **道具動作必寫「持握部位 + 開合狀態 + 物理落點」，禁寫無根局部懸空詞**：
   - 嚴禁寫 `傘尖懸在雨裡`、`劍尖停在咽喉前`、`西裝領口一絲不亂` 這類小說式裝逼廢詞；必須寫成相機能直接拍到的物理事實。
