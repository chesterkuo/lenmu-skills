# 上篇 · 階段② IP 與角色開發

## 1.1 門禁與輸入

只讀取已登記鎖定的階段①。`STEPWISE` 完成後置為 `AWAITING_CONFIRMATION`，用戶確認前禁止階段③；`FULL_SCRIPT_PIPELINE` 只有通過階段②校驗清單後才能內部鎖定並繼續。不輸出故事聖經、分集或劇本。

讀取 `PROJECT_PROFILE`、`SOURCE_MANIFEST`、全部已提供原文、事實賬本和用戶視覺硬約束。先按 [source-registration.md](source-registration.md) 第二節完成 P1/P2 角色事實掃描；沒有完成全部已提供來源覆蓋時，只能輸出 `PARTIAL_DRAFT`，不得鎖定人物終局、傷口、關係或成長弧。

本規則面向所有小說和劇本題材。測試材料只用於驗證方法，不得把其中的人名、職業、道具、關係、衝突結構或美術答案寫入通用規則。

## 1.2 開發順序

1. 掃描全篇角色證據，區分作者說明、人物自述、他人評價、重複行為、關鍵選擇和真實後果。
2. 建立 `AUDIENCE_GENRE_CONTRACT` 與 S/A/B/C 角色層級；只深做 S/A，必要的長期 B 角色做輕量檔案。
3. 為每個核心角色建立 `SOUL_ENGINE`：想要、需要、恐懼、錯誤信念、自保缺陷、底線、重複選擇和最終選擇題。
4. 建立 `AUDIENCE_AFFECTION_MODEL`：注意、敬佩、共情、反差喜愛、失望風險與重新贏回觀眾的行動。
5. 建立 `MEMORY_ANCHOR_SYSTEM`：靈魂、行為、語言、視覺、關係五類記憶點；每項必須有意義、首次使用、變化、兌現和防濫用規則。
6. 建立關係專屬行為、可表演動作、微表情、台詞節奏、音色詞和 `CHARACTER_EVOLUTION_MAP`。
7. 完成 `VISUAL_IDENTITY_SYSTEM`、基礎 `CHAR`、必要 `LOOK`、風格選擇和生成一致性約束。
8. 執行換名、剪影、盲聽台詞、角色互換、關係互換、缺陷代價與長期成長測試；失敗就返修，不用形容詞補洞。

```yaml
  genre_contract: "題材必須持續提供的體驗"
  emotional_core: "觀眾最終為哪段情感留下"
  one_line_hook: "人物 + 異常處境 + 目標 + 最大阻力"
  innovation_point: "相對常見套路真正改變玩法的一點"
  long_running_engine: "什麼矛盾能反覆升級但不重複"
  expected_payoffs:
    - "能力或身份兌現"
    - "關係或情感兌現"
    - "謎團或世界規則兌現"
  forbidden_drift: "一旦發生就破壞受眾承諾的寫法"

```

一句話賣點必須同時包含「誰、遇到什麼異常、要做什麼、失敗會失去什麼」。創新點不能只寫「更爽、更燃」，要說明新機制如何改變人物的行動選擇。

## 1.4 角色靈魂卡與 SOUL_ENGINE

把「人物好看、有個性」轉換為能連續製造選擇、衝突和記憶點的 IP 設計。所有事實保留來源；沒有證據的設計必須標記 `INFERENCE`、`ASSUMPTION` 或 `OPEN_ITEM`。

每個主要角色填寫一張；主角、核心對手和核心關係對象不可缺項。

```yaml
CHARACTER_CORE:
  character_key: "本劇本改編包使用的穩定角色鍵；本引擎不建立正式資產ID"
  story_role: "主角/對手/盟友/關係對象/催化者/見證者"
  dramatic_job: "這個角色在故事裡持續製造或解決什麼問題"
  SOUL: "當慾望和代價衝突時，他反覆選擇什麼"
  SOUL_ENGINE:
    want: "自認為想得到的具體結果"
    need: "必須學會卻尚未承認的東西"
    fear: "最害怕失去、暴露或重演什麼"
    false_belief: "由恐懼推導出的錯誤信念"
    flaw_strategy: "用於自保卻製造新問題的策略"
    moral_line: "不願跨越的邊界"
    choice_pattern: "受壓時可預測的取捨規律"
    arc_question: "最終必須以行動回答的問題"
  visible_evidence: "來源中能證明 SOUL 的動作或選擇"
  wound: "塑造當前策略的既往事件；無證據不得虛構"
  choice_cost: "堅持目標會傷害什麼"
  secret: "主動隱藏的事實"
  knowledge_boundary: "當前知道/誤以為/不知道什麼"
  relation_engine: "他需要對方什麼，又拒絕承認什麼"
  source_trace: ["EVT-####", "source_id:range"]
```

`SOUL` 用選擇表達，例如「被誤解時仍先保護弱者」，不要寫「善良正直」。核心對手也需要合理目標、有效策略和可理解代價；不能只承擔辱罵與送人頭功能。缺陷必須至少造成一次機會、資源、關係、身份或道德代價。只有「路痴、不會做飯、愛睡覺」而不影響選擇時，屬於萌點，不是人物缺陷。

## 1.5 觀眾喜愛路徑 AUDIENCE_AFFECTION_MODEL

每個 S/A 角色分別設計，不能只寫「討喜」。喜愛不是一次性標籤，而是「注意—理解—敬佩/心疼—失望風險—行動修復」的過程。

```yaml
AUDIENCE_AFFECTION_MODEL:
  attention_entry: "觀眾第一次為什麼停下來看"
  admiration_basis: "哪種能力、價值或行動值得敬佩"
  empathy_wound: "觀眾何時理解其痛苦；無來源寫 OPEN_ITEM"
  lovable_contradiction: "外在策略與真實需要之間的反差"
  disappointment_risk: "缺陷如何真實傷害目標或關係"
  recovery_choice: "靠什麼有代價的行動重新贏回觀眾"
```

角色的主要喜愛入口可來自能力、價值、脆弱、反差、幽默、關係投射或陪伴感。每個角色選擇一項主要入口、一項輔助入口；禁止全員都靠悲慘身世、身份碾壓或嘴硬心軟。只有優點沒有缺點後果會變成紙片偶像；只有創傷沒有主動選擇會變成被動受害者。

## 1.6 關係引擎矩陣

| 關係對 | A 想從 B 得到 | B 想從 A 得到 | 表面聯盟 | 隱性衝突 | 不可說出口的話 | 可升級事件 | 最終選擇 |
|---|---|---|---|---|---|---|---|
| A ↔ B | 具體需求 | 具體需求 | 當前共同目標 | 利益/價值/秘密衝突 | 潛台詞來源 | 能改變關係狀態的行為 | 尚待回答的問題 |

有效關係必須是雙向的。若刪除 B 後 A 的行動完全不變，B 可能只是工具人；若兩個人目標、語氣和解決問題方式相同，應合併職責或重設差異。

核心關係至少包含：互相需要、互相拒絕承認的需要、隱性衝突、獨有相處動作、破裂信號、修復信號和最終選擇。把關係對象互換後對白和動作仍成立，標記 `RELATIONSHIP_SWAP_PASS`。關係不是替人物「提供溫柔的一面」；不同對象必須觸發不同的控制權、距離、稱呼、保護方式和脆弱程度。

## 1.7 五類記憶點 MEMORY_ANCHOR_SYSTEM

1. **靈魂記憶點**：觀眾從一次選擇認出價值內核；重複出現但代價逐步升級的價值選擇。
2. **行為記憶點**：壓力下會重複出現、又能隨成長髮生變化的動作策略；可拍、可變化。
3. **語言記憶點**：句長、速度、稱呼、迴避方式、攻擊方式和承諾方式；不是機械口頭禪。
4. **視覺記憶點**：輪廓、主色、材質、髮型或隨身物，最多三項主錨點。
5. **關係記憶點**：人物只在特定對象面前出現的距離、視線、稱呼或保護動作。

每個記憶點填寫 `meaning`、`first_use`、`variation`、`payoff` 和 `do_not_overuse`。視覺物件若不能體現身份、情緒、時代或劇情功能，應刪除。同一集通常只突出一至兩個主記憶點；其餘保持自然存在。機械重複動作或口頭禪標記 `STATIC_SIGNATURE`。

分別寫常態、受壓、親密、憤怒和崩潰後的重組狀態。動作必須包含準備、變化和對手反應，不能只寫「眼神複雜」。聲音用年齡感、音域、氣息、語速、力度、停頓和抑揚描述，不指定現實演員或未經授權的真實人物聲音復刻。**稱呼系統與語言指紋（特徵語氣詞 / 專屬用詞）的寫法細則見 `dialogue-naturalization.md`（台詞擬人化引擎 · 台詞語感唯一權威）——本 YAML 是唯一卡模板，那份是唯一寫法權威。**

角色語言與視覺應互相支持：習慣控制局面的人可以動作極少、句子先給結論；善於偽裝的人可能外形秩序嚴密、台詞卻頻繁替換主語。不要把所有強者都設計成黑衣、低音、短句和冷臉。

## 1.9 成長地圖與長期生命力

```yaml
CHARACTER_EVOLUTION_MAP:
  stable_core: "始終不變、決定角色身份的價值核"
  ability_start: "開局的能力層級 + 能力盲區（他會什麼、不會什麼）★ 必填"
  cognition_start: "開局的認知盲區（他確信、但實際是錯的判斷）★ 必填"
  start_state: "開篇採用的舊生存策略"
  fracture_state: "舊策略造成不可忽略後果的階段"
  growth_state: "嘗試新選擇但仍會反覆的階段"
  end_state: "用新策略回答核心選擇題的狀態"
```

長期化不是凍結人物。穩定的是價值核和識別邏輯，變化的是應對壓力的策略、關係表達、錨點含義和能力邊界。每一次成長都要保留舊痕跡並支付代價，不能一集頓悟後永久無缺點。行為、語言、視覺和關係記憶點都要有成長變體：角色成長後可以不再攥緊某個物件，但可把同一物件主動交給別人；符號仍在，意義改變。

### 1.9.1 能力與認知起點（★ 2026-10-13 新增 · 治「主角開局滿級、零認知轉變」）

> **由來（粉絲系統性實測反饋）**：「人物弧光：**主角基本全是滿級，零認知轉變**！配角基本全是工具人，全程零智商」。
> **病根**：`start_state` 寫的是「開篇採用的舊生存策略」（偏"錯誤策略"），**不是"能力層級"**——於是"主角一開局就很能打 / 很會算 / 自帶金手指"**完全不違規**。全包搜不到任何一條「主角開局必須存在能力或認知盲區」的規定。

三條硬約束（**進入階段③故事聖經時逐條填寫，缺失即 `REVISE`**）：

1. **`ability_start` 必填**——寫明開局的能力層級 + **能力盲區**（他會什麼、**不會什麼**）。⛔ **不得全員滿級**：主角開局必須存在**可測量的能力缺口**，且該缺口在全劇中**至少造成 1 次真實損失**（呼應 §1.9「每一次成長都要保留舊痕跡並支付代價」）。
2. **`cognition_start` 必填**——寫明開局的**認知盲區**：他**確信、但實際是錯**的判斷（關於世界規則 / 關於某個人 / 關於自己）。⛔ **不得開局全知**：整部劇**至少一次**讓這個盲區被事實擊穿，並**迫使行為改變**。
3. **認知轉變必須落在行動上**——逐集 `growth_state` 四態（`BEFORE_BREAK`/`UNDER_PRESSURE`/`PARTIAL_SHIFT`/`NEW_CHOICE`）**不得連續 ≥3 集停留在同一態**；轉變必須通過**選擇和後果**體現，⛔ 不得只用旁白宣佈或稱呼變化頂替（呼應 `episode-planning.md` §5.9）。

**金手指類設定（重生 / 系統 / 穿越 / 天生神體）不豁免**：主角可以強，但**強的部分必須寫明代價或限制**。直接對位 IP 退回條件——「**主角只依賴外掛或身份，自己沒有選擇與代價**」→ **IP 退回**（見 §IP 質量門）。

**配角側同步（治"工具人"）**：核心配角至少各有一項**獨立於主角的目標**與**一次改變戰局的自主行動**；⛔ 刪除後主角行動完全不變的角色（§1.6 工具人判據）不得佔用核心配角名額，降為功能角色。

**長期運營**：`IP_LONGEVITY_EXTENSION` 只從角色內核推導——情緒名場面、關係名場面、日常反差、角色短片、表情表達、海報符號和周邊圖案。不得先為周邊強加寵物、武器、飾品和口頭禪，也不得讓運營提案反向成為主線事實。長期可用的角色應同時經得住主線高潮、關係戲、失敗、權力變化和普通日常；只能在一種爽點場景成立的角色，不具備長期生命力。

## 1.10 IP 設計規則：CHAR / LOOK / VOICE

- `CHAR`：不輕易變化的臉、發、年齡感、體態、身高關係、基礎服裝結構和個人符號。
- `LOOK`：由劇情支付、跨場景持續或高頻複用的服裝、傷勢、身份和階段狀態。
- 短暫表情、單鏡動作、臨時汙漬不建立新 `LOOK`。
- 年齡、傷勢、貧富、職業和時代變化必須有來源或顯式假設。
- 每個主要角色優先一個行為記憶點、一個語言記憶點和一組視覺錨點；視覺錨點服務身份、時代和情緒，不添加與劇情無關的複雜裝飾。

## 1.11 視覺身份與 IP 包裝

視覺目標不是「細節很多」，而是在不同鏡頭、服裝和情緒狀態下仍能穩定識別，並且每項設計都能解釋人物、時代或劇情功能。

### ★ WORLD_ANCHOR_CARD · 世界錨卡（2026-10-12 新增 · 階段③ 強制產出）

> **由來（粉絲群實測反饋）**：「劇本大綱明確了 2035 年南京，劇本名字就是外賣員，世界觀第一句就是『全鏈智能』AI 系統上線，
> **他出來的是 80 年代的破街爛車，人物也搞得像個協警，和外賣員的特徵沒有關係**。」
> **病根**：世界觀設定此前只活在散文裡——**沒有被登記成一張卡、沒有寫進 HANDOFF 禁改項、也沒有機檢**，

### VISUAL_IDENTITY_SYSTEM

每個 S/A 角色固定記錄：

- `silhouette`：正面、3/4、側面和背面仍成立的外輪廓。
- `shape_language`：圓、方、三角和不對稱如何表達人物，不把形狀當絕對人格公式。
- `palette`：主色、輔助色、強調色及使用比例；狀態變化如何調整而不換人。
- `material`：服裝和個人物件的主要材質、磨損與時代邏輯。
- `face_hair`：兩至三個穩定臉發錨點，不堆十項細節。
- `body_posture`：重心、肩頸、手部和空間習慣。
- `signature_symbol`：最多一至兩個有劇情意義的個人符號。
- `forbidden_drift`：不可改變的身份、年齡感、體態、輪廓和時代邊界。

視覺身份至少定義輪廓、形狀語言、主輔色、材質、臉發錨點、身體重心和一個主符號。

### 三秒識別與去裝飾

執行：

1. `SILHOUETTE_TEST`：純黑輪廓能否和主要角色區分。
2. `GRAYSCALE_TEST`：去掉顏色後，形狀和材質層級是否仍可認。
3. `CROP_TEST`：半身、臉部或手部局部至少有一種穩定錨點。
4. `MOTION_TEST`：不看臉，只看站姿、走路和取物方式能否區分。
5. `SWAP_TEST`：互換服裝或道具後是否全部失去身份；若是，說明人物本體太弱。

三秒識別來自結構與動作，不來自堆疊飾品；任意交換兩個角色的服裝細節後若仍無違和，說明視覺沒有與人格和身份綁定。刪除與身份、情緒、時代、劇情和關係都無關的裝飾。超過三個主視覺錨點通常會降低識別和生成穩定性，標記 `VISUAL_OVERDESIGN`。

### 風格評分

對推薦主風格和最多兩個備選風格分別按 1–5 評分：題材清晰度、情緒表現、角色一致性、動作可生成性、場景複用率、豎屏構圖、資產成本和長篇耐看度。輸出證據和代價，不因「流行」直接選擇。同時從題材證據、情緒基調、目標畫幅、動作複雜度和資產成本推薦主風格，說明備選與不推薦方案的代價。

### 身份提示詞拆分

每個身份提示詞拆成：身份塊、造型塊、表演塊、鏡頭中性塊和負面約束。身份主圖使用單人、中性光線、中性表情和無敘事背景；行為圖只展示已經鎖定的記憶動作。

### IP_PRESENTATION_PACKAGE

面向用戶檢查的包裝包必須包含：

1. 一句話靈魂和一句話市場識別。
2. 觀眾喜愛路徑與可能反感點。
3. 三秒識別拆解：輪廓、動作、語言、關係。
4. 正面/3/4/側面/背面、半身、面部、手部和個人符號的文字規格。
5. 常態、受壓、真心、憤怒四組表演關鍵幀。
6. 主風格、備選風格和明確不推薦理由。
7. 可直接生圖的身份主圖、多視角、表情行為圖提示詞及負面約束。
8. `TEXT_SPEC`、`P0_DRAFT` 或 `APPROVED_R01` 狀態，不得混淆。

## 1.12 跨題材 IP 適配器

題材適配器只改變分析重點和表現手段，不提供固定性格、服裝、創傷或劇情答案。先從來源判斷題材合同，再選擇一個主適配器和至多一個輔助適配器；混合題材要說明誰決定角色內核、誰決定外在表達。

### 通用核心不變

所有題材都必須完成：來源證據、選擇型靈魂、觀眾喜愛路徑、真實缺陷代價、關係專屬性、五類記憶點、視覺身份、表演聲音和成長變體。適配器不能繞過這些核心，也不能把流行套路當成來源事實。

### 題材側重點

**男頻成長、逆襲與強者敘事**：重點檢查能力如何被行動證明、尊嚴和責任底線、獲得力量後的選擇、勝利代價與對手有效策略。禁止把角色吸引力等同於財富、戰力、身份碾壓和所有人震驚。

**女頻情感、婚戀與成長**：重點檢查主體目標、情感邊界、關係權力變化、照顧與控制的區別、被愛之外的能力和選擇。禁止把「受歡迎、被寵、被爭奪」當成人物靈魂。

**懸疑、犯罪與職業推理**：重點檢查觀察/判斷方法、知識邊界、秘密管理、職業倫理和真相代價。禁止用萬能直覺、突然文件和創傷標籤代替推理人格。

**喜劇與輕喜關係**：重點檢查尊嚴目標與現實結果的落差、反應節奏、錯誤策略、關係接球方式和可變化的日常記憶點。禁止靠固定口頭禪、降智和重複社死維持喜感。

**古裝、權謀與歷史幻想**：重點檢查禮法身份、公開與私下語言、政治目標、權力姿態、服裝層級和時代材料。禁止現代網絡口吻、全員黑金華服和無來源的王者氣場。

**玄幻、仙俠與超能力**：重點檢查世界規則如何進入身體、能力使用、代價、倫理選擇、輪廓和材質。禁止只靠發光特效、血統和等級製造識別。

**末日、生存與群像**：重點檢查資源策略、群體位置、壓力決策、人性底線、損失後的行為變化和裝備功能。禁止全員戰術黑衣、冷臉和同一種強硬說話方式。

**年代、現實與家庭倫理**：重點檢查時代身份、勞動細節、社會限制、家庭權力、樸素情感和符合年代的色彩材質。禁止用現代審美直接覆蓋人物處境，也禁止把受苦等同於討喜。

**穿越、重生與身份錯位**：重點檢查原身份與新身份衝突、知識可用邊界、改變既定事件的代價、語言偽裝和雙重關係位置。禁止讓現代知識變成無成本萬能外掛。

**恐怖、怪談與暗黑幻想**：重點檢查恐懼應對策略、規則認知、身體反應、道德邊界和不可解釋部分。禁止用蒼白皮膚、紅眼、黑衣等外觀直接代替人物。

### 跨題材檢查

對每個核心角色回答：如果把本角色移到另一題材，換掉服裝和道具後是否仍完全成立？完全成立說明題材沒有進入行為和價值；完全不成立說明人物只剩世界觀裝飾。合格結果應是穩定靈魂仍成立，但能力、壓力、關係和表達必須依賴當前項目。跨題材測試至少選擇與主項目差異最大的兩個合成素材，驗證不會重複輸出同一套高冷、嘴硬、悲慘過去、黑紅配色和固定小動作；發現固定答案時標記 `GENRE_TEMPLATE_IMPRINT`。

## 1.13 概念圖模式

- 默認 `TEXT_SPEC_ONLY`：交付完整視覺規格和可直接生圖的身份提示詞，狀態為 `TEXT_SPEC`。先讓用戶確認文字身份、輪廓和風格，再考慮生成。
- 用戶明確要求生成概念圖時才進入 `GENERATE_DRAFTS`；先鎖文字身份塊，再生成中性身份圖、多視角圖和少量行為/表情圖，狀態只能是 `P0_DRAFT`。逐項記錄它鎖定了什麼、偏離了什麼。
- 用戶確認後才能升為 `APPROVED_R01`；未經確認的概念圖不是正式資產，也不得反向改變人物來源事實。概念圖若與來源或文字身份衝突，修改圖，不修改原作人物。
- **裁定**：概念圖的實際生成屬於 sd-asset-engine 職責（人物立繪三風格模板）；本引擎交付文字規格與提示詞，狀態保持 `TEXT_SPEC`。

## 1.14 IP 質量門

`IP_QUALITY_GATES` 用來判斷角色能否進入故事和劇本階段，不判斷市場一定爆款。所有結論必須引用來源、可執行設計或明確的用戶確認。

### 十二項質量門

```yaml
IP_QUALITY_GATES:
  full_source_coverage: PASS
  source_fidelity: PASS
  choice_driven_soul: PASS
  audience_affection_path: PASS
  character_distinctiveness: PASS
  relationship_specificity: PASS
  visual_recognition: PASS
  performance_playability: PASS
  evolution_capacity: PASS
  production_consistency: PASS
  downstream_bindability: PASS
  genre_fit_without_template_copy: PASS
failure_flags: []
```

**`evolution_capacity` 門判據補充（★ 2026-10-13 增補 · 治「主角滿級零轉變」）**：本門除原有的「成長前後有真實差異且保留內核」外，**追加兩條必判**——① `ability_start` 已填，且主角存在**可測量的能力盲區**（⛔ 不得開局滿級、不得全員滿級）；② `cognition_start` 已填，且全劇**至少一次**讓認知盲區被事實擊穿並改變行為。**缺任一條 → 本門判 `REVISE`**（判據見 §1.9.1）。**門數不變（仍十二項），本條是已有門的判據強化。**

### 八項識別與互換測試

1. `換名測試`：刪除名字後，能否從選擇、語言和行為認出角色。
2. `剪影測試`：去臉去顏色後，核心角色輪廓是否區分。
3. `盲聽測試`：去掉說話人標籤後，句式、節奏和關係態度是否可辨。
4. `角色互換測試`：把兩名核心角色的行動互換；若劇情仍完全成立，角色策略克隆。
5. `關係互換測試`：把關係對象互換；若親密、攻擊和保護動作不變，關係沒有專屬性。
6. `缺陷代價測試`：刪除人物缺陷後，劇情和關係是否不變；不變則缺陷只是標籤。
7. `成長測試`：成長前後是否既有真實差異，又保留穩定內核。
8. `下游綁定測試`：能否給故事弧、分集和劇本提供具體選擇、台詞、行為、關係和視覺約束。

### 退回標記

出現任一未解決標記時不得鎖定階段②；不能通過清空數組掩蓋正文問題。

- `SOURCE_INCOMPLETE`：已提供來源沒有完整掃描。
- `ADJECTIVE_ONLY_SOUL`：靈魂只能用形容詞描述，無法指向代價選擇。
- `GENERIC_LIKABILITY`：只寫善良、強大、可愛、悲慘，未說明觀眾喜愛過程。
- `CLONED_CHARACTER_VOICE`：核心角色句長、攻擊、防禦和承諾方式相同。
- `DECORATION_ONLY_MEMORY`：記憶點與身份、情緒、關係和劇情均無關。
- `RELATIONSHIP_SWAP_PASS`：關係對象互換後表現不變。
- `VISUAL_OVERDESIGN`：主錨點過多、層級混亂或無法穩定生成。
- `STATIC_SIGNATURE`：動作或口頭禪機械重複，沒有意義變化。
- `UNPAID_FLAW`：宣稱缺陷，但從未造成選擇或後果。
- `MAX_LEVEL_START`：主角開局即滿級 / 全能，無能力盲區，全劇無一次因能力不足受挫（治「主角滿級零轉變」，見 §1.9.1）。
- `NO_COGNITIVE_SHIFT`：主角認知全書不變，無被事實擊穿的盲區（治「零認知轉變」，見 §1.9.1）。
- `UNSUPPORTED_WOUND`：虛構來源沒有提供的創傷或秘密。
- `GENRE_TEMPLATE_IMPRINT`：把參考案例或流行題材模板寫入當前角色。
- `DOWNSTREAM_UNBINDABLE`：人設無法轉成故事選擇、分集壓力或劇本表演。

### 主編與觀眾雙讀

主編檢查事實、差異、長線和生產；第一次觀看的觀眾只回答：我為什麼注意他、為什麼喜歡或討厭他、最記得哪個選擇、哪個動作只能屬於他、下一次想看他面對什麼。兩種讀法都成立，才允許進入下游。

階段③的職責不是「概括每章發生了什麼」，而是建立全劇可追溯的真值、變化、創作核心和改編策略，讓分集編劇不用重新通讀原文也能準確回答：

- 這是什麼故事，最不可替代的創意是什麼？

- 世界規則如何限制行動併產生代價？
- 哪些人物選擇體現鎖定 IP，哪些缺陷必須支付後果？
- 哪些內容必須保留、可以壓縮或允許重排？
- 按 1—3 分鐘短集估算，故事具有多大的系列容量？

階段③可以提出集數區間、事件級商業里程碑、鉤子候選和敘事重排候選；不得鎖定精確集數、把鉤子分配給具體集、展開正式對白或決定鏡頭。

## 2.2 三遍通讀

短篇與長篇都執行三遍；短篇可以在同一上下文完成，但不能省略任何一遍；長篇按 P1/P2 覆蓋全部已提供來源。沒有完成全源覆蓋時只可輸出 `PARTIAL_DRAFT`，不得鎖定全局大綱、終局價值判斷、集數區間或人物終局。

**第一遍：觀眾通讀。** 不急於做表格，記錄真實閱讀反應：第一次產生興趣、理解題材承諾和願意繼續讀的位置；第一次明確共情、敬佩、厭惡或擔心人物的位置；高概念第一次被動作證明而不是被說明的位置；閱讀動力減弱、事件重複、規則混亂或情緒斷裂的位置；最期待的三類兌現，以及結尾是否真正支付。產出 `AUDIENCE_READING_TRACE`。不要把個人喜好冒充市場事實；寫清依據事件和可能對應的受眾。

**第二遍：事實通讀。** 按來源順序鎖定事件、因果、人物、關係、規則、狀態、信息、伏筆、賭注和壓力。每個關鍵事件至少能用下列鏈條複述：

`因為前提成立 → 人物想得到目標 → 採取行動 → 對手/規則反制 → 人物換策或支付代價 → 狀態發生變化`

若只能寫「發生了衝突」「有人震驚」「關係更差」，說明還沒有識別有效事件。

**第三遍：改編通讀。** 在事實鎖定後判斷表現形式、壓縮合並、視覺化、信息延後、敘事重排、商業里程碑、鉤子候選和系列容量：哪些敘述可以轉成動作、道具、環境變化或關係行為；哪些重複說明可以合併、哪些重複是成長遞進不能刪；哪些事件適合成為大弧入口、中點、高潮和情感回收；哪些信息可以延後、哪些前提必須先建立；哪些事件允許冷開場、插敘、倒序或並行交叉；若重排，如何回到主時間線並維持人物知識邊界。產出 `ADAPTATION_BLUEPRINT`、`HOOK_CANDIDATE_LEDGER` 和 `SERIES_CAPACITY_REPORT`，不改寫來源事實。

## 2.3 P1 分塊事實提取 與 P2 全局增量合併

**P2**：只處理新哈希與未覆蓋範圍，檢查姓名別稱、絕對/相對時間、身份、關係、地點、規則、資源、道具、傷勢、知識邊界和伏筆狀態。原文不能解決時保留兩個候選並標記 `OPEN_ITEM`，不得選擇更戲劇化的版本冒充事實。

## 2.4 P3 全劇開發與改編診斷

## 2.5 原始創意 DNA

`ORIGINAL_CREATIVE_DNA.md` 固定回答：

1. 原始前提：人物在怎樣的異常處境中必須做什麼？
2. 核心機制：什麼規則能持續製造新行動，而不是一次性噱頭？
3. 核心梗：觀眾用一句話能複述的反差、關係或玩法是什麼？
4. 慾望投射：觀眾借主角體驗何種補償、成長、愛情、正義或生存幻想？
5. 情緒承諾：爽、燃、甜、虐、笑、疑、懼分別來自什麼事件結構？
6. 新鮮差異：與常見題材相比，哪一條具體規則或人物選擇不同？
7. 長線發動機：故事為何可以不斷升級，而不是重複同一衝突？
8. 傳播記憶：三至五個來源支持的場面、台詞功能、道具或選擇候選。

**創意三層**：表層賣點（最容易被看到的身份、機制或處境）、中層引擎（能反覆生成目標、阻力、代價與變化的衝突機制）、深層命題（人物在越來越高代價下反覆回答的價值問題）。三層必須互相支持：只有表層賣點會快速耗盡；只有深層命題會缺乏短劇入口；中層引擎重複會造成每個大弧換人不換戲。

## 2.6 類型與受眾合同

`AUDIENCE_GENRE_CONTRACT` 至少包含：主類型、次類型與題材外殼；核心目標受眾和次級受眾；受眾進入故事的第一興趣點；受眾持續追看的長期問題；外部、關係、情感和信息四類承諾；觀眾可能棄看的原因；本項目不能丟失的類型滿足；本項目不能機械複製的同類套路。

「年輕用戶」「喜歡爽劇的人」不夠具體。應說明他們期待看什麼選擇、關係、規則或兌現，以及什麼重複會讓他們失去興趣。

## 2.7 一句話故事與多層梗概

在 `02_STORY_BIBLE.md` 和 `STORY_CANON_MANIFEST.json` 中同時建立四層：

- `one_sentence`：一句話包含主角 + 異常處境/獨特機制 + 主動目標 + 主要阻力 + 最大代價。不要只羅列題材標籤。
- `short_synopsis`：約 300—500 字，說明起因、目標、主要阻力、第一次有效行動、重大轉折、高潮選擇和結局方向。
- `full_synopsis`：按完整因果寫清開始、發展、中點、危機、高潮、結局以及主要關係變化。不得用「經歷一系列困難」「最終戰勝敵人」跳過核心過程。
- `arc_outline`：按行動型大弧複述全劇，每弧寫入口狀態、目標、阻力、換策、代價、高潮選擇、三類兌現、出口狀態和下一弧債務。它是階段④的直接宏觀輸入。

梗概必須覆蓋結局；來源未完結時明確寫 `SOURCE_INCOMPLETE`，不自行補完。

## 2.8 世界觀和規則

`WORLDVIEW_VALUE_BIBLE.md` 與 `WORLD_RULE_LEDGER.json` 分開承擔人類可讀解釋和機器狀態。

**世界觀層**：時間、地域、社會結構、階層和日常秩序；陣營、組織、職業與利益關係；資源如何獲得、流轉、爭奪和損耗；普通人在規則中如何生活，而不只描述強者；異常規則第一次進入日常的事件。

**規則層**：每條 `RULE-####` 記錄 `source_trace`、`rule_statement`、`scope`、`activation_condition`、`capability`、`limit`、`cost`、`failure_consequence`、`known_by`、`effective_from_event`、`changed_by_event`、`status`。

能力沒有限制和代價時，規則不能製造戲；規則沒有在事件中影響行動時，只是背景設定。

## 2.9 價值觀與主題衝突

不要用作者口號代替主題。建立 `WORLDVIEW_VALUE_CONTRACT`：主角認為世界應該如何運作；主要對立者認為世界應該如何運作；兩種觀點各自為何具有現實吸引力；主角觀點的盲區和對立觀點的真實反證；哪三個遞增選擇檢驗價值觀；哪次選擇造成關係或現實損失；結局通過行動肯定、否定或保留什麼。

主題問題必須可被人物選擇回答。例如「規則公平是否等於人的公平」可以進入利益分配、救援順序和世界選擇；「正義很重要」無法預測人物行動。

`dramatic_proof` 必須列事件：誰選擇了什麼、失去什麼、世界因此發生什麼變化。刪除價值觀描述後若事件不變，說明主題還沒有進入劇情。

## 2.10 人物故事小傳

`CHARACTER_STORY_BIOS.md` 不是重複階段②的外形和性格，而是說明角色如何進入這一個故事。

每個 S/A 角色固定包含：`character_id` 與鎖定 `ip_version`；原文身份、經歷、當前狀態和來源證據；外部目標、內部需要和當前錯誤策略；在主線中的不可替代功能；能主動推動的事件，不是隻被捲入的事件；最有效的對手或關係阻力；起始、裂變、變化和終局狀態；缺點造成的真實後果；觀眾喜愛點由哪次行動支付；關鍵關係建立、斷裂、修復和回收事件；記憶錨點在全劇如何首用、變體和兌現；若刪除此角色，哪些因果或情感必然失效。

B/C 角色可以使用輕量小傳：身份、目標、阻力功能、信息權限、狀態範圍、合併風險和不可替代證據。

人物小傳中的傷口、秘密、關係和能力必須來自來源或標為創作增強候選。不得為讓人物「更立體」自動添加童年創傷、愛情、血緣或隱藏身份。

## 2.11 全劇大綱與大弧

### 核心問題

用一組可檢驗的問題統領全劇：外部問題（主角必須完成什麼，失敗的可見後果是什麼）、內部問題（主角的舊策略為什麼已不再有效）、關係問題（主角要獲得目標必須與誰重新選擇彼此）、世界問題（異常規則如何限制行動而非只提供便利）、受眾承諾（觀眾持續等待哪三類兌現）。

### ARC 大弧卡

```yaml
ARC:
  arc_id: "ARC-##"
  title: "行動型名稱"
  source_events: ["EVT-####"]
  entry_state: "目標、關係、信息、資源、危險的起點"
  driving_question: "本弧必須回答的問題"
  protagonist_goal: "可完成或失敗的外部目標"
  opposition: "有目標、有策略的主要阻力"
  escalation_ladder:
    - "第一次有效行動"
    - "行動造成的新代價"
    - "信息改變後的新策略"
    - "不可迴避的選擇"
  midpoint_change: "使原計劃失效的新事實或關係變化"
  climax_choice: "人物必須付出代價的行動"
  payoff: "外部、情感、信息分別兌現什麼"
  exit_state: "五類狀態發生了什麼變化"
  unresolved_debt: "交給下一弧的具體問題"
  confidence: "FACT/INFERENCE/ASSUMPTION"
```

大弧的高潮必須是人物行動產生的結果。若刪除主角仍會自然解決，說明主角沒有推動故事；若每次升級只換一個更有權勢的敵人，說明衝突引擎重複。

額外檢查：大弧名稱必須描述行動，不用「成長篇」「感情篇」一類標籤；每弧至少存在一次有效反制和一次策略改變；每弧高潮由人物選擇造成，不由巧合或救兵自動完成；每弧至少支付外部、情感、信息中的兩類承諾；連續三個大弧不得共享同一衝突公式；下一弧繼承新狀態，不重複上一弧已經解決的爭吵。

全局大綱應同時保留來源順序和建議呈現順序。來源順序是事實；建議呈現順序是候選，必須通過重排審計後才能交給階段④。

### IP_ARC_BINDINGS

在事件因果賬之前，先為每個 S/A 級角色建立可被分集消費的 `IP_ARC_BINDINGS`：

```yaml
IP_ARC_BINDINGS:
  character_id: "CHAR-####"
  ip_version: "v1.0"
  stable_core: "全劇不可漂移的價值核與人格矛盾"
  false_belief_under_test: "本弧被事件反覆檢驗的錯誤信念"
  choice_escalation: ["低成本選擇", "關係代價選擇", "不可逆選擇"]
  flaw_consequence: "缺點在本弧具體造成的損失"
  affection_payoff: "觀眾為何在本弧更理解、敬佩、心疼或想追隨他"
  relationship_arc: "關鍵關係如何因雙方行動改變"
  memory_anchor_evolution: "行為/語言/視覺/關係錨點如何變體或兌現"
  forbidden_drift: ["本弧不得出現的人格捷徑"]
```

`stable_core` 不能寫成「高冷、善良、聰明」一類空泛形容詞；必須能預測人物在兩難處境中的取捨。`memory_anchor_evolution` 不是每弧機械重複口頭禪或招牌動作，而是讓同一識別錨點在壓力、關係和成長狀態下產生新含義。

### 事件因果賬

`EVENT_LEDGER.json` 的關鍵事件至少記錄：

```yaml
event_id: "EVT-####"
source_trace: ["source_id:range"]
precondition: ["發生前必須成立的事實"]
trigger: "引爆事件"
actor_goal: "行動者此刻想得到什麼"
action: "行動者主動做了什麼"
counteraction: "誰如何反制"
result: "可見結果"
state_change: "目標/關係/信息/資源/危險的變化"
causes: ["EVT-####"]
enables: ["EVT-####"]
```

「有人生氣」「雙方爭吵」不是充分事件，除非它改變承諾、關係或後續行動條件。

## 2.12 信息差、伏筆、狀態與賭注賬本

### 信息差矩陣

`INFORMATION_MATRIX.md` 按事實列出觀眾、主角、盟友、對手分別處於 `KNOWS`、`SUSPECTS`、`BELIEVES_FALSE` 或 `UNKNOWN`，並記錄生效事件。身份懸念的張力來自誰知道什麼以及誰據此行動，不來自作者故意隱瞞已經被人物說出口的信息。

| 信息項 | 觀眾 | 主角 | 盟友 | 對手 | 釋放事件 | 行動後果 |
|---|---|---|---|---|---|---|
| INFO-### | 狀態 | 狀態 | 狀態 | 狀態 | EVT-#### | 誰改變策略 |

### 伏筆與回收賬

`SETUP_PAYOFF_LEDGER.md` 同時管理身份、道具、規則、承諾、創傷和關係行為。

| 賬項 | 類型 | 種下事件 | 當時表層功能 | 二次提醒 | 計劃回收事件 | 回收方式 | 狀態 |
|---|---|---|---|---|---|---|---|
| SP-### | 道具/信息/承諾 | EVT | 不洩底的當下作用 | EVT/無 | EVT/待定 | 行動、證據或選擇 | PLANTED/REMINDER/PAID/OFFENDED |

伏筆第一次出現必須有當下功能，不能只為未來強行擺設；回收必須改變人物決定或局勢。已經回收的賬項不得再次當作全新秘密。

### 狀態連續賬

人物關係、傷勢、資源、職業、地點控制權、道具歸屬和造型變化都記錄 `effective_from_event` 與可選 `effective_until_event`。狀態變化先進入賬本，再允許下游使用，防止人物突然康復、知道秘密或持有不存在的道具。

### 賭注與後果階梯

為每條主線登記 `STAKE_CONSEQUENCE_LADDER`：觀眾何時知道人物可能失去什麼、誰有能力讓損失發生、第一次警告、第一次真實損失、不可逆後果和最終支付。資格、項目、婚姻、生命或身份不能在人物拿來施壓時才第一次出現。

| stake_id | 賭注 | 建立事件 | 首次受壓 | 首次真實後果 | 不可逆節點 | 誰推動後果 |
|---|---|---|---|---|---|---|
| STK-### | 具體可失去項 | EVT | EVT | EVT | EVT/待定 | 有目標的行動者或規則 |

「可能被問責」不是後果；被暫停權限、失去機會、公開站隊、交出證據、關係破裂或時限縮短才是可觀察狀態變化。

同時建立 `SOURCE_PRESSURE_LEDGER`，把每項來源壓力拆成：原文措辭/原意、開始時間、觸發條件、作用對象、後果強度、來源範圍和當前狀態。下游可壓縮表達，不得改變邏輯量詞：`可能` 不能變成 `一定`，`三天後未完成` 不能變成 `今天停止就立即發生`，`面臨審查` 不能變成 `已經被取消資格`。用戶若明確授權改變，登記為 `USER_OVERRIDE`，否則維持 `UNCHANGED`。

### 情感證據鏈

傷口和關係不能只停留在人物小傳。為核心情感記錄：觸發物、身體/語言反應、人物試圖隱藏什麼、它如何改變一次策略、人物最終為此支付或放棄什麼。若刪除情感設定後人物行動完全不變，說明情感線尚未進入故事。

## 2.13 商業追看承諾

商業性來自「兌現後打開更大問題」，不是永遠拖延答案。階段③登記事件級里程碑：

高概念第一次可視化；主角無法退出的損失和目標；第一次有效能力驗證；關鍵關係結盟或決裂；第一次完整外部與情感兌現；更大目標建立；中段規則重估；核心秘密的來源支持反轉；不可逆失敗或代價；最終選擇與情感回收。

每個里程碑綁定 `EVT`、`ARC`、`IP_ARC_BINDINGS` 和來源範圍。階段③只登記適合形成追看承諾的事件，不分配集號。推定只可組織已有事實或補足連接動作，不能生成新的核心證據和答案。原文未提供真正身份、失蹤原因、關鍵道具來源、隱藏文件、機關或最終勝負時，相關里程碑寫為 `OPEN_ITEM`，不得因為交付集數較少就自動創造謎底；閉合人物當下行動，不閉合來源未回答的事實。

## 2.15 改編藍圖：七類改編決策

改編可以改變呈現順序、信息密度、場面組織和表達媒介，但不能無授權改變：主線的目標、關鍵因果和重大結果；人物做出關鍵選擇的真實動機；世界規則的能力、條件、限制與代價；已經建立並在後文回收的伏筆；關鍵關係的形成、背叛、修復和終局位置；具有獨特功能和情感意義的來源台詞。

「為了節奏更爽」不是改變核心事實的授權。增強只能在不改變核心事實的連接動作、可見反應、職業流程、空間調度和信息組織中進行，並標為 `INFERENCE` 或 `ASSUMPTION`。

**`MUST_KEEP`**：保留主線因果、關鍵選擇、核心規則、關鍵台詞功能、關係轉折和伏筆回收。記錄來源範圍與事件 ID、必須保留的功能、允許改變的表達形式、刪除後會破壞什麼。

**`COMPRESS`**：壓縮重複解釋、重複升級、重複圍觀反饋、功能相同的流程和對主線無新增狀態的往返。壓縮後必須保留因果前提、人物為何改變策略、第一次有效建立和最後一次完整兌現、關係與世界狀態變化。若重複行為本身用於證明習慣、升級代價或關係惡化，不能全部壓成一句。

**`MERGE`**：合併功能相同的次要人物、場所、會議或阻力節點。合併前檢查：兩者是否擁有不同信息權限；是否分別承擔不同伏筆；是否在不同關係中產生獨特選擇；合併後是否造成角色知道不該知道的信息；是否讓一次背叛、救援或見證失去情感意義。名稱不同但功能相同不代表必須合併；功能相似但信息與關係不同也不能合併。

**`VISUALIZE`**：把敘述、心理和設定轉成可見可聽的行為證據——心理懷疑 → 核對記錄、停手、改變站位或試探對方；身份壓力 → 權限失效、稱謂變化、座位調整或資源被收回；關係疏遠 → 停止專屬行為、拒收物品、改用正式稱謂；世界規則 → 能力失敗、代價出現、環境響應或普通人改變行為。視覺化不能新增能夠回答核心謎底的證據，也不能讓人物提前暴露秘密。

**`REORDER_CANDIDATE`**：允許冷開場、倒序、插敘、並行交叉和多視角，但當前只登記候選，不直接改變事實順序。每項寫：來源時間順序、建議呈現順序、預期觀眾收益、進入點和回到主時間線的位置、被提前展示的信息、必須隱藏的信息、因果知識和情感風險、`CANDIDATE/REJECTED` 狀態。

**`DEFER`**：延後解釋或釋放已經存在的事實。延後必須滿足：人物仍能依據當時可見信息做出合理行動；觀眾不會把必要因果誤解成編劇漏洞；延後位置有來源支持的證據或人物行動可兌現；不重複假揭露同一秘密。

**`FORBIDDEN_CHANGE`**：明確禁止——新增來源不存在的幕後身份、血緣、暗號、隱藏文件或能力來源；把條件式壓力改成已經發生的懲罰；為製造爽點讓人物違背鎖定 IP 且不承擔後果；把對手降智以便主角贏；把未完成原作強行寫成閉合結局；為縮短集數刪除人物作出關鍵選擇的前提。

### 場景化候選（DRAMATIZATION_CANDIDATE）

為每個重要敘述段落填寫：

```yaml
source_trace: "SRC-###:範圍"
source_function: "這段敘述提供何種因果、情感或規則"
visible_evidence: "觀眾能看到或聽到什麼"
active_character: "誰為了目標採取行動"
opposition_response: "誰或規則如何反制"
state_change: "動作後發生什麼變化"
protected_information: "不能提前洩露什麼"
confidence: "FACT/INFERENCE/ASSUMPTION"
```

不能只把旁白拆成人物輪流朗讀。若沒有行動、阻力和變化，仍然只是換了說話者的說明文。

## 2.16 混編、倒序與插敘：六項重排門禁

每個 `REORDER_CANDIDATE` 必須通過六項門禁：

1. **因果門**：觀眾可以暫時不知道原因，但人物行動所需的原因必須已經真實發生。不能讓未來結果反向成為過去行動的動機。
2. **知識邊界門**：重排後分別記錄觀眾、主角、盟友和對手知道什麼。人物不能使用只向觀眾展示的信息。
3. **懸念保護門**：冷開場展示危險或結果時，避免同時洩露依賴身份、方法或關係選擇的真正答案。展示「發生了什麼」不等於展示「誰、為什麼、如何做到」。
4. **返回路徑門**：明確何時、以何種動作、聲音、道具或時間標記回到主時間線。不得連續多集停留在解釋性回憶，使主行動失速。
5. **情感支付門**：如果提前展示死亡、背叛或勝利，會不會讓之前的關係選擇失去不確定性？若會，只能展示不完整結果或拒絕該候選。
6. **來源忠實門**：重排改變的是觀眾獲取信息的順序，不是事件真實發生的順序、人物動機或結果。兩套順序必須同時保存在賬本中。

通過六門後狀態仍為 `CANDIDATE`，由階段④根據全劇節奏決定是否採用。

## 2.17 鉤子候選池

`HOOK_CANDIDATE_LEDGER.md` 只登記來源支持、存在具體等待問題且有兌現事件的候選。

| 字段 | 要求 |
|---|---|
| `hook_id` | 穩定 `HKC-####` |
| `hook_type` | ACTION/CHOICE/EVIDENCE/ARRIVAL/DANGER/IDENTITY/EMOTION |
| `source_events` | 產生鉤子的事件 |
| `waiting_question` | 觀眾下一步等待的唯一具體答案 |
| `payoff_events` | 來源支持的部分或完整兌現事件 |
| `source_trace` | 原文範圍 |
| `spoiler_risk` | 是否提前破壞更大秘密 |
| `relationship_or_value_effect` | 兌現後改變哪段關係或判斷 |
| `status` | `CANDIDATE/REJECTED`；交給階段④的只能是 `CANDIDATE` |

階段③不填寫 `episode_id` 或 `payoff_episode`。同一來源秘密不能拆出多個含義相同的假鉤子。

**有效鉤子的最低條件**：等待對象具體；已有來源事件建立問題；已有來源事件能夠兌現；兌現會改變行動、關係、信息或危險；不依賴突然出現的身份、巧合或資源；可以在後續動作中兌現，不只靠解釋。

**鉤子與拖延的區別**：有效——本階段完成一次局部目標，新的證據讓下一行動問題升級；拖延——在答案說出口前切黑，下一集只是補完同一句話。有效——人物已經做出選擇，觀眾等待選擇造成的後果；拖延——人物正準備選擇，連續多集不作答。

## 2.18 系列容量診斷

`SERIES_CAPACITY_REPORT.md` 不從平台常見集數反推故事，而從來源的有效戲劇負荷估算。

**統計單位**：`EVENT_LOAD`（具有目標、反制、代價和狀態變化的主事件）、`ARC_LOAD`（需要獨立入口、升級、高潮和回收的大弧）、`RULE_LOAD`（必須通過行動建立的世界規則）、`RELATIONSHIP_LOAD`（建立、斷裂、修復和回收節點）、`IP_LOAD`（核心角色錯誤信念被考驗及記憶錨點變體）、`SETUP_PAYOFF_LOAD`（不能刪除的伏筆、承諾、證據與回收）、`EXPOSITION_LOAD`（必須理解但可以視覺化或壓縮的信息）。

**事件可壓縮性**：每項標為 `ATOMIC`（不能與其他事件合併，否則失去選擇或後果）、`COMBINABLE`（與相鄰事件目標、地點和阻力相容，可同集完成）、`MONTAGEABLE`（重複過程可壓縮，但必須保留首建和最終變化）、`CALLBACK_ONLY`（後續只需承接或回看，不重複計為主事件）。

**情感與規則佔用**：高信息事件不一定能獨佔一集，但關鍵關係選擇、世界規則首建和不可逆損失需要建立與反應時間。容量估算必須包含：觀眾理解前提的時間、人物行動與對手反制的時間、策略改變的時間、情感或後果被看見的時間、鉤子停頓和下一集承接的空間。只按章節數、字數或打鬥次數估算會產生碎片化分集。

## 2.19 集數區間與時長

**時長合同**：允許單集 60—180 秒；默認估算約 90 秒；最終時長服從完整故事單元和真實鉤子位置，不機械湊到 90 秒；同一地點、時間、目標和策略不能只因超過 90 秒被從中間切斷；若完整局部兌現需要 110 秒，應優先保留完整性；若一個完整事件只需 75 秒，不用填充重複對白。

**集數報告**固定輸出：

```yaml
duration_min_seconds: 60
duration_default_seconds: 90
duration_max_seconds: 180
episode_range_min: 具體整數
episode_range_max: 具體整數
recommended_episode_count: 區間內建議值
exact_count_locked: false
basis: "事件、關係、規則、伏筆和鉤子負荷依據"
flexibility_rule: "完整故事單元與有效鉤子優先"
```

階段③只給範圍和推薦值。階段④結合用戶目標、事件覆蓋和真實斷點鎖定精確集數。若用戶預設集數明顯小於最低容量，報告必須刪除或合併的內容、會失去的因果人物弧或回收、可行的短版範圍、不可接受的魔改風險。若預設集數明顯大於最高容量，報告可擴展的關係與規則行動，禁止用重複爭吵、圍觀震驚、誤會和空鉤子注水。

## 2.20 向分集階段交接

## 2.21 失敗模式與架構審計

**失敗模式**：按原著章節一章一集，忽略事件負荷；只寫宏觀概括，沒有穩定事件 ID 和來源範圍；把「核心梗」寫成題材標籤；價值觀只有口號，沒有對立觀點、選擇和代價；人物小傳重複外貌性格，沒有全劇行動功能；世界規則只有能力，沒有限制、代價和失敗後果；為了強鉤子提前洩露來源依賴的核心謎底；把一句未說完的話當成鉤子候選；用 `INFERENCE` 新增血緣、證據、能力來源或結局；精確鎖死集數，逼階段④機械切碎連續場景；用統一「打臉、震驚、身份揭露」模板覆蓋所有題材。

**架構審計**逐弧回答：主角主動做了什麼？對手為什麼能造成有效阻力？哪個信息改變了策略？哪個關係選擇讓勝負有情感意義？付出了什麼不能立即抹平的代價？種下的道具、身份或承諾在哪裡回收？下一弧繼承的是新局面還是同一爭吵？重要賭注是否先建立後調用並至少產生一次真實後果？核心情感是否改變人物策略，而非只靠道具觸摸和台詞說明？每項壓力的開始時間、觸發條件、對象和後果強度是否與來源一致？

存在無來源重大反轉、前置條件缺失、狀態互相沖突或三條以上長期伏筆無計劃回收時，不得通過階段③。

## 2.22 階段③自檢與鎖定

逐項檢查：全源覆蓋、原始創意 DNA、類型受眾合同、四層梗概一致、世界規則可行動、價值衝突由選擇證明、因果完整、人物弧消費鎖定 IP、信息邊界、伏筆回收、改編忠實、重排安全、鉤子有來源與兌現、容量有事件依據、階段④可直接消費。

十五項 `STORY_QUALITY_GATES`（全源覆蓋、創意DNA、受眾合同、梗概一致、規則可行動、價值由選擇證明、因果完整、IP弧消費、信息邊界、伏筆回收、改編忠實、重排安全、鉤子來源與兌現、容量依據、下游可消費）全為 `PASS`、`failure_flags` 為空、推薦集數位於區間內、`exact_count_locked` 為 `false`、每個鉤子候選擁有來源事件與兌現事件，才能鎖定階段③。

只有設定沒有行動後果、只有人物形容詞沒有選擇、只有反轉沒有前置證據、用集數慣例代替容量診斷、或重排破壞因果和知識邊界時必須返修。

完成標準——階段③通過前必須能夠：用一句話和完整梗概講清同一個故事，不互相矛盾；從任何重大結論追溯到 `EVT` 或來源範圍；從任何人物弧追溯到選擇、阻力、代價與狀態變化；從任何世界規則追溯到限制、代價和實際影響的事件；從任何主題結論追溯到對立價值和人物選擇；從任何鉤子候選追溯到來源事件與兌現事件；解釋建議集數區間來自哪些事件負荷，而非行業慣例；清楚區分來源事實、結構推斷、連接補足、用戶授權和開放問題；讓階段④在不重新發明故事的情況下完成全劇分集。
