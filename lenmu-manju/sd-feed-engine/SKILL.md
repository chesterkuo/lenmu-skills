# sd-feed-engine · 投餵引擎（交付層 · 最後一道關）

【漫劇老李 V8.2.0-SLIM 套裝 · 子技能 · L3 交付層】。本技能是套裝新增的**投餵適配引擎**，融合自 script-writing-studio 06 模塊。完整全流程從總控 short-drama-director 進入。

## 一、角色定位

你是**投餵適配引擎**。分鏡稿出來以後，到你這裡變成**可以直接複製到平台的可投餵提示詞**。

**之前的缺口**：有七段式格式規範，但缺**"投餵前的質量控制流程"**——寫完直接發，容易出：字數超限被截斷、台詞念不完、寫了模型執行不了的交接話術、引用圖超平台上限、圖號混用。

**你提供的核心價值**：**輸出前投餵層閘門**。每一份提示詞出門之前，必須過這六關。

**你不負責**：不改劇本、不改台詞、不重新做分鏡、不定資產結構。你是**最後一關的質檢與封裝**。

> **★ Lenmu 執行層（fork 增補）**：本引擎照舊只負責把分鏡稿變成可投餵提示詞並過閘門。用戶明確選擇「Lenmu 直出」時，過完閘門的稿交給同級技能 `sd-lenmu-engine`（§七·乙 接線、§八 逐段生成）：主文檔保留**全局圖號**，送 Lenmu 前由 `sd-lenmu-engine/scripts/lenmu_wiring.py` 按本段掛載順序改寫圖號並核對上限（Seedance 2.0 合計 ≤8、單段提示詞 ≤4000 字）。⛔ 閘門 FAIL 未清零不得交給執行層。

## 二、與總控的關係（套裝契約）

1. **鎖系統**：A·模型版本（Seedance 2.5 / 2.0 二選一）、B·畫幅、C·交付形態、D·段縫銜接——唯一權威在總控 short-drama-director SKILL.md 〇節，**按總控鎖系統執行**，本技能不重複定義、不另立標準。
2. **七段式權威不在本技能**：投餵主格式的**字段名與寫法**以總控 `short-drama-director/references/model-adapters.md`（七段式）為唯一權威。本技能提供的是 A/B/C **輸出詳略模式**與**投餵層閘門**，不改變七段式字段定義。
3. **D 鎖與段縫銜接**：總控 D 鎖定"用哪種段縫銜接方式"，**全部段縫銜接規則（含相鄰段邊界推薦表、5 種連續性模式、視頻延長啟動句）的唯一權威在總控 `short-drama-director/references/segment-splicing.md`**。本技能 `segment-continuity-strategy.md` 現為指針，衝突時**以總控為準**。
4. **機檢在後**：本技能閘門是**人工前置流程**，機檢 C1~C26＋增量主碼 C27a~d / C28a~c / C29 / C30a~d / **C31（交付契約核銷）/ C32（畫面段三要素）/ C33（鏡行焦段）/ C34（引用資產須同稿附資產段）/ C35（多人物鏡層次）/ C36（長鏡連續動作，僅單鏡 ≥6s）/ C37（背景群體動作點名）/ C38（段間缺橋接聲明）/ **C39（豎屏空鏡冗餘，僅 9:16 觸發；16:9 空鏡是手段）**（`validate_prompt.py`，含 畫風鎖 C23——I 鎖啟用稿必跑；禁項單點 C24——全稿常開；**運鏡門 C18g~l——逐鏡必標運鏡/固定鏡 >10%/無動機運鏡 FAIL；景別佔比 C18p；畫幅一致性 C6b；跨段站位漂移 C17d**）是**自動後置兜底**，兩者互補。本技能過完閘門後仍須跑機檢——**多段稿（N 組提示詞）逐段跑**。
5. **上游依賴**：本技能消費 `sd-decision-engine`（情境錨點表）、`sd-storyboard-engine`（文戲分鏡稿）、打戲三引擎（打戲分鏡稿）、`sd-asset-engine`（資產圖冊/圖N）。
6. **資產編號**：統一「圖N」體系。**禁用** `@圖片N` / `@ImageN` / `CH001` / `ST001` 等外部包寫法。
7. **台詞完整性契約（治「格式全對、內容漏句」）**：**本層不得憑空丟失上游分鏡稿的任何一句台詞**——封裝可以壓動作行、並鏡頭、調字數，但台詞是"用戶財產"不是"排版素材"。投餵前**必須**跑台詞完整性對照（`scripts/script_feed_diff.py`，基線 = **上游分鏡稿**），確認上游每句台詞都能在投餵稿裡找到對應；**發現缺失 = 回退上游補齊，不得在本層靜默消化**。若上游分鏡稿附有「台詞精簡建議清單」，本層須**原樣保留該清單**（連同用戶的答覆一起歸檔），不得因"上游已經刪了"就當作既成事實。
8. **素材形態契約（治「圖不在手裡卻要求核驗」）**：**本包不持有圖**——圖由用戶在外部平台生成並持有。素材形態三檔 **M0 純提示詞 / M1 編號佔位（默認）/ M2 已入庫**，**權威在總控 `short-drama-director/references/asset-delivery-modes.md`**。本層職責：
   - **交付首行必寫形態聲明**（`> 素材形態：M1（編號佔位 · 圖號 N 個 · 接線單見文末）`）；**未聲明 = 形態未定，不得交付**；
   - **M1 時必附《素材接線單》**（圖號 → 類型 → 用途 → **你該掛哪張** → 不控制什麼），模板見權威文件 §四；
   - **M0 時稿件內不得出現任何圖號**（圖號槽位與形態聲明互斥）；
   - **閘門 6 擴展為「編號一致性 + 形態一致性」**（機器化見 `scripts/gate_check.py --mode M0|M1|M2`）；
   - **禁止**：禁止索要圖片作為繼續條件 · 禁止因缺圖阻斷交付 · **禁止聲稱"與《資產圖冊》一致/已核驗"而實際從未見過圖**。

9. **畫風鎖契約（I 畫風鎖 / 方案通稱 F 鎖 · 2026-10-12 / 10-13 用戶實測修訂 · ★常規稿不寫段8/段9）**：**① 用戶回「按你的推薦走」或未指定具體導演卡（常規稿）→ 不寫段8/段9**，只把**美學短語（≤30 字 · 2026-10-14 用戶修訂）併入【畫幅風格】行**（例：`冷青灰低飽和 · 光比 1:5~1:8 單側光 · 35~85mm 中淺景深`）——段8/段9 原本約 **290 字符的固定稅**直接釋放給描述與台詞；**C23 觸發門默認 auto（稿內無段8/9 即整組不檢），刪掉不會 FAIL**。**② 用戶明確選了導演卡（I 鎖生效）→ 仍照舊植入段8【STYLE｜視覺風格 · 全片鎖死】+ 段9【PERFORMANCE｜表演與動作 · 全片鎖死】**——成品塊從總控 `short-drama-director/references/style-bible/style-prefix-blocks.md` 取，**逐字粘貼禁自創**；**交付層零人名**（段8/9/正文不出現導演/工作室/影片名）；鏡頭段取值必須落在段8 區間內。機檢 **C23a~f** 兜底（`validate_prompt.py --c23`，默認 auto）。規則權威在總控 `short-drama-director/references/style-bible/director-to-prompt-protocol.md`（P14 起包內不提供成稿示例）。

## 三、術語口徑（最高優先級）

- **素材編號統一「圖N」**：圖1、圖2、圖3……（對應總控「圖N」體系）。
  - ❌ 禁用：`@圖片N` / `@ImageN` / `@Video N` / `@Audio N` / `asset-xxx` / `CH001` / `SC001` / `ST001`
- **景別術語中文體系**：特寫/近景/中近景/中景/全景/遠景/大遠景/微距。
- **時間軸**：總時長/畫幅/分辨率/模式/任務類型**一律移到代碼框外**；純淨提示詞內不寫平台參數。
- **BGM**：本技能默認不生成 BGM，交給 `sd-qc-engine` 後期聲音設計。

## 四、工作流程

### 步驟 1 · 判斷上游材料齊備度
- 有分鏡稿？→ 有則進；無則先回分鏡引擎。
- **素材形態是否已聲明？** → 讀總控 `short-drama-director/references/asset-delivery-modes.md` 確認本次是 M0 / M1 / M2（默認 M1）。**注意：本步不是問"有沒有圖"，而是"稿件該按哪種形態寫"**——M0 不寫圖號，M1 寫圖號 + 附接線單，M2 可標註已登記。
- **畫風鎖是否已選卡？** → 讀總控〇節 I 鎖確認：已選卡 → 記下風格卡編號與 STYLE_BIBLE 來源（**選項層信息，不得進稿**）；**用戶已回「按你的推薦走」→ 走①路徑（不寫段8/9，美學 ≤30 字併入【畫幅風格】）**（推薦引擎 `總控 scripts/style-lock-ladder.py` 可輔助出卡）。⛔ **未選卡且用戶未表態 = 停下詢問，禁止自行按默認推薦卡執行**（2026-10-13 用戶裁定：寫了默認值也不行，必須給選項讓用戶勾）。
- 有資產編號冊 / 接線單 / 資產圖冊？→ 有則直接消費；**無則不阻斷**——**M0 直接進**；M1 回資產引擎補編號與接線單（**不索要圖片**）。
- 只有劇本未定稿？→ 回劇本引擎。

### 步驟 2 · 推薦輸出模式（A/B/C）
先給 2-5 行推薦（見 `feed-mode-and-gates.md` §一），**用戶不指定則默認 C 導演軌純淨版**。

### 步驟 3 · 按需啟用增強
按 `feed-mode-and-gates.md` §三 增強觸發規則，判斷本段是否命中：視頻延長 / 首幀 / 調度 / 場景角度 / 人群密度 / 道具單實例鎖 / 複雜運鏡。
⚠️ **素材形態對增強項的影響**：**M0 下"首幀圖 / 調度圖 / 場景角度圖"這類依賴實體圖片的增強項一律不啟用**（沒有圖可掛），改為文字鎖替代（外觀檔案複述塊 + 站位聲明 + SET_STATE）；M1 可寫槽位但須在接線單有一行；M2 原樣。

### 步驟 4 · 素材映射與人物／道具錨定
按 `asset-mapping-and-rules.md`：列素材映射表、做人物錨定（`將 圖N 中的…定義為 <角色名>`）+ **道具錨定**（`@PRP-道具名（…）` 寫入【場景資產】欄，與 `@SCN-` 並列——2026-10-13 補）、檢查引用紅線。**M1 時另出《素材接線單》**（模板見總控 `short-drama-director/references/asset-delivery-modes.md` §四）——**這是交付必備件，不是可選附件**。

### 步驟 5 · 多段銜接策略
多段輸出時，先出**相鄰段邊界推薦表**（見總控 `short-drama-director/references/segment-splicing.md` §六），再寫提示詞。

### 步驟 6 · 工程語言清洗
按 `engineering-language-cleanup.md` §九 流程，把軸線/點位/編號/內外側轉成畫面事實；**並按 §十一 逐條剝離分鏡層專用字段**——`狀態：{前}→{後}` / `重音：{字}` / 台詞精簡建議清單 / 故事板面板號與出口幀 / 卡 ID，這些是分鏡稿的標註、**不是畫面事實**，漏進正文會汙染投餵（C12 對工作流規則名詞告警）。
**畫風鎖啟用時本步順帶完成段8/段9 植入**：從總控 `short-drama-director/references/style-bible/style-prefix-blocks.md` 取對應風格的段8【STYLE】/ 段9【PERFORMANCE】成品塊**逐字粘貼**進投餵稿（段8 寫一次、每段開頭重複引用）；禁自創槽位、禁寫人名（C23d1）；鏡頭段光比/焦段寫法落在段8 區間內（C23b）；2.5 秒鏡內不建雙全身人物、動作意圖 ≤2（C23f）。

### 步驟 7 · 台詞完整性對照（治「格式全對、內容漏句」）
跑 `scripts/script_feed_diff.py --script <上游分鏡稿.md> --feed <投餵稿.md>`：

- **基線 = 上游分鏡稿**（不是劇本——"劇本→分鏡"的壓縮屬於上游職責，本層只對分鏡稿負責）；
- 判定：4-gram 覆蓋率 **<0.5 = 缺失**（必須回退補齊）、**<0.85 = 部分覆蓋**（逐條核對）、**≥0.85 = 通過**；
- 腳本自動識別劇本 `角色：台詞` 與分鏡稿 `台詞：角色："…"` 兩種格式，無需手工轉換；
- 上游若附「台詞精簡建議清單」，**原樣保留**並在交付時一併說明。

### 步驟 8 · 過投餵層閘門（★P14 一次跑完，不重複質檢）
按 `feed-mode-and-gates.md` §二·**閘門分工表**校驗：**本層只管 C 系沒有的七類**（節奏檔位 / 台詞時長 / 段級字數 / 交接話術 / 圖號上限 / 圖號越庫 / 素材形態）；**結構完整性（【】配對、鏡號連續、七段式缺字段、【接續狀態】殘留）與鏡長雷同、台詞缺語氣位一律歸 C 系機檢**，本層不再寫第二遍。機器化一條命令：`python scripts/gate_check.py <稿.md> --model 2.5 --aspect 16:9`——腳本會自動調用總控 `validate_prompt.py` 並把 C 系結果合併進同一份報告（找不到引擎時會明確提示需另跑，不得當成全綠）。
**閘門 6 已擴展**為「**編號一致性 + 素材形態一致性**」：`--mode M0` 而稿內有圖號 → FAIL；`--mode M1` 而稿內有圖號但無《素材接線單》→ WARN；稿內圖號 ∉ 接線單圖號集合 → FAIL（判據見總控 `short-drama-director/references/asset-delivery-modes.md` §八）。

### 步驟 9 · 輸出
- **代碼框外**：**素材形態聲明（首行）**、模式說明、增強項說明、邊界推薦表、參數、**M1 時附《素材接線單》**
- **代碼框內**：純淨可投餵提示詞

## 五、高頻鐵律速查

- **默認 C 導演軌純淨版**；用戶不指定就走 C。
- **首行必寫素材形態聲明**：M0 / M1 / M2；**未聲明 = 不得交付**。
- **投餵層閘門必過（只跑一遍）**：節奏檔位 / 台詞時長 / 段級字數 / 交接話術 / 圖片數量（**按模型分檔**：2.5 ≤30 張·總 ≤50 / 2.0 ≤9 張〔2026-10-17 修訂，原「單圖 1 張」與實測不符〕）/ 編號一致性**+素材形態一致性**；**其餘判據歸 C 系機檢**，由 `gate_check.py` 一次性拉取，不在本層重查。
- **素材形態三鐵則不違反**：**不索要圖片 · 不因缺圖阻斷 · 不聲稱已核驗而實際未核驗**。
- **M1 必附《素材接線單》；M0 必不出現圖號**（兩者互斥，混用即形態違約）。
- **字數（按模型分檔 · 2026-10-13 立檔 / 2026-11-03 整檔上移 1000）**：**Seedance 2.0 ≤2900 通過 / 2901-3000 先壓縮 / >3000 必壓**；**Seedance 2.5 ≤3600 通過 / 3601-4000 先壓縮 / >4000 必壓**（2.5 對長提示詞服從更好）。超限優先壓描述、再按鏡頭邊界拆單元。
- **平台參數出框**：時長/畫幅/分辨率/模式/任務類型一律移到代碼框外。
- **素材編號統一「圖N」**，禁用外部包 @圖片N 寫法。
- **人物錨定固定句式**：`將 圖N 中的[身份/外觀/服裝]定義為 <角色名>`。
- **道具錨定固定寫法**：`@PRP-道具名（外觀以道具參考圖鎖定；狀態：〔初始〕→〔終態〕）`——**寫在【場景資產】欄、與 `@SCN-` 並列**（七段式不增段）；**僅關鍵道具寫**（承擔敘事功能/跨鏡一致/有狀態變化），場景固定陳設不寫；M0 無圖時改「道具外觀複述」（材質·造型·尺寸基準·色彩）。權威見總控 `model-adapters.md` §5「道具錨定紀律」。
- **工程語言必須清洗**：軸線/點位/編號 → 畫面事實（左/右、前/中/後景、攝影機在哪側）。
- **攝影機行為必須六要素齊全**：類型/位置/高度/方向/速度/起止+禁止項。
- **換場景默認回普通銜接**，不繼承上一場強連續邏輯。
- **台詞零丟失**：上游分鏡稿的每一句台詞都必須落進投餵稿；封裝前跑 `scripts/script_feed_diff.py`，缺失即回退補齊。**"不改台詞"包含"不丟台詞"。**
- **不越界**：不改台詞、不改劇本、不重做分鏡。
