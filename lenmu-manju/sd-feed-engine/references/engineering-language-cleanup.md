# 工程語言清洗規則（Engineering-to-Visual Translation）

> **本文檔是交付層核心規則庫 · 權威文件**
> 融合來源：script-writing-studio 06-core-format 適配原則 21/22/23/24（工程語言轉畫面語言）
> 定位：分鏡稿裡的"給人看的工程語言" → 投餵稿裡的"給模型看的畫面語言"。

---

## 〇、為什麼需要清洗

分鏡稿裡可以有軸線、錨點、點位表、調度編號——**這些是給人看的**。但 AI 視頻模型**不理解**這些內部術語。如果不清洗，模型看到"180度軸線""A2點位""參考MAP001"只會一臉茫然，甚至生成錯誤畫面。

**本文件職責**：把工程語言逐條翻譯成模型能識別的**畫面事實**。

---

## 一、工程語言 → 畫面語言 對照表

| ❌ 工程語言（給人看） | ✅ 畫面語言（給模型看） |
|---|---|
| 180度軸線 / 不要越軸 | 攝影機始終在兩人連線的同一側；<br>角色A 在畫面左側、角色B 在畫面右側 |
| A2 點位 / B1 站位 | 角色A 站在窗邊、角色B 站在門口（**用具體空間描述**） |
| 參考 MAP001 | 人物站位如 圖7 所示：角色A 在左前、角色B 在右後（**用圖號+空間描述**） |
| 以沙盤為錨點 | 角色A 站在沙盤左側一步遠的位置 |
| 窗內外 / 櫃檯內外 / 車內外 | 角色A 位於窗內，角色B 位於窗外；或"隔著櫃檯相望" |
| 內外側 / 側別鎖定 | 攝影機在走廊右側拍攝，角色面向畫面左方 |
| 攝影機安全區 | 攝影機保持在角色行進路線的右前方，不穿越兩人之間 |
| 前景 / 中景 / 遠景層 | 畫面前景是茶杯（虛化），中景是角色A，遠景是窗戶 |
| 移動方向 | 角色A 向畫面右側移動 / 朝攝影機方向走來 |

## 二、攝影機行為鎖 — 必須寫成可執行句

❌ **不能只寫**："固定 / 手持 / 跟拍 / 退拍"

✅ **必須寫清六要素**：
```
① 攝影機類型（手持/穩定器/固定三腳架/滑軌/搖臂）
② 位置（在哪、距主體多遠）
③ 高度（與人物視線平齊/略高/俯視/仰視）
④ 運動方向（推/拉/搖/移/環繞，朝哪個方向）
⑤ 穩定程度與速度（緩慢/勻速/急促）
⑥ 起止狀態 + 禁止項
```

## 三、風格 / 色彩 / 負面詞 — 禁止直接複製編號

❌ **禁止**：只寫 `ST001 / CL001 / NP001 / 繼承 ST`

✅ **必須翻譯成自然語言**：
```
項目風格：<具體描述——媒介質感、人物審美、場景審美、畫面質感>
當前鏡頭光影：<光源來源、主光方向、亮區、暗區、色溫、明暗反差>
風格禁止項：<具體說明禁止什麼——如"不要塑料感皮膚""不要萬能霧"">
```

**規則**：風格/色彩/負面詞包可以出現在**代碼框外的投餵信息或素材管理說明**裡用編號；但**代碼框內的最終提示詞必須翻譯成自然語言**。

## 四、風格光影衝突時的融合規則

**如果風格包/色彩包的默認光影與當前分鏡的真實光源、劇情時段或角色位置衝突**：

```
✅ 以當前鏡頭的真實光源和劇情時段為準
✅ 同時保留項目風格的媒介質感、明暗反差、顆粒/渲染方式、人物審美和禁止項
❌ 不要在同一提示詞裡同時寫兩套互相打架的光影系統
```

## 五、光影字段必須可見可執行

❌ **不能只寫**："電影級布光 / 高級光影 / 氛圍感"

✅ **必須寫清**：光源來源、主光方向、亮區、暗區、臉部受光、輪廓光或背景分離、色溫、明暗反差

**如果寫丁達爾光效**，必須寫**光束來源、介質和落點**。

---

## 六、情緒表演必須拆成微動作

❌ **不能只寫**："悲傷 / 憤怒 / 害怕 / 心動"

✅ **必須寫眼神、眨眼、嘴部、呼吸、肩頸、手部或身體重心的可見變化**

**限制字段必須寫清禁止過度表演**：
```
不要假哭、不要誇張皺眉、不要咆哮、不要突然失控
（除非劇情明確爆發）
```

## 七、人群 / 道具 / 場景角度 — 三個易錯點

### 人群密度

❌ **不能只寫**："CR001 / 同上一段人群 / 保持之前人流"

✅ **直接寫清**：本段可見的**人數、層次、類型、移動方向、遮擋規則**

⚠️ 場景母版如果是空場圖，**只作為空間結構/燈光/透視/固定物參考**；啟用人群時直接寫本段可見人群，**不寫"不繼承空無一人狀態"這類管理說明**。
⚠️ 無路人需求時，**不新增人群密度字段**，只在限制裡寫"不允許出現額外人物、路人、群演"。

### 道具單實例鎖

❌ **不能寫**："添加一個道具"

✅ **必須寫**："圖4 只作為已存在那一件道具的外觀參考，**不新增第二個實例**"

必須包含：**數量限制、綁定位置、移動後原位置變化、禁止複製項**——避免桌上一個、手裡一個、背景又一個。

### 場景角度圖

❌ **不能只寫**："SCV001 / 使用角度圖"

✅ **必須寫**："本段使用 圖5（V02 角度），只參考**拍攝方向、空間透視、門窗/傢俱相對位置和固定光源**"

⚠️ 不得讓角度圖替代場景母版、調度圖或首幀圖。

## 八·補、畫面內文字與系統面板規則（2026-10-10 併入）

**默認：不生成文字。** 普通背景字、招牌字、無來源的界面文字一律**不可讀**——可轉寫為模糊符號、文字狀光痕、發光紋路、光點排列或不可辨識的書寫痕跡。

**唯一例外 · 系統面板。** 當原文**明確提供**系統面板 / 界面字段、數值、等級、增益或懲罰時，它是**劇情依賴的 in-world 界面元素，不是字幕**——必須在本段畫面內以**面板、界面光層或懸浮信息框**完整、逐項、可讀地呈現，**不得省略、改寫、模糊化或補造**。

| 項 | 處理 |
|---|---|
| 有來源的系統面板 | **必須可讀**：寫清面板位置與層級，數值 / 等級 / 名稱**逐項列全** |
| 無來源的背景文字 / 招牌 / 說明字 | **不可讀化**：模糊符號 / 文字狀光痕 / 光點排列 |
| 字體細節 | 只呈現**原文提供**的字段，**不得**替原文補造面板數據（與角色 / 道具 / 台詞同源保真） |

- 與"不製作字幕"的約束**不衝突**：字幕約束針對**無來源**的台詞/說明文字；有來源的系統面板不受此約束。
- 系統面板**必須可讀**，與"背景文字不可讀化"是兩條相反的處理——**不得把面板當字幕糊掉，也不得把無來源文字當面板寫清**。

**自檢**：(1) 本段是否有原文提供的系統面板？有 → 是否逐項完整可讀？(2) 無來源的背景文字是否已做不可讀化處理？(3) 有沒有把面板當字幕糊掉、或把無來源文字當面板寫清？

## 九、清洗流程圖

```
分鏡稿（含工程語言）
        ↓
① 掃軸線/點位/編號/內外側 → 逐條轉畫面事實
② 掃攝影機描述 → 補全六要素
③ 掃風格/色彩/負面詞編號 → 翻譯成自然語言
④ 掃光影字段 → 補來源/方向/色溫/反差
⑤ 掃表演描述 → 拆成可見微動作
⑥ 掃人群/道具/角度圖 → 按 §七 三易錯點改寫
⑦ 掃符號 → 按 §八 規範
⑧ 掃分鏡層專用字段（狀態/重音/清單/面板號/卡ID） → 按 §十一 剝離
        ↓
可投餵提示詞（純畫面語言）
```

## 十一、分鏡層專用字段 —— 投餵前必剝離（2026-10-11 併入）

分鏡稿裡有幾樣東西是**給作者、給機檢、給團隊看的**，模型讀不懂、也不該讀。它們**必須停在分鏡稿層**，封裝投餵時逐條剝除：

| 字段 / 產物 | 為什麼不能進投餵 | 剝離後由誰承擔 |
|---|---|---|
| `狀態：{前}→{後}`（`sd-storyboard-engine` 單鏡頭模板） | 描述的是**鏡與鏡之間的關係**，不是本鏡的畫面事實——同類工作流標註（C12 對工作流規則名詞告警） | 本鏡「畫面內容」裡寫清人物的姿態與持物 |
| `重音：{字}`（同上） | 是**設計標註**，模型的配音不吃這個記號 | 落進發聲描述（"『修』字重讀"）＋畫面內容裡的表演描寫 |
| **台詞精簡建議清單**（分鏡稿文末） | 是**與用戶的對話**，不是提示詞內容 | 剝離後再封裝；精簡與否由用戶裁定（`sd-storyboard-engine` §二·8） |
| **故事板面板號 / 出口幀六項** | 執行稿標註，面板號是給人看的 | 逐格落進鏡行後剝離；出口幀只作段縫畫面鎖依據 |
| **機長時碼 / 卡 ID**（SHOT_TEXT） | 時碼已有【時間軸分鏡】承載 | 時碼進鏡行；卡 ID 不進投餵 |
| **神態-動作供給庫 / 錨點表 / 節拍表** | 創作腳手架，不是畫面 | 只把**結果**（具體神態與動作）寫進畫面內容 |

**一句話判據**：**凡是"描述鏡頭之間關係"或"給創作者看的標註"，一律不是畫面事實**——要麼按 §一 對照表轉成"畫面裡看得見、聽得見的東西"，要麼直接刪。

**自檢**：投餵正文裡搜一遍 `狀態：` `重音：` `面板` `出口幀` `卡 ID`——命中即剝離。
