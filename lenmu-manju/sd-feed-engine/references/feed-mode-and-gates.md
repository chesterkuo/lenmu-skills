# 投餵輸出模式與投餵層閘門（Feed Mode & Gates）

> **本文檔是交付層核心規則庫 · 權威文件**
> 融合來源：script-writing-studio 06-core-format 第六節（A/B/C 輸出模式 + 輸出前投餵層閘門）
> 定位：分鏡稿 → 可投餵提示詞的**最後一關**。

---

## 〇、定位與邊界

**解決什麼問題**：有七段式格式規範，但缺**"投餵前的質量控制流程"**——寫完提示詞直接發，容易出現：字數超限、台詞念不完、寫了模型執行不了的交接話術、引用圖超過平台上限、圖號混用。

**本文件提供**：A/B/C 輸出模式選擇 + 輸出前**投餵層閘門**逐項校驗。

**邊界**：本文件不定義七段式字段寫法（那是總控 `short-drama-director/references/model-adapters.md` 的權威）；本文件只負責**"輸出模式怎麼選"**與**"發出去之前必須過哪幾道關"**。

---

## 一、A/B/C 三種輸出模式

每次用戶要求生成 Seedance 提示詞包時，先用 2-5 行**推薦輸出模式**，並允許用戶指定 A/B/C。**用戶不指定時，默認使用 C 導演軌純淨版。**

### 模式對照表

| 模式 | 全稱 | 適用場景 | 默認傾向 |
|---|---|---|---|
| **A** | 標準字段化詳細版 | 完整展開字段，適合 1-3 鏡頭高精度控制、鏡頭審查、教學拆解、用戶明確要求完整字段 | 按需使用 |
| **B** | 導演執行增強版 | 一鏡到底、強運鏡、人群、動作戲、遮擋轉場、強聲音敘事、複雜表演 | 命中高難鏡頭時推薦 |
| **C** | 導演軌純淨版 | **默認成品格式**，適合 4-7 鏡頭直接投餵，保留硬鎖並控制字數 | ⭐ 默認優先 |

### 用戶可見模式提示（模板）

```
本段可以用三種輸出模式：
A 標準字段化詳細版：完整展開字段，適合 1-3 鏡頭高精度控制、鏡頭審查或用戶明確要求完整字段。
B 導演執行增強版：適合一鏡到底、強運鏡、人群、動作戲、遮擋轉場、強聲音敘事和複雜表演。
C 導演軌純淨版：默認成品格式，適合 4-7 鏡頭直接投餵，保留硬鎖並控制字數；命中高密度動作或強鉤子時可容納 8-10 個短鏡頭，但必須過閘門。
我建議本段使用：____，原因：____。如果你不指定，我會按推薦模式繼續。
```

### 輸出原則（三種模式共通）

1. **信息底座不變**：無論 A/B/C，都必須保留素材、場景、人物位置、焦點、攝影機、動作、台詞、光影、限制、銜接和段末狀態。C 用導演軌合併表達；A 才展開完整字段；B 在 C/A 基礎上疊加增強。
2. **增強按需啟用**：視頻延長、首幀、調度圖、場景角度、人群密度、道具單實例鎖、複雜運鏡增強——只在命中條件時加入，普通段落不默認全壓。
3. **用戶可見但不囉嗦**：代碼框外簡短說明推薦模式和命中的增強項。
4. **字數紅線（★ 2026-10-13 按模型分檔 · 2026-11-03 整檔上移 1000）**：單個可投餵單元 **Seedance 2.0 默認 ≤2900 字、3000 硬上限；Seedance 2.5 ≤3600 字、4000 硬上限**（2.5 對長提示詞服從更好；兩檔軟硬間距保持原設計——2.0 差 100、2.5 差 400）。細則見下方閘門 3。
   > ⚠️ **別把兩個閾值混成一個（口徑統一）**：本閘門是**段級**——逐投餵單元計（2.0：≤2900 通過 / 2901–3000 先壓一輪 / >3000 必壓；2.5：≤3600 / 3601–4000 / >4000），由 `sd-feed-engine/scripts/gate_check.py`「閘門3」判；機檢 `validate_prompt.py` 的 **C4** 是**篇級兜底**——單個投餵稿文件 ≤6000 字符（按整份文件的字符數計，含標點與格式符），判據全集見 `sd-qc-engine/references/machine-check-manual.md`。
   > 一個文件 = 一個投餵單元時，兩者是「**自律線按模型分檔**（保念得完、渲染穩）／**兜底線 6000 字符**（防單文件過大被截斷）」的關係，**不衝突**；把多個單元合成一個文件時會超 6000，此時**以本閘門的段級判定為準**。
5. **強度保護**：不得為壓字數刪除素材用途、人物錨定、場景位置關係、景深焦點鎖、攝影機行為鎖、台詞語氣、可執行光影、段末狀態。
6. **重複去除**：全局約束（人物錨點/字幕水印/全局風格/光線連續性）只集中寫一次，不在多處反覆展開。

## 二、★ 輸出前閘門（核心）

每個投餵單元輸出前**必須先過閘門**。**P14 起判據級去重：一條判據只留一處實現，出稿只跑一次質檢。**

**執行口徑**：`python gate_check.py <稿.md> --model 2.5 --aspect 16:9` **一條命令跑完全部**——
投餵層閘門自查 + 自動調用總控 `validate_prompt.py` 拿 C 系結果，合併成一份報告。
⛔ 不再需要"先跑閘門、再跑機檢、最後跑契約核銷"三遍（同一個語氣位/鏡長問題被查三次的時代結束了）。
單獨安裝 `sd-feed-engine` 時找不到機檢引擎，腳本會明確提示"本次只跑了投餵層閘門"，此時必須另跑機檢——不得當成全綠。

### 閘門 1 · 節奏檔位閘門

**目的**：防拖沓，不是強行切碎鏡頭。

```
檢查項：
① 先繼承或補判節奏檔位：
  電影感中速 / 短視頻中高密度 / 高密度動作或強鉤子 / 慢節奏但高信息
② 按建議時長檢查鏡頭密度
③ 10 秒以上只有 1-2 鏡時 → 判斷是否命中慢節奏白名單
   · 命中 → 保留原節奏並寫清慢鏡頭功能
   · 未命中 → 補動作標點/道具信息/反應/空間關係/段末鉤子鏡頭
```

### 閘門 2 · 台詞時長閘門

**目的**：防"台詞念不完"。**注**：本閘門只管時長；「台詞缺語氣位」由機檢 **C16b** 負責，不在此重複檢查。

> 📐 **畫幅分檔（P6.4 · 2026-10-23）**：**16:9 橫屏半精品**按標準對白 **3.5~5 字/秒** 寫，句間留 0.5~1s 停頓做情緒落點；**9:16 豎屏快節奏**按快念 **5~7 字/秒** 寫，幾乎不停頓（停頓只在"憋住/被打斷"時出現）。**分檔的是寫稿語速，不是判據**——"念不念得完"仍按最快檔 7 字/秒 判，判據不因畫幅變成兩套。檔位定義見 `short-drama-director/references/blooper-prevention-playbook.md` §十·10.0（畫幅-劇型分檔）。

> ⚠️ **（2026-10-08）**：真人快念 **5.5~7 字/秒** 完全做得到（短劇常態即在此區間）。**判定"念不念得完"必須用最快檔 7 字/秒**，不得拿 4~4.5 字/秒 的中值硬卡——後者會把大量能快唸完的台詞誤判成"念不完"，是本包此前誤觸發"精簡台詞"的根因。

```
語速基準（判定看最快檔）：
  強情緒慢速/低聲耳語 → 2.5-3.5 字/秒
  標準對白           → 3.5-5 字/秒
  快速（爭吵/逼問）   → 5-5.5 字/秒
  高速（短劇常態快念）→ 5.5-7 字/秒   ← 完全可行、不是極限
  超過 7 字/秒       → 需授權（搶話/急辯/快嘴喜劇，僅短句且須寫明快念）

停頓補償：
  逗號/頓號        ≈ 0.2 秒
  句號/問號/歎號   ≈ 0.4 秒
  省略號/情緒停頓  ≈ 0.6-1.0 秒
  開口前後反應承接 ≥ 0.5-1.5 秒

檢查：先按**最快檔 7 字/秒**算 `字數÷7 + 停頓` = 最短可行時長
      → 鏡長 ≥ 此值 = 念得完，合規，**不得判超載/不得建議精簡**
      → 只有連 `字數÷7 + 停頓` 都塞不進，才是真念不完
      → 再按 3.5~5 字/秒算舒適時長作參考，據此決定建議生成時長
```

### 閘門 3 · 字數閘門（★ 2026-10-13 起按模型分檔）

```
Seedance 2.0（及未註明模型）：        Seedance 2.5：
≤2900    → 通過                       ≤3600    → 通過
2901-3000 → 必須先壓縮一輪             3601-4000 → 必須先壓縮一輪
>3000    → 繼續刪除低收益內容          >4000    → 繼續刪除低收益內容
          （見下方壓縮順序）                     （見下方壓縮順序）

⚠️ 禁止因為字數超限就壓扁單鏡頭字段
```

> ⚠️ **分檔依據（2026-10-13 粉絲實測反饋）**：「用 2.5 模型出視頻，但字數還限制在 2000」——2.5 對長提示詞的服從與穩定性明顯好於 2.0，舊的單檔 2000 把 2.5 的容量浪費掉了。故 2.5 曾放寬到自律線 2600 / 硬上限 3000。**2026-11-03 字數額度整檔上移 1000**（用戶裁定）：2.5 → **3600/4000**、2.0 → **2900/3000**，軟硬間距按原設計保留；若後續實測在新區間出現丟字段/漂移，再回調。**機檢同步**：`sd-feed-engine/scripts/gate_check.py` 閘門3 按 `--model` 分檔（2.5 → 3600/4000，其餘 → 2900/3000）。

**固定壓縮順序**：

```
① 刪除管理話術和解釋說明
② 刪除默認不輸出的低收益後綴項
③ 合併重複限制
④ 縮短空泛形容詞
⑤ 縮短非末鏡可見轉接
⑥ 把同一控制點集中到 硬鎖/聲音軌/段末狀態
⑦ 用更短但完整的攝影機行為句和光影句表達同一控制
```

仍超限 → 優先用 C 模式；若 5-7 完整鏡或高密度 8-10 短鏡仍超本檔硬上限（2.0 = 3000 / 2.5 = 4000）→ **按鏡頭邊界拆成連續單元**（拆分點必須落在鏡頭之間，用段末狀態承接下一單元第一幀），**不在單個鏡頭內部硬拆**。

### 閘門 5 · 單組圖片數量閘門（按模型分檔 · 2026-10-12 修訂）

```
按 A 鎖模型取上限，**不得把 2.0 的 9 張套到 Seedance 2.5 上**：

  Seedance 2.5（全能參考）   圖 ≤ 30 / 視頻 ≤ 10 / 音頻 ≤ 10 / 總數 ≤ 50
  Seedance 2.0               圖 ≤ 9（單參考圖鎖形象、無首尾幀；平台側多錨點實測可掛 3~4 張）

（含人物、場景、道具、首幀、調度圖、位置參考圖、場景角度圖等所有圖片）

⚠️ 項目資產庫可以超過上限，但單組代碼框內不得引用超過該模型上限的圖號

```

> **為什麼改**：原閘門寫死「每組 ≤9 張」且未分模型——**9 張是 Seedance 2.0 的上限**，被誤當成全模型通用值，直接壓制了 Seedance 2.5（官方支持 30 圖 / 總數 50，權威見總控 `model-adapters.md` §5 與 `SKILL.md` §二）。2.5 用戶本可多投圖鎖一致性，卻被人為卡到 9 張。口徑現與 `sd-storyboard-engine/references/storyboard-sheet-template.md` §參考圖數量紅線（Seedance 2.5 ≤30 / 2.0 圖 ≤9）對齊。

### 閘門 5·補 · 分組三重門檻（★ 2026-10-17 新增 · 粉絲「森林」實測反饋併入）

> 📌 **來源**：粉絲「森林」2026-10-17 反饋——「分完讓 AI 組裝，3 條門檻：1. 小於 15 秒；2. 資產不能超過 9 個；3. 重複資產必須新起分組，不能合在一起，因為同個角色不同資產可能會影響或誤導視頻，也就是所謂的汙染」。
>
> **裁定**：① 時長門檻**方向對、數值需分檔**（15s 是 2.0 的上限，不是全模型值）；② 資產 9 個**不能照收**（9 是 2.0 上限，2026-10-12 已專門修過「把 9 套到 2.5」——收它等於把修復推回去）；③ 資產隔離**屬真空缺，已收**（原文無此規則）。故本節按「分檔 + 分層」重寫，不照抄原話。

**術語對齊**：粉絲說的「分組」= 本包的「投餵單元 / 段」= `## 【投餵單元 N/M · 段K】` 一個代碼框。三者同義，本節統一叫「組」。

**門檻順序固定**：**先按劇情斷點切組，再逐條過三關**；任一關不過 → 拆組或換組，**不得硬塞**。

| # | 門檻 | 判據 | 不過怎麼辦 |
|---|---|---|---|
| **A** | **時長** | 單組 ≤ A 鎖單段上限（**2.0 = 15s / 2.5 = 30s **）；下限見 §〇 ⑦（2.5 禁 16~24s 碎段區） | 按劇情斷點拆，⛔ **不在句子中間切**（台詞跨組 = 口型斷裂） |
| **B** | **資產數** | 單組實際引用的**圖號 + `@` 錨點**合計 ≤ 模型上限（**2.5 = 30 / 2.0 = 9**）；**實操建議 ≤9 更穩**——超過 9 個後每多一個都在稀釋注意力 | 低風險參考**轉文字約束**、合併同源素材，或拆到下一組（低風險項才可拆） |
| **C** | **資產隔離** | **同一角色的不同形態 / 不同年齡 / 不同服裝版本，不得出現在同一組** | 按形態**新起一組**（編號仍保持相鄰，見下） |

**門檻 C 的病根與邊界（必須讀懂，否則會跟「同角色多形態相鄰編號」打架）**：

- **病根**：一組裡同時掛「知夏-4 歲」與「知夏-成年」，模型會把兩張臉**揉成一個人**——不是"兩個角色"，是"一個角色長了兩張臉"，比缺人更難修。粉絲原話「同個角色不同資產可能會影響或誤導視頻，也就是所謂的汙染」，**機制成立**。
- **與「同角色多形態相鄰編號」的關係（分層不衝突）**：
  - **相鄰編號**（`asset-mapping-and-rules.md` §二 鐵律 4）管**《素材接線單》的排序**——讓模型建立"同一主體的兩個形態"關聯；
  - **門檻 C** 管**投餵單元的切分**——一次生成裡**只能出現一個形態**。
  - ⛔ **不是二選一**：**編號照樣相鄰，組必須分開**。
- **正確寫法**：`組1 = 4 歲知夏 + 溫良 + 破屋` / `組2 = 成年知夏 + 溫良 + 破屋`
  **錯誤寫法**：`組1 = 4 歲知夏 + 成年知夏 + 溫良`（同組雙形態 = 汙染）
- **⚠️ 別讀成「同角色不能跨組」**：同一角色**連續出現在多組是正常且必須的**（組 1/2/3 全是 4 歲知夏 = 完全合規）。門檻 C 禁的只有**同一組內多形態並存**，不是"重複出現"。

**機檢兜底**：`gate_check.py` 閘門 5 按 `--model` 分檔（2.5→30 / 2.0→9 ，`--img-limit` 可覆蓋）；門檻 C 目前**只做人工判據**（形態識別依賴資產卡命名，機檢易誤報），出稿自檢時按組核對「本組是否出現同一角色的兩個形態版本」。

### 閘門 6 · 素材編號一致性 ＋ 素材形態一致性閘門

> **前置**：本閘門以**素材形態聲明**為準。形態三檔 **M0 純提示詞 / M1 編號佔位（默認）/ M2 已入庫**，權威 = 總控 `short-drama-director/references/asset-delivery-modes.md`。

```
A · 編號一致性（原）
① 鏡頭軌中出現的每個 圖N / 視頻N / 音頻N 是否已在素材錨定 / 映射表中定義？
② 角色/場景/道具/首幀/調度圖/視頻/音頻職責是否混用？
③ 發現圖號混用 → 先修正或提示用戶確認，不直接交付

B · 素材形態一致性
④ 交付首行是否已聲明素材形態（M0 / M1 / M2）？未聲明 = 形態未定 → 不得交付
⑤ M0 稿內出現任何圖號 → 形態違約（FAIL）：圖號槽位與 M0 聲明互斥
⑥ M1 稿內有圖號但未附《素材接線單》 → 形態違約（WARN）：接線單是 M1 交付必備件
⑦ 稿內圖號 ∉ 接線單圖號集合 → FAIL（用戶會去掛一張不存在的圖）
⑧ 接線單每行是否寫明"只控制什麼 / 不控制什麼"？缺項 → WARN
⑨ 是否出現"已與《資產圖冊》核對一致 / 已核驗"之類斷言？M0/M1 下本包看不到圖 → 一律 FAIL（虛假核驗）

機器化：python scripts/gate_check.py <投餵稿.md> --mode M0|M1|M2
```

## 三、增強觸發規則（按需啟用）

| 命中情況 | 默認處理 |
|---|---|
| 普通劇情段 / 常規連續段 | 推薦 C；不強行加入高級增強 |
| 用戶明確要求完整字段、審查漏項、1-3 鏡頭高精度控制 | 推薦 A |
| 同場景順延，下一段像繼續拍 | 建議視頻延長啟動句；默認 C |
| 必須首幀 / 建議首幀 | 加入首幀參考，說明只鎖第 0 秒 |
| 多人站位、軸線、遮擋、攝影機安全區高風險 | 加入調度圖參考或側別約束；複雜時推薦 B 或 C |
| 核心場景、反打、回切、複雜空間或高穿幫場景 | 加入場景角度參考，說明只鎖拍攝方向和空間透視 |
| 公共空間、街道、商場、車站、學校、醫院、營業餐廳等需路人真實感 | 加入人群密度，寫清人數、層次、類型、移動方向和遮擋規則 |
| 同一道具已在場景/角度/首幀可見且又引用道具圖，或道具會被拿起/移動/跨段延續 | 加入道具單實例鎖 |
| 一鏡到底、複雜運鏡、動作戲、強遮擋轉場、強聲音敘事 | 推薦 B |
| 長對白單元（同一說話人連續 ≥3 句，或單句 ≥20 字） | 可選啟用**台詞氣口標記**（§三·1）——把停頓位置與秒數寫出來；不啟用亦合規，閘門不判缺 |
**多增強疊加超字數時**：優先用 C，刪除低收益後綴、壓縮管理話術、合併重複約束，把字數留給鏡頭軌關鍵控制。**不得刪除關鍵控制信息。**
**§三·1 台詞氣口標記（可選槽位 · 非必填）**

給長對白的停頓一個顯式槽位：閘門 2 的「停頓補償」是**算**停頓，本槽位讓停頓**寫出來**，讓模型按氣口表演，而不是一口氣唸完。

寫法——**追加在台詞行 `】` 之外**（引號內一個字都不許動）：

```
台詞：【柳娘（壓著怒·低語）："你走吧，別回頭。"】 〔氣口：句尾停頓約 0.8 秒〕
```

四條鐵律：

1. **可選**：不寫 ＝ 合規；只在長對白單元建議補，閘門**不判缺**。
2. **零改動台詞**：標記寫在 `】` **之外**，引號內台詞文字一個字符不許變——「台詞零丟失」優先於本條。
3. **禁寫進 `【】` 內**：寫進去會破壞 `台詞：【角色（語氣）："…"】` 的解析，閘門 0/閘門 2 與 `script_feed_diff.py` 都會**漏檢該句**。
4. **不新設字段**：氣口是**行內註解**，不是新欄；七段式字段名不變（C7 不受影響）。只寫「停頓位置 + 秒數」，**禁寫「切鏡/轉場/接下一段」類工作流詞**（會被閘門 4 與 C12 攔）。

秒數口徑沿用閘門 2：逗號/頓號 ≈0.2s、句號/問號/歎號 ≈0.4s、省略號/情緒停頓 ≈0.6~1.0s、開口前後承接 ≥0.5~1.5s。
