## 四、敘述體怎麼寫（四條鐵律）

1. **每格回答六問**：誰在哪 / 朝哪 / 看哪 / 做什麼 / 鏡頭在哪 / 光從哪來。缺一項，AI 就要自己編。
2. **⛔ 禁寫本包術語**：不寫「九宮格 / CLEAN_GRID / SHOT_TEXT / action_phase / D 鎖 / R1 / 圖STB」。這張圖是給圖像模型和人看的，術語只會讓它畫出一堆標籤（"九宮格"被認成場景圖的坑已復發多次）。
3. **抽象詞翻譯成可見物**：「壓迫感」→「A 站在門框內側，影子壓在 B 臉上」；「猶豫」→「手停在半空，指尖離門把三釐米，視線落在門把上」。
4. **格數 = 該段鏡數，不設固定格數**（2026-10-22 二次修正）：**4 格、6 格、9 格、12 格都可以，由段落分鏡的鏡數決定**——一鏡一格，投餵稿這一段有幾鏡就出幾格。⛔ 禁止把格數寫死成 3~4 格 / 3~6 格，也禁止為"四宮格好看"硬湊或硬砍，更禁止寫"同上"佔位。
   > **版式隨格數自動選**：4 格 → 2×2 ／ 6 格 → 2×3 ／ 9 格 → 3×3 ／ 12 格 → 3×4 ／ 5 格 → 單行 5 格或 2+3 ／ 8 格 → 2×4。版式是**排版結果**，不是格數的來源。
   > **確實要合併時才合併**：一格合併多鏡寫 `〔鏡K+M 景別〕`，並在該段前寫一句合併理由（如"鏡7、8 是同一次動作的連續兩拍，合併為一格"）。
5. **★每格必須標投餵稿鏡號**（2026-10-22 新增 · 治「故事板與投餵稿各寫各的」）：格式 `第N格：〔鏡K 景別〕…`，K 就是投餵稿該段的鏡頭號，景別必須與該鏡一致。**一格合併多鏡時寫 `〔鏡K+M 景別〕`**。
   > **病根（實測事故）**：舊口徑文戲上限 **4 格**，而文戲段常是 **6 鏡**——6 塞不進 4，規則又不要求標鏡號，於是"4 格故事板"和"6 鏡投餵稿"各自成立：段落數一樣、景別對不上（故事板寫近景、投餵稿是特寫）、主體也不同（故事板畫蘇念寫卷子，投餵稿那一鏡的主體其實是沈甜在爆料）。**讀者拿故事板去驗收，驗的是另一部片。**
   > **現在**：格數**優先等於該段鏡數**（6 鏡就 6 格，2×3 排列）；確實要合併時才用 `鏡K+M`，並在段首寫清合併理由。機檢 `P459`（缺鏡號）+ `P45A`（景別/鏡號/覆蓋交叉核驗，需 `--feed`）攔。

**提示詞骨架**：
```
畫一張分鏡故事板，{N} 格，{排列方式}，{畫幅}，{畫風}，畫面中沒有任何文字、數字、水印或邊框標註。
統一人物設定：{角色名}：{年齡/髮型/服裝/體型，逐項寫死}。
場景：{一句話寫清空間結構與光源方向}。
第 1 格：{六問填滿}。
第 2 格：……
第 N 格：……
要求：各格人物服裝與髮型完全一致；動作逐格遞進、不可跳躍；相鄰格空間關係連續，不越軸。
```

## 五、看圖之後怎麼改（改的是稿，不是圖）

用戶看完預演圖，會指著某格說"這裡不對"。這時**不要重畫圖**，回到 P4 投餵稿定點改：

**三條鐵律**：
1. **唯一 ID 尋址**：`段{n}-格{k}` → `鏡{nn}` → `圖{類型}-{編號}`。⛔ 禁"把那段改一下""整體再優化下"——無 ID 必然整段重寫，**改一處壞三處**。
2. **只改指定項**，其餘逐字不變，附《改動回執》：
   ```
   【改動回執 · 段{n}】
   改動：鏡{nn}【時間軸分鏡】第 3 句 —— 「A 站在門內」→「A 站在門框內側，右肩貼框」
   未動：本段其餘 7 條鏡行、全部【核心人物】【場景資產】【強制禁止項】逐字未變
   ```
3. **改法分三級**：L1 改描述（默認，最便宜）→ L2 用戶重新出圖（提示詞不動）→ L3 回 P3 改分鏡（**須先告知用戶**）。

> **經驗建議（非官方能力斷言，比例未經統計驗證）**：優先檢查 L1 描述歧義；若空間或調度本身不成立，應回 P3 修正，不能保證僅改一句即可解決。

## 六、盲區（寫進附件開頭，別讓人誤以為驗過了就萬事大吉）

**預演圖能看**：構圖、景別、機位、站位越軸、人物一致性、道具位置、光源方向、敘事順序。
**預演圖看不出**：跨幀連貫、運鏡軌跡、轉身/出手的高速瞬間、接觸點物理、多主體互動。

→ 打戲與長鏡頭，預演圖過了也照樣可能抽卡。補法是給該段預留抽卡預算（≤2 次），或改用 `storyboard-sheet-template.md` §三 七態拆格 / 首尾幀對（僅 Seedance 2.5）。**⛔ 禁止承諾"看完預演圖就一次成"。**

## 七、邊界

1. **不替代 P3 故事板圖提示詞**（那份進投餵體系，這份不進）；
2. **必須過 P4.5 專用機檢**（`sd-storyboard-engine/scripts/check_p45.py --feed <投餵稿.md>`：段結構 / 格數與編號 / 六問 / 術語 / 佔位 / 圖片聲明 / 段覆蓋 / **格內鏡號（P459）/ 與投餵稿的景別·鏡號·覆蓋交叉核驗（P45A）**）——**FAIL 清零才交付**；它**不替代** P5 機檢（`validate_prompt.py` / `audit_contract.py` 驗投餵稿文字層），兩份各管一份；
3. **不改鎖**——它跑在交付環節，不重新問模型/畫幅；
4. **不產圖**——默認永遠是提示詞；只有用戶下出圖口令 + 形態 M2 才出圖，且走 `asset-first-pipeline.md` 門禁。

## 八、機檢門（★ 2026-10-21 合併保留 · FAIL 清零才交付）

> **背景**：P1 只把 P4.5 接進「契約層 CT5-P45」（命中不附即 FAIL），**沒有結構機檢**——少段、少格、漏六問、術語混入、寫「同上」仍能過。本倉保留專用檢查腳本。

**命令**：

```bash
python sd-storyboard-engine/scripts/check_p45.py <項目名>-預演故事板.md --segments <段數>
```

- `--segments N`：與投餵稿段數對齊；缺段且無 ⛔ 豁免說明 → FAIL；
- `--m2`：僅形態 M2 時使用，放開「已核驗 / 看圖」類表述；
- `--self-test`：跑 6 個內置用例自檢腳本本身。

**11 條規則**：P450 命名 · P451 段結構四件套 · P452 格數/格號 · P453 六問 · P454 術語汙染 · P455 佔位引用 · P456 圖片聲明 · P457 段覆蓋 · P458 交付清單行 · **P459 格內鏡號** · **P45A 與投餵稿交叉核驗（景別/鏡號/覆蓋）**。

**門禁口徑**：ERROR 清零才算 P4.5 完成；WARN 須逐條處理或書面說明。本檢查只驗 P4.5 附件，**不替代** P5 的投餵稿機檢。
