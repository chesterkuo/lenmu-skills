# 交付翻車清單（實戰回寫 · 2026-10-19）

> 來源：《獸瞳》第01集全流程實跑（國內劇 · 原創 · Seedance 2.5 · 9:16 · 90 秒/集 · 東方神話3D · M1）從立項到交付的完整踩坑記錄。
> 定位：本文件**不重新定義任何規則**，只把已發生過的翻車固化成「症狀 → 病根 → 硬規則 → 檢查手段」四段式，供**交付前逐條自查**。
> 用法：P2 資產出稿、P4 投餵封裝、交付打包前，各過一遍對應章節。規則本體仍以各權威文件為準。

---

## 一、交付形態：件數、分層、命名

### 1.1 交付件數爆炸（最嚴重 · 一次性產出 15 個文件 / 10 個目錄）

**症狀**：用戶只要一份東西，交付出一整個目錄樹——IP聖經、故事聖經、分集規劃、資產包、導演稿、情緒錨點表、分鏡稿、投餵稿、質檢報告、連續性台賬各佔一個文件。

**病根**：**把「引擎工作文件」當成「交付物」**。本包是多引擎流水線（劇本 / 資產 / 分鏡 / 投餵 / 質檢），每個引擎按自己的規範產出一箇中間件——那是**引擎之間的協作接口**，不是給用戶的東西。逐個落盤並交付 = 把工廠流水線當成品賣。

**硬規則（件數上限 3）**：

| 件 | 內容 | 何時出 |
|---|---|---|
| **① 主文檔**（md 或離線看板，二選一按 C 鎖） | 全部對外內容合一 | 必出 |
| **② 看板 HTML** | 由主 md 編譯，雙擊即開 | 僅 C 鎖含看板時 |
| **③ P4.5 預演故事板** | 只出提示詞、不出圖 | 僅場景複雜 / 用戶點名 |

- ⛔ **超過 3 件即視為交付層違規**。中間件一律併入主文檔或留在內部檔案，不單獨交付。
- 合併順序建議：總控 → IP → 故事聖經 → 分集規劃 → 劇本 → 資產提示詞 → 審核 → 製作全案 → 質檢；合併後**內部交叉引用改成「第X部分」**，不再保留下游文件名引用（否則刪掉中間件就斷鏈）。

### 1.2 內部內容外洩（C 鎖 = 只要 md 時的正文邊界）

**症狀**：用戶要的是「拿去生圖、生視頻的東西」，交付稿裡卻是 IP 聖經、世界錨卡、人物錨卡、分集規劃、圓桌審核、質檢報告、情緒錨點表。

**病根**：把「說服自己寫對了」的過程材料，當成「用戶能用的東西」交出去。

**硬規則（正文只放兩樣）**：

- **md 正文 = 資產提示詞 + 分鏡提示詞**。這兩塊是用戶唯一真正要動手用的內容。
- 其餘全部歸**內部檔案**：單獨文件、文件名前綴 `_內部_`、**不放桌面**、不進交付包。
- 判據：交付稿裡出現「世界錨卡 / 人物錨卡 / 分集規劃 / 圓桌 / 質檢 / 情緒錨點 / P0A / M1 / C27 / 六道閘門自檢」這類內部術語 = 洩漏，改寫或刪除。
- 例外：**出看板時**才承載完整內容（看板是「給人看全貌」的形態），此時分層規則不適用。

### 1.3 英文命名與代號殘留

**症狀**：目錄叫 `shoutong`、文件叫 `EP001_SCRIPT.md`、標題寫 `EP001`。

**硬規則**：目錄、文件名、正文標題**一律中文**；集數寫「第01集」「第01-03集」（區間末尾不再補零寫三位）。技術標識保留原文（Seedance 2.5 / 9:16 / M1 / 圖號），改掉會與機檢指紋對不上。

## 二、提示詞自包含：五條鐵律

**症狀**：單條提示詞複製到生圖/生視頻平台後不成立——「同規格」「見母版」「同圖2」「降級條款同圖2」「按第三部分」。

**病根**：寫作時站在「整份文檔」視角，用了跨條引用做壓縮。**提示詞的投餵單位是單條，不是整份文檔。**

1. **禁跨條引用**：`同上 / 同規格 / 見母版 / 同圖N / 同前 / 按上述 / 參見X / 見第X部分 / 降級條款同圖N` 全部禁止。
2. **禁省略式佔位**：寫「②③④ 格同規格無臉全身」→ 必須把②③④每格內容逐條寫死。
3. **每條自帶上下文**：畫幅、格數、**所選通道的臉部規則**（四格＝②③④ 無臉全身；八格＝左三格正常有臉＋④格唯一面部標記）、負向詞、圖底細節條要求，**逐條重複寫**，不靠上文繼承。
4. **降級條款要完整**：不能寫「降級條款同圖2」，要寫全「中文崩字 → 格內編號 1~9 + 圖外對照表 + 重試上限 2 次 + 降級後仍保留 9 格」。
5. **圖號 ↔ 提示詞 ↔ 槽位自洽**：接線單裡的「參考圖 N」必須指向本冊已存在的圖號；改了圖號要同步接線單與分鏡裡的槽位。

> 自檢：`python scripts/check_asset_blocks.py <交付稿.md>`（規則 A1）

## 三、資產提示詞：結構與格數

### 3.1 角色出成 5 格（僅通道① 四格 · 最常見的廢圖）

**症狀**：要 4 格，出圖是 5 格，正面被畫了兩遍。

**病根**：提示詞裡**同時出現「立繪 / 全身完整入畫」與「四格」**，或用了舊稱「主圖」。模型按「1 張主圖 + 4 格」做加法。

**硬規則**：
- 一條提示詞 = **一張 16:9 四格純圖板**，開頭顯式聲明「**全圖共 4 格，橫向並排……不設獨立大主圖、不重複任何視角、不出現第 5 格**」。
- ⛔ **禁止「主圖」二字**（正向用法）；要指代正面那張，寫「正面格」。
- 三格全身必須**無臉但保留頭**（不許砍頭，否則頭身比失真）、**頭頂至鞋完整入畫**。
- 負向詞必須含：`fifth panel`、`extra panel`、`different face`（或 `second face`）、`text`、`watermark`。
- 圖底細節條 = 聲紋波形 + ≤8 詞音色標籤，**不計入格數**。

### 3.2 五宮格缺字段（出圖後無法定位機位）

**症狀**：九宮格出來了，但不知道哪格對應哪個機位；建築還漂了。

**病根**：八字段只寫了五個，缺 **【場景定位】【九宮格內容分配】【參考場景鎖定模式】**。

**硬規則（八字段，缺一即不合規）**：
【場景定位】（含空間類型，決定攝影機矩陣取哪張表）→【場景畫面描寫】→【九宮格內容分配】（模式A 單場景多機位 / 模式B 多子區域）→【參考場景鎖定模式】（A 檔「僅允許攝影機移動」/ B 檔「允許按子區域切換機位」，**按模式選檔、不得混用**）→【攝影機矩陣】→【攝影機參數】→【光照曝光】→【標註要求】。
- 必須顯式寫「**全圖共 9 格，不多不少**」。
- **機位名與空間類型必須匹配**（室內 / 室外獨立建築 / 自然場地三張表），禁硬湊。
- 標註降級條款寫全：中文崩字 → 格內編號 1~9 + 圖外對照表，**禁止無標註裸格交付**，重試 2 次仍失敗也要保留 9 格。

### 3.3 道具字段名不統一

**症狀**：道具圖和角色圖混淆，或四格寫成了「正面/45°側視/頂部俯視」，模型不知道出設定板。

**硬規則**：
- 開頭必須寫「整板固定 16:9 橫版的**道具設定圖**（單張，不拆圖）」。
- 四格字段名用模板原名：**正面視圖 / 45° 側視圖 / 頂部俯視圖 / 關鍵細節特寫**。
- 必須禁手持、禁人（`禁止人物、人手、肢體、剪影`），必須有尺寸參照物。
- 左（或右）上角標註道具名屬允許文字，其餘文字禁止。

> 自檢：`python scripts/check_asset_blocks.py <交付稿.md>`（規則 A2~A7）

## 四、分鏡與投餵：容易被人工目檢漏掉的紅線

| 症狀 | 病根 | 硬規則 | 判據 |
|---|---|---|---|
| 段內幾乎沒有人物特寫 | 全寫中景/全景鋪信息 | **段內人物特寫佔比 ≥25%** | C15 |
| 一個鏡頭 7~9 秒 | 拉長鏡湊滿劇本標註時長 | 單鏡按內容倒推，**≤6s**（一句≤40 字動作行）；總時長允許短 25% | C10 |
| 相鄰兩鏡機位描述完全一樣 | 拆鏡時複製未改 | 同段內**機位表述不得重複**（改越肩/反打/大特寫） | C15/C10 |
| 畫面段缺背景與光線 | 把「背景/光線」寫在「台詞：」之後 | **背景元素 + 光線方向必須寫在「台詞：」之前**（畫面段內） | C32 |
| 運鏡詞報錯 | 用了不在詞表的詞（如「快搖」） | 用詞表內詞：**橫搖 / 平搖 / 搖鏡 / 推 / 拉 / 跟 / 升降 / 固定** | C18g |
| 群像人數被判錯 | 寫「畫面中沒有其他人」 | 用**肯定式人數句**：「殿內共五人：A、B、C 與兩名弟子」 | C26/C17 |
| 鏡號跳號/重號 | 增刪鏡後沒重編號 | **每段鏡號從鏡1 起算**；增刪後整段重編，分鏡稿與投餵稿同步 | 人工 |
| 同段首尾鏡機位撞車 | 段縫只用「換機位」未換景別 | 段縫首鏡**換景別 + 換機位**（如末鏡特寫 → 首鏡大遠景） | D 鎖 |

> 判據編號對應 `scripts/validate_prompt.py`；`--by-segment` 見下節。

## 五、機檢口徑：多段稿必須分單元跑

**症狀**：一段 30 秒的文戲稿，機檢報「打戲位移不足 / 貼身對招佔比低（C21/C22）」，看了半天稿子里根本沒有打戲。

**病根**：**整份文檔送檢**。90 秒 = 3×30 秒的稿子被當成「一段 90 秒 / 17 鏡」解析，鏡密度與動作密度雙雙超標，被判成打戲檔；同時按段口徑的 C10 單鏡時長、C15 特寫佔比也跟著失真。

**硬規則**：
- **凡一稿含 ≥2 段，一律加 `--by-segment`**：
  ```
  python scripts/validate_prompt.py <交付稿.md> --model 2.5 --by-segment
  ```
- 該模式按「段N/M」標題切段，逐段獨立跑判據，輸出帶 `[段N]` 前綴，末尾給「段數3（分單元校驗）」。
- 整份模式仍保留用途：**資產契約（C31/CT2）與結構指紋按全文核銷**。
- 報告裡要寫清用哪種口徑出的結論；**不許拿整份模式的 C21/C22 去改本沒有打戲的段**。

## 六、改動同步紀律

**症狀**：交付稿修好了，內部檔案還是舊版；下次複用拿到的是舊稿。

**硬規則**：
- **單一真相源**：交付稿是唯一對外真相；內部檔案裡同一段落必須**同步為同一版本**（改完立刻回寫，別等）。
- 改圖號 / 改鏡號 / 拆鏡 / 並鏡，一次改三處：提示詞、接線單、分鏡稿（+ 投餵稿鏡行）。
- 每輪修改記一條「改了什麼 + 為什麼」，寫進內部檔案附錄（規範複核記錄），便於下集複用。

### 6.1 區間替換吞節（2026-10-20 實戰 · 一次性刪掉整節 P3 清單）

**症狀**：用「從 A 段落開頭，一直替換到下一個標題 B」的方式改稿，**B 前面夾著的小節被一起吞掉**，交付後人工翻不到、機檢也不報。

**實例**：改段6 時按「段6 起點 → `# 附錄`」做區間替換，把中間的 `## P3 圖形化交付清單`（含故事板格數表 + 劇情分鏡格表）整節刪了。機檢 `validate_prompt.py` 只按【畫幅風格】切段跑判據，**不會發現少了一節**；`check_asset_blocks.py` 也不管。發現時已是第三輪交付。

**硬規則**：

1. **區間替換隻允許「到下一個同級或更高級標題」**——用 `^## ` / `^# ` 正則定位，不要用「某個字符串」當右邊界。
2. **替換前後各數一次節數**：`grep -c "^## " <file>` 與 `grep -c "^### " <file>`，數目變了必須解釋。
3. 替換後**必跑一次結構清單**：`grep -n "^#\{1,3\} " <file>`，人眼掃一遍有沒有整節消失。
4. 大改前先 `cp <file> <file>.bak`；改完 `diff` 一遍再刪備份。

### 6.2 劇本 ↔ 分鏡 雙向同步（改台詞必回寫劇本）

**症狀**：分鏡（第三部分）台詞改了，劇本正文（第一部分）還是舊句。用戶讀劇本以為故事沒改，讀分鏡又對不上。

**硬規則**：台詞一改，**兩份一起改**，且**劇本是給人讀的、分鏡是給機器讀的**——劇本保留動作與情緒描述，分鏡只保留可投餵字段。禁止只改一份。

**自檢**：把劇本正文裡的台詞逐句 `grep` 到分鏡裡，應全部命中；反向也成立（畫外對白除外）。

### 6.3 故事板 ↔ 分鏡 同步（分鏡動過 = 整份重出）

**症狀**：分鏡改了鏡序/景別，故事板只被人手改了一句，格與鏡錯位。詳見 `sd-storyboard-engine/references/storyboard-sheet-template.md` §十二。

**硬規則**：不許補丁式改字。跑 §12.3 的逐鏡檢查，`不一致 = 0` 且 `鏡數 == 格數` 才算過。

## 七、交付前驗收（照這個順序跑）

1. `python scripts/check_asset_blocks.py <交付稿.md>` → **FAIL 必須清零**（跨條引用 / 格數 / 字段 / 道具）。
2. `python scripts/validate_prompt.py <交付稿.md> --model 2.5 --by-segment` → **FAIL 清零**；WARN 逐條判「真缺陷」還是「口徑誤報」，真缺陷改稿、誤報寫理由。
3. `python scripts/audit_contract.py <交付稿.md>` → 契約件核銷（內部件缺失屬預期，須能指出它在內部檔案的哪一部分）。
4. 人眼過三件事：**件數 ≤3**、**正文只有兩樣（資產提示詞 + 分鏡提示詞）**、**每條提示詞單拎出來能獨立使用**。
5. 命名檢查：目錄/文件/標題全中文，無 `EP0xx` 類代號。
6. **故事板逐鏡檢查**（有故事板時）：跑 `storyboard-sheet-template.md` §12.3 腳本 → **不一致 = 0**、**鏡數 == 格數**；再核 `## P3 圖形化交付清單` 的「四格覆蓋」列是否已同步成「鏡N 內容」格式。
7. **節數變動核對**（大改後）：`grep -n "^#\{1,3\} " <交付稿>` 掃一遍，確認沒有整節被區間替換吞掉（見 §6.1）。
8. **口型/語序抽查**：隨機抽 3 條帶台詞的鏡行，確認 ① 台詞按時間順序內嵌、沒堆行尾；② 畫面段無聲音詞（C16a）；③ 說話人嘴唇狀態在故事板裡有標。
