## 一·補、 跨項目汙染專檢（2026-10-10 併入）

迭代與多項目並行時，最容易把"上一版規則 / 上一個項目的樣例"當成通用規則帶進新稿。交付前過一遍下表——**這是 P0~P2 之外的獨立專檢，與 §一 並行生效**：

| 汙染類型 | 症狀 | 處置 |
|---|---|---|
| **舊時間格式回滾** | 稿中出現 `△0.0-3.0s` 絕對起止時間軸，或省略每鏡時長 | 恢復編號鏡頭 + 整數秒口徑；**總時長 = 各鏡之和** |
| **佔位語殘留** | "根據劇情分配 / 待補充 / TBD / XXX / 某角色 / 某地點 / 某道具" | 正式字段內**不得保留**；無法確認則說明缺資料，不用佔位語糊弄 |
| **風格 / palette 默認化** | 把某項目的色號、palette、攝影設備名稱寫成所有項目默認 | **默認不寫 palette/色號**；項目明確要求才臨時執行 |
| **樣例劇情升級為長期設定** | 單集/單場劇情、單張參考圖姿態、某段 prompt 的道具，被寫進項目長期規則 | 長期設定只來自項目資料或用戶明確確認；不確定的保持不確定 |
| **工具 / 元數據洩漏** | 稿中出現 YAML 頭、allowed-tools、運行環境或模型能力聲明 | 全部剔除，只保留可執行的自然語言規則 |

**原則**：項目長期設定必須來自項目資料或用戶確認；**單段劇情不得汙染全局**；歷史來源與當前規則衝突時，**以當前項目資料與用戶當前要求為準**。

## 二、 聲音三層架構與混音電平規範

$$\text{第一層：對白清晰度 (0 dB)} > \text{第二層：動作物理音效 SFX (-6 dB)} > \text{第三層：環境聲景與 BGM (-14 dB $\sim$ -18 dB)}$$

* 對白必須永遠處於最高清晰度優先級，動作音效（骨裂/破風/撞擊）不得遮蓋人聲，BGM 在激烈打鬥或對白爆發時自動避讓（Ducking）。

## 三、 改動後複驗鐵律（2026-09-04 新增 · 防"只驗改動處"漏檢）

> 改稿禁止只複驗改動處。改動內容會與劇本其他部分衝突（伏筆/因果/資產/時長/畫幅）——典型翻車：改一句台詞劇透前文伏筆、改一個場景與《資產圖冊》錨點衝突，而整片未重跑審核。

### 三步複驗閉環（缺一不可）
1. **局部驗證（改動處自檢）**：改動內容本身達標（台詞/畫面/錨點/時長）；
2. **聯動衝突檢查（七項交叉掃描）**：伏筆 → 角色（人設/臉模/服裝）→ 信息量（劇透/節奏）→ 因果節拍 → 資產錨點 → 時長預算 → 畫幅一致性，逐項確認無衝突；
3. **全量審核**：整片重跑 P0~P2 門禁（本文 §一），不允許以"已檢查改動處"豁免。

### 《改動複驗報告》交付要求
- 修改類交付物文末必須附：**改動清單 + 聯動檢查結論 + 全量審核結論**；
- 未附報告 = 視為未完成複驗，**禁止交付**（對應 `asset-first-pipeline.md` 門禁 6）。

## 四、 多模態拉片診改協議（`/拉片診改` · 成片/廢圖逆向診斷與 V2 重抽閉環 · 2026-10-14 新增）

> **定位**：出稿機檢（`validate_prompt.py`）攔的是「提示詞文本結構與語義風險」，而 AIGC 實戰的下半場發生在**用戶在平台（Seedance 2.5/2.0）跑出資產圖或視頻之後**。當用戶把跑壞的資產圖、關鍵幀截圖或成片視頻發回對話（或口述實拍翻車現象）時，必須按本節「**症狀 → C 碼根因映射 → V2 重抽提示詞處方**」執行逆向診改，禁止盲目讓用戶“多抽幾次”。

### 4.2 `/拉片診改` 四步執行序列
1. **視覺取證**：讀取用戶上傳的廢片關鍵幀/資產圖（或解析用戶描述的翻車點），定位具體發生在哪一段、哪一鏡；
2. **C 碼歸因**：對照 4.1 矩陣指出觸發的具體 C 碼/閘門病根（禁止籠統歸咎於“模型抽卡隨機性”）；
3. **生成 V2 重抽稿**：僅針對病灶鏡行與對應欄位打補丁，自動重跑 `validate_prompt.py` 與 `gate_check.py` 確保零新增告警；
4. **同步回寫台賬**：若涉及資產級或狀態級調整（如補登記 `CHAR_STATE` 或修正外觀三件套），同步更新 `project_state.json` 與《改動複驗報告》。
